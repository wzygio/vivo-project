# 建立显式领域范围的快速烟测入口

## What to build

提供统一的快速烟测命令，要求调用者显式选择 `spc`、`yield`、`equipment` 或 `all`。命令把领域映射到现有测试文件/模式，先展示实际目标，再执行 pytest。默认和共享范围采用保守的完整单元测试；快速路径不替代发布前完整回归。

同步测试可观测性文档，使 Agent 能区分“快速烟测”和“完整验证”。

## Acceptance criteria

- [x] 单一入口支持 `spc`、`yield`、`equipment`、`all`，无效领域以非零状态和清晰信息退出。
- [x] 不显式给出领域时采用 `all`，不自动猜测 Git diff。
- [x] 执行前打印领域和 pytest 目标；目标不存在或没有收集到测试时不能假通过。
- [x] SPC 目标覆盖现有 SPC/CPM 单元测试，Equipment 目标覆盖备件 core/service 单元测试，Yield 目标覆盖现有 Yield 相关单元测试。
- [x] `all` 保持当前完整 `tests/unit/` 语义；既有失败如实暴露。
- [x] 领域映射、默认行为和参数错误具备 RED→GREEN 单元测试。
- [x] 当前环境的 SPC 快速烟测相对 11.64 秒可运行单元基线至少快 60%。
- [x] `references/test_references/` 中记录使用方式、能力边界及完整回归要求。

## Risk points

| Risk | Possible impact | Required control |
|---|---|---|
| 领域测试遗漏跨域依赖 | 快速烟测通过但完整回归失败 | 显式说明不是完整回归；共享/未知变更使用 `all`；发布前运行完整验证 |
| 测试文件重命名后映射漂移 | 少运行或零运行测试 | 入口检查目标存在；pytest 零收集非零退出；映射测试锁定 |

| 既有完整单元失败 | `all` 当前仍失败，影响使用体验 | 保留并报告基线缺陷，不改业务代码掩盖失败 |
| 新命令改变现有验证入口 | Harness/人工命令失效 | 只新增入口和文档，不删除原有 pytest 命令 |
