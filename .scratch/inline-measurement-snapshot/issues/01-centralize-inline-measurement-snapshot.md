# 统一 Inline 测量提取、快照与报表数据端口

Category: `enhancement`  
Status: `complete`

Source: `2026-08-13 用户会话：将 SPC/CTQ/AOI_TT 的同源测量提取统一到 monitor infrastructure，并重设 app 接口边界`  
Related: `ARCHITECTURE.md`、`docs/ADR/0001-streamlit-cache-native-payload-boundary.md`、`references/domain/Inline_domain/spec-data_source-spc.md`、`references/domain/Inline_domain/spec-data_source-aoi_tt.md`

## Current context

- SPC 与 CTQ 经同一个 `SpcRepository` 读取三厂测量表和产品级 Parquet 快照，再按参数类型过滤；AOI_TT 对同三张测量表执行独立 SQL，未使用该快照。
- 当前 SPC 仓储同时承担原始 DAO、快照刷新/降级、参数分类、异常值过滤及主制程追溯，导致共享数据访问和 SPC 专属预处理边界混合。
- AOI_TT 需要 `lot_id`，并按规格表 `param_type IS NULL` 的 `step_id + param_name` 组合识别 TT；这与 SPC/CTQ 的参数分类契约不同。
- Streamlit 页面通过应用服务取得 payload/ViewModel；ADR-0001 要求 `st.cache_data` 仅跨越 DataFrame、原生容器和标量，ViewModel 在缓存外构造。
- 工作树已有与自动预警合规修饰相关的用户改动；本任务必须保留并兼容这些改动。

## Desired outcome

- 三厂同源测量数据按产品和统一时间窗口只提取一次，并由共享基础设施适配器维护产品级快照、TTL、刷新和数据库失败降级。
- SPC、CTQ、AOI_TT 各自拥有独立的基础设施适配器，将共享原始测量转换为各自既有数据契约；业务专属过滤和派生不污染共享快照。
- 应用服务通过明确的测量数据出站端口获取数据；Streamlit app 不读取 Parquet、不实例化底层仓储，也不执行数据访问或仓储预处理。
- 现有报表的计算口径、过滤器、缓存刷新行为及 ViewModel/payload 契约保持兼容。

## Acceptance criteria

- [x] 共享测量 DAO 一次 UNION ALL 读取 ARRAY/OLED/TP，输出包含 `factory/prod_code/start_time/sheet_id/lot_id/step_id/param_name/site_name/unit_id/param_value` 的稳定字段超集。
- [x] 产品级共享快照统一实现三个月窗口、TTL、策略版本、强制刷新、原子持久化和“已有快照才允许数据库失败降级”的契约。
- [x] SPC、CTQ、AOI_TT 数据接口均从共享快照读取；SPC/CTQ 的白名单与异常值规则、SPC 主制程追溯、AOI_TT 的 step+param 识别分别留在各自适配器中。
- [x] AOI_TT 的 By Lot、By Sheet、period 分母和 USL/UCL 输出与迁移前契约一致，且获得共享快照降级能力。
- [x] app 页面只组装查询 DTO、调用应用服务并渲染，不直接读取快照或依赖具体 infrastructure repository。
- [x] `st.cache_data` payload 和产品级 `snapshot_signature` 继续遵守 ADR-0001；刷新一个产品不清空其他产品缓存。
- [x] 增加端口单元测试、共享快照适配器测试和三个报表的行为回归；SPC/CTQ/AOI_TT 定向测试及相关 E2E 全部通过。
- [x] `ARCHITECTURE.md` 和 ADR 记录新的所有权、依赖方向、快照契约与迁移决策。

## Out of scope

- 不改变 CPM/CPK、CTQ 分布、AOI_TT 聚合公式、OOS/人工修饰或主制程追溯业务口径。
- 不修改数据库表结构，不迁移 AOI_RS/Yield/Equipment 数据源。
- 不重构现有自动预警合规修饰规则；仅保证共享测量接口与其兼容。
- 不让 `monitor` 核心业务成为 SPC/CTQ/AOI_TT 的依赖；`monitor/infrastructure` 仅作为共享测量出站适配器的代码归属位置。

**Category:** enhancement  
**Summary:** 建立共享 Inline 测量数据端口和产品快照适配器，让 SPC、CTQ、AOI_TT 从同一次底层提取派生，同时把报表专属预处理留在各自适配器。

**Current behavior:**

SPC/CTQ 共用一个以 SPC 命名的仓储和快照，AOI_TT 重复查询同三张测量表。共享 DAO、快照生命周期、参数分类、异常值过滤和 SPC 主制程追溯混在同一具体仓储中；应用服务直接构造具体仓储，缺少可替换、可单测的出站端口。

**Desired behavior:**

应用用例依赖测量数据能力端口。共享 infrastructure 适配器一次读取并持久化未经报表专属加工的测量事实字段超集；SPC、CTQ、AOI_TT 适配器组合该能力并执行各自的参数识别、字段映射、过滤和派生。Streamlit 页面只调用应用服务。数据库失败时仅在存在可读历史快照时降级。

**Key interfaces:**

- 共享测量快照端口：按产品、结束日期和刷新意图返回稳定 DataFrame 字段超集。
- SPC 测量端口：返回现有 SPC/CTQ 消费所需字段，保留数据类型、异常值和可选维度过滤契约。
- AOI_TT 测量端口：返回 `factory/prod_code/start_time/sheet_id/lot_id/step_id/tt_name/tt_qty`。
- 应用服务组合入口：显式装配 concrete adapters，避免 app 与 Parquet/SQL/具体仓储耦合。
- 缓存 payload：只包含 DataFrame、原生容器、标量和字符串路径。

**Acceptance criteria:**

- [x] 同一产品/刷新周期只有共享适配器扫描三厂测量表并写入一个原始快照。
- [x] 三个报表端口从共享事实集派生且输出行为与迁移前一致。
- [x] app 不直接访问快照或具体 infrastructure 仓储。
- [x] 空数据、旧策略快照、数据库失败、强制刷新和并发写入有明确测试。
- [x] 定向单元/集成测试与 SPC、CTQ、AOI_TT E2E 通过。

**Out of scope:**

- 改变报表公式、视觉设计、数据库结构或其他领域的数据访问。
