# 为 AOI_RS 报表增加本地数据快照

Category: `enhancement`

Source: 用户任务：仿照 AOI_TT 为 `app/pages/AOI_RS监控报表.py` 增加本地快照，并先评估 DAO 是否应并入共享 `measurement` 基础设施  
Related: `docs/ADR/0007-aoi-rs-report-data-source-and-counting.md`、`docs/ADR/0012-shared-inline-measurement-snapshot.md`、`references/domain/Inline_domain/spec-data_source-aoi_rs.md`

## Current context

- AOI_RS 页面当前只有 `st.cache_data` 页面 payload 缓存；缓存未命中时，应用服务直接调用 AOI_RS infrastructure loader，分别查询三厂 RS Code 明细、三厂过货分母视图和 RS 规格表。
- AOI_TT 通过 application-owned port、composition root 和共享 Inline measurement Parquet 仓储消费本地原始测量快照；该快照按产品隔离，采用三个月滚动窗口、8 小时 TTL、策略版本、原子写入和数据库失败降级。
- 共享 `measurement` 快照的稳定事实契约是连续量测数据：`factory, prod_code, start_time, sheet_id, lot_id, step_id, param_name, site_name, unit_id, param_value`。AOI_RS 的主事实是 RS 缺陷 Code 计数：`factory, prod_code, start_time, sheet_id, lot_id, step_id, rs_code, code_qty`，并依赖结构不同的过货分母事实。
- AOI_RS 与共享 measurement 虽然都按三厂表、产品、时间窗提取，并统一 sheet/glass 字段，但物理表、事实类型、值语义和消费口径不同。把 RS DAO 并入现有 measurement 原始快照会破坏 ADR-0012 的稳定字段及“同源事实才共享”的边界。
- ADR-0007 曾以 AOI_RS 月级数据量较小为由明确决定“不引入 Parquet 快照”。本需求改变了该架构选择；交付时必须用新的 ADR 记录取代范围与理由，而不能静默背离旧决定。
- 当前工作树中的四个 `resources/*_decoration.xlsx` 文件存在用户改动，本任务不得覆盖或回退这些文件。

## Desired outcome

- AOI_RS 获得产品级本地 Parquet 数据快照；正常缓存命中时无需重复查询 RS 明细和过货分母数据库源。
- AOI_RS 专属数据访问、快照和投影职责保留在 AOI_RS infrastructure 边界中，不把 `rs_code/code_qty` 或过货分母语义加入共享 measurement 原始测量契约。
- AOI_RS 应用服务只依赖其拥有的数据端口；具体 SQL、Parquet、TTL、刷新与降级实现由 composition root 在页面边界装配。
- 管理员“刷新数据”能强制更新当前产品的 AOI_RS 底层快照；“刷新缓存”继续只失效当前产品的 Streamlit 页面缓存和重载代码/配置，两层刷新语义与 AOI_TT 一致。
- 数据库刷新失败时，若已有可读快照则继续提供历史快照；没有可用快照时安全返回空数据并保留明确日志，不用空查询结果覆盖最后一份有效快照。
- RS 规格仍作为小型元数据查询独立加载，不进入 RS 明细/过货原始快照；既有统计、修饰、筛选和图表口径保持不变。

**Current behavior:**

AOI_RS 只有 Streamlit payload 缓存。页面缓存未命中时，应用服务直接调用具体数据加载器，查询三厂 RS Code 明细、三厂过货分母视图和 RS 规格表。它没有持久化数据快照、“刷新数据”任务或数据库失败后的本地数据降级能力。共享 measurement 快照服务的是另一套连续量测事实，不能表达 RS Code 计数及其独立分母。

**Desired behavior:**

AOI_RS 通过自身拥有的数据端口读取 RS 明细、过货分母和规格。具体基础设施为前两类产品数据提供可审计的本地 Parquet 快照；快照新鲜时不查相应数据库源，失效时刷新，数据库异常或空结果时保留并降级到已有可读快照。规格仍独立查询。管理员可以强制刷新底层快照，且不会隐式清除 Streamlit 页面缓存。现有统计、规格、修饰和图表行为保持不变。

**Key interfaces:**

- AOI_RS data port：按查询配置提供 RS 明细和过货分母，按产品提供 RS 规格；application 只依赖此接口，不知道 SQL 或 Parquet。
- AOI_RS snapshot repository：按产品和请求结束日期返回原始 RS 数据，支持强制刷新；快照有稳定列契约、策略版本、TTL、滚动窗口、并发冷启动合并、原子写入和安全降级。
- Composition root：装配数据库 loader、AOI_RS snapshot repository 和应用端口，并暴露当前产品底层快照的强制刷新操作。
- Page refresh contract：“刷新数据”只刷新 AOI_RS 底层快照；“刷新缓存”通过产品 revision 失效 Streamlit payload，两者保持分层。

**Edge cases:**

- 数据库异常、返回空结果、快照不存在、快照损坏、策略版本过期、TTL 过期以及快照不覆盖请求日期。

- RS 规格缺失继续按现有无规格行为降级；规格不进入本地数据快照。
