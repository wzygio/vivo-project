## Current context

- 当前 SPC 监控报表已具备产品与时间窗口加载、厂别/站点/参数筛选、Sheet 超规片修饰、月/周/日分布图、Sheet 点位分布图，以及名称含 `UNI` 的参数使用点线图等能力。
- SPC 应用服务会强制查询 `data_type = "SPC"`，并额外计算 CPM/CPK、CPK 预警及 CPK 修饰结果；这些能力不属于 CTQ 报表。
- Inline 基础设施中的物理数据仓储已经支持按白名单 `data_type` 过滤，可直接读取 `CTQ` 数据，无需增加第二套数据源。
- Streamlit 缓存边界受 adr-0001 约束：缓存函数只能返回 DataFrame、原生容器和标量，页面 ViewModel 必须在缓存外构造，并保留模块热重载回归验证。

## Desired outcome

- 新增独立的 CTQ 监控页面，视觉样式和非能力指数交互与 SPC 页面保持一致。
- CTQ 后端位于 `inline_domain` 下独立的 CTQ 子模块中，并在服务边界强制使用 `data_type = "CTQ"`；底层继续复用现有 SPC 物理仓储。
- CTQ 保留筛选、查询门控、Sheet 超规片修饰、月/周/日分布、Sheet 点位分布和 `UNI` 点线图业务规则。
- CTQ 页面和 ViewModel 不暴露、不计算也不渲染 CPM、CPK、CPK 预警或 CPK 修饰功能。

- CTQ Dashboard：渲染与 SPC 一致的筛选和非能力指数图表布局，不提供能力指数指标卡或表格。
- CTQ OOS 修饰资源：行为与 SPC OOS 修饰一致，但持久化边界独立，禁止跨报表污染。
