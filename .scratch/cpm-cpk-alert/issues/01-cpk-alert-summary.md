# 在 CPM/CPK 监控报表中预加载并展示 CPK 预警明细

Category: `enhancement`  
Status: `ready-for-agent`  
Created: `2026-07-14`  
Source: `docs/dev_docs/dev_prompt/feat-CPM.md` 中“Task2-fix：汇总图表优化”  
Related: `docs/adr/0001-streamlit-cache-native-payload-boundary.md`、CPM/CPK 监控报表与 SPC 周期能力数据

## Current context

- CPM/CPK 页面在产品 Header 渲染完成后、筛选框出现前，已经加载当前产品近三个月的原始点位、Sheet 特征、监控指标和月/周/日能力数据。
- 昂贵查询与计算由一个 `st.cache_data` payload 边界缓存；页面 ViewModel 在缓存外构造，以满足模块热重载期间的序列化安全约束。
- “查询”按钮目前只控制按厂别、站点、参数筛选后的图表是否渲染，并不控制上述产品级数据加载。
- 页面尚未提供产品级 CPK 预警汇总。现有 Yield 预警中心提供 Expander、状态提示和明细表的交互参考，但其 Lot/趋势数据契约不适用于 SPC CPK。
- 当前周期能力数据包含月、周、日三类重叠周期，字段包括产品、厂别、站点、参数名称、周期标签和 CPK；数据源没有第二个参数代码或参数描述字段。

## Desired outcome

- 用户进入页面或通过 Header 切换产品后，无需点击“查询”，即可在筛选框上方看到当前产品的 CPK 预警 Expander。
- Expander 清晰显示是否存在低于 `1.33` 的 CPK，并在存在预警时展示可追溯到厂别、站点、参数和日期的明细。
- 预警与查询后的图表复用同一次产品级数据加载及计算结果；Streamlit rerun 不重复执行昂贵查询和能力计算。
- 原有“点击查询后才渲染筛选图表”的行为、CPM/CPK 计算口径和缓存刷新入口保持不变。

## Acceptance criteria

- [x] Header 使用默认产品完成页面初始化后，CPK 预警 Expander 在厂别/站点/参数筛选框之前出现，且不依赖“查询”按钮。
- [x] Header 切换产品后，预警内容随当前产品数据更新，不显示上一产品的结果。
- [x] 预警判定对 `cpk` 做数值化处理，只把有效且严格小于 `1.33` 的记录视为预警；等于 `1.33`、空值和非数值不报警。
- [x] 预警只检查每日 CPK，并保留所有 `CPK < 1.33` 的记录；有预警时按“厂别、站点、参数名称、超规日期、CPK值”五列展示，并采用稳定、可验证的排序。
- [x] 无预警或无能力数据时显示明确的正常/无数据状态，不抛出异常。
- [x] 预警直接消费页面已加载的产品级周期能力结果；点击查询后图表继续复用同一 ViewModel，不触发第二次原始点位、Sheet 特征或 CPK 计算。
- [x] 缓存继续只返回 DataFrame、原生容器和标量；不得把项目自定义 ViewModel 放入 `st.cache_data` 返回值，也不得改用 `st.cache_resource`。
- [x] 页面 Header 的缓存刷新仍能清除实际 CPM payload 缓存；原有筛选、查询门控、管理端超规片功能和三行图表布局保持不变。
- [x] 通过逐条 RED→GREEN 的自动化测试覆盖预警筛选、阈值边界、空数据、页面渲染顺序和缓存复用契约，并通过相关 SPC/CPM 回归测试。

## Out of scope

- 不修改 CPK/CPM 公式、sigma 数据源、月/周/日窗口或 Sheet 超规修饰逻辑。
- 不为 CPK 预警新增数据库查询、持久化报警历史、消息推送、确认/关闭工作流或阈值配置界面。
- 不把 Yield 的 Lot/趋势预警数据模型直接复用到 SPC 页面，也不重构其他报表的预警中心。
- 不改变筛选后的图表必须点击“查询”才渲染的现有交互。
