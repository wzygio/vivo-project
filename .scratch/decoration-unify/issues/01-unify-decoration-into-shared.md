# 修饰逻辑统一：修饰算法收敛 shared + aoi 对齐 spc/ctq（自动修饰 + 工作簿释放/删除）

Category: `enhancement`

Created: `2026-08-14`  
Source: `docs/dev_docs/dev_spec/Inline_domain/feat-decoration_unify.md`  
Related: `.scratch/decoration-unify/PRD.md`、`docs/dev_docs/generated/Inline_domain/decoration-unify-proposal.md`、`docs/dev_docs/generated/Inline_domain/spc-ctq-decoration-analysis.md`、`docs/dev_docs/generated/Inline_domain/decorated-features-pipeline.md`

## Current context

- 核心修饰引擎 `core/spc/spc_sheet_oos_decoration.py`（三态 flag：Delete 删除 / True 截断 / False 释放 + 稳定哈希截断 + 工作簿持久化）是单份实现，被 spc/ctq/monitor 共用，但物理位于 spc 包内，ctq/monitor 跨包反向依赖。
- 应用层包装重复：`application/spc/spc_data_decoration.py` 与 `application/ctq/ctq_data_decoration.py` 约 90% 逐行重复，差异仅工作簿文件名（`spc_sheet_oos_decoration.xlsx` vs `ctq_sheet_oos_decoration.xlsx`）、持久化参数名、是否保留修饰前特征。
- `application/shared/decorated_features.py::fetch_decorated_features` 已是统一缓存管线（scope=spc/ctq/none），但路由的下层仍是上述两个重复 wrapper；ctq 分支存在延迟导入循环依赖。
- CPK 双轨（真实/修正）已于 2026-08-14 移除（用户决策）：CPK 仅基于修饰后点位计算，`cpk_actual` 不复存在；修饰前特征（original_*）因此无消费方，仍随 payload 透传并多算一次特征。
- aoi_tt 在 service 层调用 `core/shared/auto_decoration.py::auto_clip_over_spec` 做超规截断（位置正确）；aoi_rs 的截断在图表组装层 `app/sections/aoi_rs/aoi_rs_dashboard.py:416-425`（By Lot 用 LOT_RATIO 规格、By Sheet 用 SHEET_ID/GLASS_ID 规格，两次独立截断），service 显式不做（`aoi_rs_service.py:106-107`）。
- aoi_tt/aoi_rs 均无"配置文件指定释放或删除"能力；spc/ctq 的该能力由 `resources/` 根目录工作簿（每产品一个 sheet）承载。
- 截断语义已单一来源：`auto_decoration.py` 复用引擎的 `_stable_fraction`，margin 均为 5%~15% span。

## Desired outcome

- 修饰算法在 shared 中只存在一份：引擎迁入 `core/shared/`，应用层统一为按 scope 参数化的单一入口，spc/ctq 两个 wrapper 删除；统一后 SPC/CTQ/monitor 数据口径与统一前一致。
- 修饰前特征（original_*）透传随 wrapper 合并一并清理，payload 精简，少一次特征重算。
- aoi_rs 截断下移到 service 层，section 层只消费修饰后数据做渲染，无任何修饰逻辑与未修饰数据依赖（用户决策 D4：是否修饰由 application 层决定）。
- aoi_tt / aoi_rs 各新增修饰工作簿（`resources/` 根目录、每产品一个 sheet），复用三态 flag 语义：默认自动截断（与现状一致）、`False` 释放真实值、`Delete` 删除；aoi_rs 工作簿需区分 By Lot / By Sheet 图表口径。
- 引擎键列从硬编码 `OOS_KEY_COLUMNS` 泛化为参数，spc/ctq 既有行为不变。
- "改工作簿 → 页面刷新缓存生效"操作契约固化到文档；三份分析文档更新至最终状态。

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement  
**Summary:** 将 inline_domain 的数据修饰收敛为 shared 中的单一算法（引擎归位 + 应用层 wrapper 合并 + 清理修饰前特征透传），并把 aoi_tt/aoi_rs 对齐到 spc/ctq 的修饰能力：自动截断保持默认，新增工作簿三态 flag（True 截断 / False 释放 / Delete 删除）；aoi_rs 截断从 section 层下移到 service 层。

**Current behavior:**

- 引擎 `core/spc/spc_sheet_oos_decoration.py` 单份但位于 spc 包内，ctq/monitor 反向依赖；键列硬编码 `OOS_KEY_COLUMNS = [prod_code, step_id, param_name, sheet_id]`。
- 应用层两个 wrapper（spc/ctq）约 90% 重复，仅文件名/参数名/是否保留修饰前特征不同；`decorated_features.py` 双分支路由，ctq 分支延迟导入。
- CPK 已单轨（2026-08-14 落地），original_* payload 键无消费方仍透传。
- aoi_tt：service 层 `auto_clip_over_spec`（join_keys=[step_id, tt_name]，value=tt_qty，单边 USL）；无工作簿。
- aoi_rs：截断在 `app/sections/aoi_rs/aoi_rs_dashboard.py:416-425`，`attach_spec_values(chart_kind="lot"/"sheet")` 后分别 `clip_over_spec_column`；service 不做修饰。

**Required behavior:**

- 引擎迁入 `core/shared/`，键列泛化为参数，spc/ctq 行为逐行不变（先跑绿现有测试再动）。
- `application/shared/` 单一装饰入口（scope→工作簿文件名映射），删除 spc/ctq 两个 wrapper；payload 移除 original_* 键；ctq 延迟导入消除。
- aoi_rs 的两次截断（By Lot / By Sheet）在 service 层完成，payload 产出图表就绪数据；section 只渲染，无修饰调用、无未修饰数据消费。
- aoi_tt/aoi_rs 修饰工作簿：`resources/` 根目录、每产品一个 sheet；默认自动截断（现状一致），`False` 释放、`Delete` 删除；缺文件/缺 sheet 按空修饰语义；aoi_rs 工作簿区分图表口径。
- 改工作簿 → 页面"刷新缓存"生效；缓存命中不重读工作簿。

**Key interfaces:**

- 引擎 `prepare_sheet_oos_decoration(..., key_columns=...)`（新增参数，默认值保持 spc/ctq 现状）；`auto_decoration.py` 继续复用其 `_stable_fraction` 与 margin 常量。
- 统一入口（如 `prepare_decorated_data(raw_measurements_df, spec_df, prod_code, scope, persist)`）返回修饰后 measurements + features + decoration result。
- `fetch_decorated_features` payload 键：去除 `original_sheet_features_df`/`original_raw_measurements_df`，其余不变；spc_service 的空数据判断改用修饰后数据。
- 缓存边界遵守 ADR-0001：`st.cache_data` 只跨 DataFrame/原生容器/标量。

**Edge cases:**

- 工作簿缺失、产品 sheet 缺失、企业加密文件（openpyxl 失败回退 Excel COM）→ 空修饰语义（默认截断）。
- flag 解析：空值/无法识别默认 True；`Delete` 大小写不敏感；`False` 兼容 `false/0/no/n/否/不修饰/不截断`。
- aoi_rs 双规格：同一 rs_code 行可能需要在 By Lot 图中修饰、By Sheet 图中释放（或反之），键设计必须含图表口径维度。
- 单边规格（无下限）截断到上限 85%~95%；非法规格（usl<=lsl）不修饰。
- aoi 明细缺 sheet_id/lot_id 列时按键候选降级并在 issue 留痕（D6）。

**Verification expectations:**

- 重构段前后 SPC/CTQ/monitor 数据口径一致；定向单元/集成测试全绿；全量 pytest 不引入新失败（既有基线：yield_global_data_policy ×2、code_selector_filter ×2 等）。
- E2E：SPC / CTQ / AOI_TT / AOI_RS / 自动预警全部通过（含 aoi 工作簿 flag 行为验证）。

**Out of scope:**

- monitor AOI 组 scope 切换、合规洗白、CPK flag 语义、历史 flag 数据迁移、aoi 参数识别集统一。
