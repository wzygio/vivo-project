# Inline 密集点测试报表

Status: ready-for-agent
Date: 2026-11-03
Mode: general
Authorization: 用户要求完成 development-flow，所有选项选择默认；采用下述推荐方案、测试边界和执行顺序。

## Problem Statement

用户需要在门户的 Inline指标下，按产品查看已有密集点测试工作簿的明细与三阶段膜位汇总。

## Solution

新增密集点测试报表，按产品配对读取 detail/summary 工作表，展示完整明细与调整前、调整后、修正后三类汇总。保留来源值，不重新推算汇总。

## User Stories

1. 作为工程师，我希望在 Inline指标中打开密集点测试报表。
2. 作为工程师，我希望明确选择产品，避免混看不同产品数据。
3. 作为工程师，我希望查看全部明细字段和记录并使用原生表格排序、搜索和 CSV 下载。
4. 作为工程师，我希望分别查看调整前、调整后、修正后的膜位汇总。
5. 作为工程师，我希望每条汇总保留 Sheet ID、膜位、MAX、MIN、AVE、STD、极差。
6. 作为工程师，我希望相同膜位在不同大板或阶段的记录不被合并。
7. 作为工程师，我希望文件更新后缓存自动失效，也可使用页面刷新重读。
8. 作为工程师，我希望无数据和读取失败都有明确业务提示。

## Implementation Decisions

- Indicator 的独立 point_test 子领域拥有读取与报表投影，前端归属同一能力；不查询数据库。
- Application 的读取端口返回按产品配对的原始明细/汇总；Core 负责纯解析和验证；Infrastructure 处理标准/企业加密工作簿。Composition 解析全局资源注册路径。
- 产品从 `<product>-detail` / `<product>-summary` 成对名称确定，当前只有 Z576；不从 PRODUCT_SPEC 或其他字符串猜测产品。不完整配对是来源错误。
- 展示和下载范围取工作簿产品与全局 enabled_products 的交集，顺序以全局配置为准，注释仅用于选择器标签，配置变化清理失效选择。
- 忽略不匹配的辅助 sheet；不将 Sheet3/Sheet2 加入报表。未来可增加同结构的产品对。
- 汇总按首列阶段标题划分纵向块，块内三组横向列；只在本块、本组中向下补全 ID，空白和新标题重置状态。输出产品、阶段、Sheet ID、膜位和五个指标。
- 明细没有膜位字段，不推测 SITE_NAME 到膜位映射；不从明细重算汇总。Excel 时间序列转换为日期时间，保留其他字段和值。
- 三阶段属于用户明确要求的业务分类，可在普通展示中出现；它们与系统管理员修饰模式无关。页面不暴露技术路径、异常详情或管理员入口。
- 缓存只保存原生 DataFrame/容器，键包含配置完整路径、mtime_ns、size，TTL/容量有界；更换来源、文件更新、手动刷新均不保留旧投影。
- 文件来源无可统一使用的三阶段事件时间，不套用实时 Indicator 查询的日期前推、截止或日期排除；否则汇总会与工作簿失配。

## Testing Decisions

首选公开应用服务 + 临时标准工作簿 adapter 进行集成验证；生产 section 通过注入真实 service 进行 AppTest。覆盖 936/216 的真实来源核对、多产品、重复块、缺失与非法格式、空态、失败脱敏和恢复、缓存换源/更新。浏览器使用无数据库测试页覆盖桌面/平板/手机布局及产品和阶段切换，并用来源值验证实际读取链路。架构守卫检查层间依赖。

## Out of Scope

数据库接入、上传与编辑、测点膜位映射推断、统计重算、第三第四张工作表、告警、图片抓取、规格判定以及修改既有业务。
