# 创建 Q-Time 监控报表

Category: `enhancement`
Status: `ready-for-agent`

## Current context

- 系统当前仅在旧门户配置中链接外部 FineReport Q-Time 页面，没有 Python + Streamlit 的仓库内实现。
- 参考页面的用户流程为时间范围、厂别、产品、From-To 路径级联筛选，查询后展示 Lot 级等待时长柱状图、Q-Time 规格线和双语明细表。
- FineReport 查询契约给出 `step_desc`、`lot_id`、`prod_qty`、`sub_prod_type`、`f_step`、`t_step`、`q_spec`、`wait_time`、`timekey`、`prodcode`；厂别由 `f_step` 首字符映射为 ARRAY/OLED/TP。
- 只读数据库探查确认 `QTIME_TZBJX` 解析为 `mdw.qtime_tzbjx`，列与任务 SQL 一致；`eda.imp_qtime_tzbjx` 是产品/站点规格配置源。当前应用账号能读取元数据，但对这两张目标表没有 `SELECT` 权限。
- 页面必须遵守薄入口、section、图表/表格适配器的展示边界；后端建立独立 DDD domain，页面不直接访问数据库。

## Desired outcome

- 新增仓库内 Q-Time Streamlit 页面，用户可以选择半开区间时间范围、厂别、From-To 路径和一个或多个产品后执行查询。
- 查询结果以参考样式呈现：等待时长按 Lot 的青色柱状图、红色 Q-Time 规格线，以及带序号和双语列名的明细表。
- 数据访问使用参数化 SQL，明确处理空筛选、非法时间范围、空数据和数据库/权限错误，不泄露连接信息。
- 输出数据源分析文档，记录源表、字段映射、时间口径、筛选口径、探查证据和当前权限前置条件。

## Acceptance criteria

- [ ] 页面可由 Streamlit 自动发现并打开，入口保持为薄组合层，页面标题为“北极星QTime监控”。
- [ ] 筛选顺序和依赖为时间范围 → 厂别 → From-To 路径 → 产品；结束时间按排他上界处理，查询按钮明确门控数据加载。
- [ ] 厂别映射严格为 `f_step LIKE '1%'` → ARRAY、`LIKE '2%'` → OLED、其余 → TP；路径选项受厂别约束。
- [ ] 明细仓储仅通过参数化查询访问 `mdw.qtime_tzbjx`，返回规范化且稳定排序的目标字段；空产品列表表示不过滤产品，不拼接用户输入到 SQL。
- [ ] 图表对每条明细显示 `wait_time` 柱，并叠加对应 `q_spec` 红色规格线；空数据、缺失/非数值规格和部分字段缺失均有安全、明确的展示行为。
- [ ] 明细表显示序号、QTime监控、LotID、ProductQTY、ProductionType、FromOperation、ToOperation、T_TimeMeasure、WaitTime，且保持参考图的蓝色表头与斑马纹语义。
- [ ] 数据源分析文档说明 `eda.imp_qtime_tzbjx` 与 `mdw.qtime_tzbjx` 的职责和当前 `SELECT` 权限限制，不把不等价的 ARRAY-only 视图当作静默替代源。
- [ ] 单元/集成测试覆盖查询参数、厂别映射、时间边界、筛选级联、图表/表格模型和错误/空状态；浏览器 E2E 使用隔离数据验证筛选、查询、图表和表格关键流程并通过。
- [ ] 既有页面和相关测试无新增回归，生产代码不修改用户已有的资源工作簿或任务文档改动。

## Out of scope

- 变更目标数据库表、申请/授予数据库权限或修改 FineReport 报表。
- 复刻 FineReport 自带的分页、打印、邮件和通用导出工具栏。
- 将权限不足时切换到业务语义不同且查询代价高的 `mdw.dwr_qtime_info_v`。
