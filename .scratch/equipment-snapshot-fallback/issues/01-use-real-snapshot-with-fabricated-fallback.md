# 关键备件报表采用真实快照优先、仿造快照补缺

Related: `.scratch/equipment-data-fabrication/issues/02-fabricate-blank-parameter-specifications.md`

## Current context

- 关键备件规格来自 CSV；测量快照按规格内容签名写入 `data/equipment/part_life_snapshot_<signature>.parquet`。
- 数据库查询快照与仿造器当前使用相同文件名。仿造数据会在真实快照超过 TTL 或手动刷新后被数据库结果覆盖，无法稳定作为缺口回填来源。
- 报表匹配当前只接收一份快照。非空参数按 SQL LIKE 语义匹配；空参数通过稳定内部合成键精确匹配。
- 当前仿造逻辑按正常、预警、超规比例生成一个统一时间点，不符合新的首次生成和按日更新规则。
- 页面数据服务使用 `st.cache_data` 原生载荷边界；该缓存契约必须保留。

## Desired outcome

- 真实数据库快照与仿造快照使用互不覆盖的文件和生命周期。
- 每条规格先匹配真实快照；仅在真实快照无匹配记录时使用仿造快照，不允许仿造值覆盖真实值。
- 首次仿造与后续更新由独立程序和独立业务函数负责。
- 首次生成的测量值位于对应寿命规格的 0% 至 100%，测量时间随机分布在生成时刻前两天内。
- 仿造快照有效期为 24 小时。更新时测量时间在原值上增加一天，测量值增加寿命规格的 30%；超过寿命规格时改为寿命规格 30% 以内的随机值。
- 更新后的数据集可由关键备件报表消费，并通过自动化与浏览器烟测。

## Acceptance criteria

- [x] 数据库快照继续使用既有生产文件名；仿造快照使用独立且可由同一规格签名定位的文件名，两者不得互相覆盖。
- [x] 首次生成程序不读取或更新已有仿造快照；已有目标文件默认明确失败，只有显式覆盖才可替换。
- [x] 更新程序必须读取已有仿造快照；不存在、结构无效或无法映射寿命规格时明确失败，不静默退化为首次生成。
- [x] 首次生成对每个唯一可监控规格键产生一条记录；每个值满足 `0 <= value <= 寿命规格`，每个时间满足 `as_of - 2天 <= time <= as_of`，固定种子与 `as_of` 可复现。
- [x] 更新保持键集合与行数不变；时间逐行增加一天；未超过规格线时值增加 `0.30 * 寿命规格`，超过时值按固定种子重新落入 `[0, 0.30 * 寿命规格]`。
- [x] 仿造快照 TTL 独立配置为 24 小时；更新程序在快照仍有效时不修改文件并报告跳过，过期或显式强制时执行一次更新。
- [x] 报表逐规格实行真实优先、仿造补缺。真实与仿造均匹配时选择真实；真实不匹配而仿造匹配时选择仿造；两者均不匹配时保留空测量值。
- [x] 非空参数 LIKE、空参数内部合成键、预警计算、数据修饰、前端隐藏参数列和 `st.cache_data` 原生载荷边界保持兼容。
- [x] 使用真实规格生成新的独立仿造数据集；验证完整报表中真实可命中的规格使用真实值，其余规格由仿造值补齐。
- [x] 生成/更新单元测试、真实规格集成测试、设备域 smoke 和关键备件页面浏览器烟测全部通过。

## Out of scope

- 不修改数据库表、SQL 查询口径或真实快照 8 小时 TTL。
- 不把仿造数据写回数据库，不在前端暴露内部合成键或数据来源调试列。
- 不仿造历史趋势序列；每次更新只推进现有当前记录一天。
- 不改变既有预警阈值和超规展示修饰规则。

## Questions to resolve
