# Inline Sheet OOS：修饰刷新门控与人工决策持久化（产品 sheet / `__flags` / `__refresh_meta__`）

Source: `docs/PRD/PRD-2026-08-18-Inline-Sheet-OOS修饰刷新与决策持久化.md`
Related: `.scratch/decoration-unify/issues/01-unify-decoration-into-shared.md`（修饰统一前作）、`docs/ADR/`（ADR-0001 缓存边界、ADR-0014 修饰统一）

## Current context

- L1 快照：`data/<product>/inline_measurements_<product>.parquet` 由 `InlineMeasurementSnapshotRepository` 管理，TTL 8 小时，`force_refresh=True` 时从数据库重建。
- L2 缓存：`application/shared/decorated_features.py::fetch_decorated_features` 带 `st.cache_data(max_entries=12, ttl=4h)`；SPC 外层 payload TTL 4h；CTQ 外层 payload 在 `ctq_service.py:81` 仅 `max_entries=1`、**无 TTL**。
- 产品级失效机制已存在：`app/components/page_header.py` 的 `build_product_cache_signature` / `bump_product_cache_revision` / `invalidate_page_cache(product_code=...)`，revision 存于 `output/tmp/product_cache_revisions/`。
- 页头“刷新数据”（`_refresh_data_callback`）只执行 L1 refresh handlers，成功后仅 toast 提示，**不失效 L2**；“刷新缓存”（`_hard_reset_callback`）才推进产品 revision 并做代码/配置重载。
- 修饰工作簿：`resources/spc_sheet_oos_decoration.xlsx`、`resources/ctq_sheet_oos_decoration.xlsx`，每产品一个 sheet；当前产品 sheet 同时保存当前 OOS 明细和人工 `flag`。当前明细经“当前 OOS LEFT JOIN 旧 flag”重建——旧记录一旦不再属于当前 OOS 集合即从 sheet 消失，**人工决策随之丢失**。
- `fetch_decorated_features` 在任意缓存 miss 时以 `persist=True` 运行（`decorated_features.py:148-154`）；TTL 到期、容量淘汰、进程重启、参数差异都会重写工作簿。
- `replace_workbook_sheet()`（`src/shared_kernel/utils/excel_tools.py:93`）返回 `None` 且吞掉 `PermissionError`（仅告警），调用方无法区分“成功写入”与“被占用跳过”；企业加密工作簿走 COM 整体重写回退，无多 sheet 原子提交。
- 页面 `snapshot_signature` 含页面 base（SPC/CTQ/Monitor 各不相同），不能作为跨页面共享的生成判定键。
- 三态修饰语义（True 截断 / False 释放 / Delete 删除）、稳定哈希截断、决策匹配键 `(prod_code, step_id, param_name, sheet_id)` 已稳定，不在本次改动范围。

## Desired outcome

- 页头“刷新数据”在所有 L1 handler 成功后推进当前产品 revision（失效 L2），任一失败则保持 L2 与 revision 不变；成功提示为“L1 快照与 L2 缓存已刷新”；不执行代码卸载/配置重读（仍属“刷新缓存”）。
- 工作簿改为三 sheet 结构：产品 sheet（系统所有，当前 OOS 明细+解析 flag）、`<产品>__flags`（管理员决策台账，跨窗口长期保留）、`__refresh_meta__`（系统内部生成状态，scope/prod_code/last_generated_at/product_revision/decision_signature/detail_row_count）。
- 旧单 sheet 工作簿首次读取时自动迁移出 `__flags`（保留全部 flag、重复键取最后一行、幂等），迁移与明细重建、meta 写入同一成功事务。
- 生成门控：仅在“明细/meta 缺失、距上次成功生成满 4 小时、共享产品 revision 变化、决策内容签名变化”之一成立时重建并写入；普通 rerun、进程重启后 4h 内、L2 容量淘汰、系统自写导致的 mtime 变化、其他产品 sheet 更新均不得触发重写。
- 决策签名两阶段：`file_stat_signature=(mtime_ns,size)` 只触发重读；进入缓存键与 meta 的是 `__flags` 规范化内容哈希。系统重写产品 sheet 不改变决策 hash，不形成自触发循环。
- 运行时合并：当前 OOS 明细 LEFT JOIN `__flags`，命中用持久化 flag，未命中默认 True；历史键保留在 `__flags` 但不进入当前明细；同键重现时恢复原决策。
- 写入可靠性：新增明确的 `WorkbookWriteResult`；产品 sheet + `__flags`（首次迁移）+ `__refresh_meta__` 经临时文件验证后原子替换；写入失败（文件占用/COM 失败/临时保存失败/替换失败）时 `written=False` 或抛出业务异常，不更新 meta、不清缓存、不显示成功；同工作簿进程内锁。
- 管理员下载包含“当前明细 + 决策台账”两个 sheet；上传以“该产品完整决策集覆盖”语义写入 `__flags`（兼容旧单 sheet），不直接覆盖系统产品 sheet；内容与现有决策规范化一致时不强制重写。
- CTQ 外层缓存补齐 4h TTL（或等价边界调整），保证 4h 共享生成判定可达；SPC/CTQ/Monitor 外层缓存不得永久遮挡共享层。

## Acceptance criteria

- [ ] “刷新数据”全部 handler 成功后当前产品 revision 变化、下一次运行 L2 miss；任一失败时 revision 与 L2 均不变；提示文案为“L1 快照与 L2 缓存已刷新”；“刷新数据”不做模块卸载与配置重读。
- [ ] “刷新缓存”维持 hard reset（推进 revision、清 ViewModel memo、重载代码配置），revision 变化使生成判定返回 `product_revision_changed`，即使不足 4h 也重写一次。
- [ ] 旧工作簿首次迁移生成 `<产品>__flags`，全部旧 flag 保留（含显式 True），重复键取最后一行，迁移幂等；迁移失败保留原文件。
- [ ] 某 OOS 行消失后其决策仍在 `__flags`；同键重现恢复原 True/False/Delete；历史键不进入当前产品 sheet 与图表；SPC 与 CTQ 决策互不影响。
- [ ] 相同 revision + 相同决策签名 + 距成功写入不足 4h 时：普通 rerun、进程重启、L2 容量淘汰均不改工作簿；满 4h 后第一次有效调用只重写一次并重置 `last_generated_at`。
- [ ] 系统自写产品明细导致 xlsx mtime 变化但决策 hash 不变时，不触发二次重写；修改其他产品 sheet 不触发当前产品重写；管理员修改 `__flags` 后立即触发一次重写。
- [ ] 文件被占用时页面显示失败，旧文件与旧 meta 不变；任一 sheet 保存失败不出现“部分新明细 + 新 meta”；写入成功后可由 openpyxl 或 COM 回退重新读取；其他产品 sheet、决策 sheet、meta 行保持不变。
- [ ] 下载文件含当前明细与决策台账两个 sheet；上传决策后图表按新 flag 生效；上传内容与现有决策一致时不强制重写；上传失败不清缓存、不显示成功、不更新 meta。
- [ ] 每次生成判定记录结构化日志（product/scope/decision_signature 前 12 位/product_revision/last_generated_at/refresh_reason/write_attempted/write_succeeded/detail_row_count），不含完整业务明细。
- [ ] 定向单元/集成测试全部通过；全量 pytest 不引入新失败（既有失败基线除外）；SPC 报表 smoke 与管理员 UI 验收通过。

## Out of scope

- L1 Parquet 的 8h TTL、三个月窗口、数据库失败降级、策略版本；不新增 L1 revision 文件，不把 L1 mtime/hash 加入页面缓存签名。
- `spc_cpk_decoration.xlsx`；AOI_TT/AOI_RS 自有修饰工作簿的迁移。
- 把工作簿改造成历史 OOS 事实仓库；用户身份、审批流、决策审计数据库。

**Category:** enhancement
**Summary:** 为 SPC/CTQ 共用的 Sheet OOS 修饰链路建立可预测的刷新生命周期：页头“刷新数据”L1 全成功后失效产品 L2；修饰工作簿拆分为“产品 sheet（系统所有，当前明细）+ `<产品>__flags`（人工决策台账，跨窗口持久）+ `__refresh_meta__`（系统生成状态）”；引入 4h/revision/决策签名三因素生成门控与多 sheet 原子写入，杜绝普通 rerun 反复重写工作簿与人工决策丢失。

**Current behavior:**

- `_refresh_data_callback`（`app/components/page_header.py:121-139`）只跑 L1 handlers，成功后 toast“需要重读页面缓存时请点击刷新缓存”，不失效 L2。
- `persist_sheet_oos_decoration`（`src/inline_domain/core/shared/sheet_oos_decoration.py:297-313`）以“当前 OOS LEFT JOIN 旧 sheet flag”重建产品 sheet，历史键随明细消失丢失决策。
- `fetch_decorated_features`（`application/shared/decorated_features.py:76,148-154`）任意缓存 miss 均 `persist=True` 重写工作簿；CTQ 外层缓存（`ctq_service.py:81`）无 TTL，可永久遮挡 4h 共享判定。
- `replace_workbook_sheet`（`src/shared_kernel/utils/excel_tools.py:93-142`）返回 `None`、`PermissionError` 仅告警；加密工作簿 COM 整体重写，无原子提交。
- 已有可复用机制：产品 revision 文件（`output/tmp/product_cache_revisions/`）、`bump_product_cache_revision` / `invalidate_page_cache(product_code=...)`、`read_workbook_sheet` COM 回退、三态 flag 解析与稳定哈希截断。

**Required behavior:**

- 刷新数据：全部 handler 成功 → `invalidate_page_cache(product_code=...)` 推进 revision + 提示“L1 快照与 L2 缓存已刷新”；任一失败 → revision/L2 不动、提示失败；不做模块卸载/配置重读。
- 工作簿三 sheet：产品 sheet 仅存当前明细；`<产品>__flags` 持久决策（最小列 prod_code/step_id/param_name/sheet_id/flag）；`__refresh_meta__` 记录 scope/prod_code/last_generated_at/product_revision/decision_signature/detail_row_count。
- 旧表迁移：产品 sheet 存在而 `__flags` 缺失时，迁移全部 flag（重复键取最后一行、幂等）→ 重建明细 → 同事务写 meta；失败保留原文件。
- 生成判定纯函数 `should_regenerate_detail(...)` 返回 `RefreshDecision(should_write, reason ∈ {missing, ttl_expired, product_revision_changed, decision_changed, unchanged})`；判定与日志基于共享产品 revision 而非完整页面 signature。
- 决策签名两阶段：mtime/size 探针决定是否重读 `__flags`；规范化内容 SHA-256 作为业务签名进入缓存键与 meta；探针结果按 file_stat 缓存避免反复启动 COM。
- 写入：`WorkbookWriteResult(written, path, updated_sheets, error)`；多 sheet 经同目录临时文件 + 可读性验证后原子替换；进程内锁；失败时调用方不更新 meta、不清缓存、不显示成功。
- 管理员：下载含“当前明细 + 决策台账”；上传以完整集覆盖语义写 `__flags`（兼容旧单 sheet），校验键列/flag 枚举/重复键，内容一致不重写，失败不显成功。
- CTQ 外层缓存补 4h TTL（或等价边界调整）；SPC/CTQ/Monitor 均不遮挡共享 4h 判定。

**Key interfaces:**

- `should_regenerate_detail(*, current_sheet_exists, last_generated_at, stored_product_revision, current_product_revision, stored_decision_signature, current_decision_signature, now) -> RefreshDecision`（PRD §5.5）。
- `WorkbookWriteResult(written: bool, path: Path, updated_sheets: tuple[str, ...], error: str | None)`（PRD §5.10）。
- `SheetOosDecorationResult` 可新增 `decision_sheet` / `decision_df` / `refresh_reason`，现有字段保留。
- 决策匹配键不变：`(prod_code, step_id, param_name, sheet_id)`；产品 sheet 13 列结构不变。

**Edge cases:**

- `__flags` 无法读取时必须显式失败，不得降级为空决策（防止历史 flag 被解释为默认 True）。
- 空 `__flags` 上传 = 清空显式决策，后续全部默认 True。
- 直接编辑系统产品 sheet 不视为决策变更，下次允许刷新时被覆盖。
- 企业加密文件：COM 回退整体重写为明文的既有行为不变，但必须日志记录；临时文件验证前不得替换正式文件。
- 同工作簿并发写入：进程内锁（多进程部署留文件级锁扩展点）。
- meta 不存完整页面 base signature，避免 SPC/CTQ/Monitor 交替触发重建。

**Verification expectations:**

- 单元：页头刷新契约（全成功/部分失败/无产品作用域）、生成判定全分支（含 4h 边界）、迁移（重复键/空表/幂等）、合并（消失/重现恢复 flag）、签名（行序无关、flag 变化、明细变化不影响决策 hash）、写入结果（成功/PermissionError/COM 失败/临时保存失败/替换失败）。
- 集成：临时多 sheet 工作簿迁移；改 `__flags` 后 payload 同步；系统写明细后 mtime 变化无二次写；`force_refresh` 成功推进 revision；刷新失败保留旧 L2 与工作簿。
- 全量 pytest 不引入新失败（既有基线除外）；SPC smoke 与管理员 UI 验收（下载双 sheet、上传生效、占用显失败、连续 rerun 不改 mtime）。

**Out of scope:**

- OOS 判定/截断算法/flag 解析、L1 8h TTL 与快照策略、`spc_cpk_decoration.xlsx`、AOI_TT/AOI_RS 工作簿迁移、用户身份与审计数据库。
