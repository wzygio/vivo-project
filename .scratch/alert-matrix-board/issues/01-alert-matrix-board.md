## Current context

- `app/pages/自动预警看板.py` 已是全产品模式：固定 `prod_code="ALL"`，`MonitorAnalysisService.fetch_dashboard_data_dict` 逐产品循环加载并缓存（TTL 12h），缓存键已含逐产品 revision 与 (prod, scope) 决策签名；页面不参与 Header 单产品筛选，自带控制台对已缓存数据前端切片。
- 上一期已交付五个单产品页面的预警中心（单片异常 flag=FALSE + 趋势波动，含异常项图像自动渲染，见 `.scratch/inline-alert-center/`）。
- 当前自动预警看板仅展示汇总图与 Top10 站点图，**没有"产品 × 监控参数"的达标矩阵**，客户无法一眼看出哪个产品的哪个参数上一周不达标。
- qtime（`app/pages/Q_Time监控报表.py`）全链路**无任何缓存**，每次查询实时打生产库；服务层已支持多产品（空 tuple = 全产品），ADR-0019 记录过目标表权限与超时历史。
- `fetch_decorated_features` 缓存 `max_entries=12`（`src/inline_domain/application/decorated_features.py:79`），矩阵模式 7 产品 × 2~3 scope = 14~21 条目，会产生淘汰抖动。
- `safe_refresh_snapshots` 任一产品失败即整体不推进 revision，全产品模式下需要单元格级降级。
- 渲染门 `RenderGate`（stage/collect/collect_memoized）与 SPC 预警图像懒加载管线（`spc_dashboard.py:762-828`）均已就绪可复用。

## Desired outcome

- 自动预警看板页首展示**产品 × 监控参数预警矩阵**：列 = 启用产品（当前 7 个），行 = 八个监控参数（aoi_rs/aoi_tt/spc/ctq 单片异常、spc 趋势波动 cpk、yield lot 超规、yield 良率波动、qtime 单片异常）。
- 单元格为四态指示灯：🟢 达标（上一 ISO 周无预警）/ 🔴 不达标 / ⚪ 无数据 / ⬜ 加载失败（灰点 + tooltip 原因）。
- 点击红点单元格后，懒加载该 (产品, 监控参数) 的预警明细表与图像（复用各域既有预警图像管线），不阻塞矩阵本体渲染；矩阵本体不自动渲染图像（需求方确认的妥协 D1）。
- qtime 接入矩阵前先补缓存层：`@st.cache_data`，键含产品集合 + 时间窗 + 修饰决策签名（文件 mtime 门控），TTL 与 inline 对齐（需求方确认 D2：qtime 相关风险全部按可行性报告建议修正）。
- `fetch_decorated_features` 的 `max_entries` 由 12 调大至 ≥ 32。
- 任一产品/任一域失败时仅对应单元格灰点降级，其余正常；矩阵计算只读，不触发任何修饰工作簿重写。

**Required behavior:**

- 矩阵 payload 构建服务（纯计算、无 st.*）：输出 `{products, rows, cells: {(row_key, prod): {state, detail_key, message}}, signature}`；四态 `ok|alert|no_data|error`；各域适配器仅做"既有预警记录集合 → 四态"映射，任一域/产品异常捕获后映射为 `error` 态。
- 矩阵缓存键 = 逐产品 revision 字典 + 逐 (prod, scope) 决策签名 + 上一 ISO 周时间窗；键组装集中在矩阵服务一处（先例：`自动预警看板.py:107-117`）。
- 前端：矩阵置于 `自动预警看板.py` 页首；单元格色点可点击；点击红点展开该 (产品, 行) 详情（明细表 + 图像），复用各域既有预警图像渲染函数与 `RenderGate.collect_memoized`，chart key 前缀 `matrix_detail`；渲染遵守 RenderGate 两阶段。
- qtime 缓存层（§4.3）：键 = (products, shop, step_options, 时间窗, 决策签名)，TTL 12h；决策签名按修饰工作簿 (mtime_ns, size) 门控；既有单产品页面交互不变。
- `decorated_features.py:79` `max_entries` 12 → 32。

**Key interfaces:**

- `build_alert_matrix_payload(*, reference_date) -> dict`（schema 见 PRD §4.1）
- 各域适配器：`(prod, reference_date) -> {"state": ..., "detail_key": ..., "message": ...}`
- qtime 缓存包装（不改动 `QTimeReportService` 公共签名语义）

**Edge cases:**

- 某产品 parquet 缺失/损坏 → 该产品全部单元格 ⬜；某域整体失败 → 该行 ⬜；跨年初 ISO 周；启用产品清单变化（config/global.yaml）；缓存签名任一维度变化触发重建；点击详情时底层数据已刷新（详情独立签名）；yield/qtime 时间口径与 ISO 周对齐的边界。
