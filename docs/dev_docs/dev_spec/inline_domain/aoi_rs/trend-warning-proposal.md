## Problem Statement

AOI_RS 监控报表已有上一 ISO 周的单片异常预警，但未识别未超规格的日密度上升。用户要求参考提供的 RSCode 密度分析代码及 Yield 异常检测方式，增加独立趋势预警，并把最终业务逻辑记录到 AOI_RS 领域知识目录。

## 已核实的现状

- AOI_RS 密度为同厂别、站点、周期内 `SUM(code_qty) / COUNT(DISTINCT sheet_id)`，可大于 1。不能照搬参考程序的缺陷行数分子，也不能将 Yield 的 0.2 个百分点阈值直接用于 RS/片。
- 当前页面先显示已有单片异常中心及其自动图像，再按查询门控显示手动筛选结果。趋势预警应作为另一独立区域，在未手动查询时也可展示。
- Yield 使用 Core 检测器返回结构化预警记录，由应用层和展示层消费并自动定位图像。可借鉴此职责分工，无需引入 Yield 依赖。
- 页面与 PDF 的趋势数值均经既有应用入口计算；指定厂别启用专用规则时，日/周值可能受既有月基准规则影响。新预警必须消费同样的当前报表数值。
- 当前日轴为最近 7 个有 RS 明细的日期，可能跨越 7 个自然日。检测器必须另行约束自然日范围。

### 参考程序的实际行为与差异

提供的参考程序在主报警流程中计算目标日与前一天、此前 5 天均值的比较。实际实现有以下细节：

1. 目标日是参考时间的前一天，但有效点窗口包含参考时间当天，两个窗口存在偏移。
2. 缺日期和零分母返回 0；正密度才算有效天，真实零值也被排除。
3. 基线仅平均正密度，不保证前一天有有效数据。
4. 名称虽为“连续两日上升”，实际只验证目标日高于前一天及基线，没有验证前一天高于更早一天。

本方案保留相对上升判定，统一自然日窗口、缺测语义与规则名称，不复制上述偏差。

## Solution

在 AOI_RS 页面增加“趋势预警中心”，按当前产品下的厂别、站点、RS Code 独立检测日密度上升；展示判断日期、比较值、过货量和预警原因，并自动展开命中指标的现有三张图。

经用户确认采用以下规则：

| 项目 | 建议定义 |
|---|---|
| 判定日期 T | 当前报表结束日的前一天，即昨天；不是自动寻找最新有数据日期 |
| 窗口 | `[T−6, T]` 共 7 个自然日，不向窗口外追补缺失日期 |
| 密度 | 直接消费当前趋势图使用的日 `value`，单位 RS/片，不显示为百分比 |
| 有效日 | 对该指标存在日行，密度有限且非负、过货量大于 0；真实零密度有效 |
| 最少数据 | 当日超规要求 T 和 T−1 均有效、7 日内至少 3 个有效日；连续两日上升要求 T、T−1、T−2 均有效 |
| 历史基线 M | T−6 至 T−2 的有效日密度算术平均，至少 1 天，且 M 大于 0 |
| 当日超规 A | `density(T) > 1.2 × density(T−1)` 且 `density(T) > 1.2 × M`，并满足该规则的数据门槛 |
| 连续两日上升 B | `density(T) > 1.2 × density(T−1)` 且 `density(T−1) > 1.2 × density(T−2)`；独立评估，不受历史基线为零或缺失影响 |
| 总预警 | A 或 B 任意规则命中即报警，同时命中时记录两个原因，每个指标只出一条记录 |
| 等号边界 | 恰好 1.2 倍不触发 |
| 规格关系 | 不要求超过 MWD_RATIO 规格；无规格也可以评估，既有单片异常规则独立运行 |
| 缺测处理 | 缺日期、零分母、无效密度不补零，不回退到更早日期冒充 T 或 T−1 |

“当日超规”是用户指定的原双比较规则名称，不是新增 `density > spec` 条件；既有单片规格异常继续独立展示。示例：基线 0.10、T−1 为 0.12、T 为 0.16，即使规格为 0.50 仍触发 A。T−2、T−1、T 分别为 0.10、0.13、0.17 时触发 B。T−1 缺测时两条规则均不可评估。有效零值参与比较，不计算无穷大增幅。

日序列必须覆盖截至昨天的 7 个自然日；即使今天也有数据，也不能因现有图轴只保留 7 个日期而漏掉 T−6。为此，仅预警计算的日轴截至 T；月基准仍截至报表结束日，使相同日期的密度与当前报表图表一致。主报表/PDF 原有日期轴保持原样。

该规则没有额外的单日过货量下限；展示过货量以便业务判断小样本影响。后续如需增加此门槛，应作为单独的业务策略调整。

## User Stories

1. 作为报表用户，我希望在 RS 密度未超过规格时看到明显上升，以便提前检查。
2. 作为报表用户，我希望看到判断日期、当前密度、前一天密度、历史均值与过货量，以便理解原因。
3. 作为报表用户，我希望自动看到命中 Code 的现有三张图，以便定位问题。
4. 作为报表用户，我希望无需提交手动查询就能看到当前产品的趋势预警。
5. 作为报表用户，我希望不同厂别、站点及 Code 分开比较，以免混合口径。
6. 作为报表用户，我希望缺数据时明确提示数据不足，以免把缺测解释为正常。
7. 作为报表用户，我希望无预警时知道实际可评估的指标数量。
8. 作为报表用户，我希望趋势预警与当前趋势图数值相同。
9. 作为报表用户，我希望已有单片异常、手动筛选、刷新及 PDF 导出继续正常工作。
10. 作为维护者，我希望规则与边界有自动化证据，并在领域文档中可检索。

## Implementation Decisions

- Core 负责纯日序列判定，接收当前趋势 DataFrame 与明确参考日期，产出结构化命中记录及评估状态。核心判定不访问 Streamlit、数据库或工作簿。
- Application 在现有报表用例中协调共享趋势产物和判定结果；通过现有原生 payload / ViewModel 边界向页面交付。新增数据使用 DataFrame 或原生容器，遵守 ADR-0001。
- 共用既有图表趋势入口，避免在页面重算另一套密度；必要时为当前报表视图增加趋势与预警字段，以复用同一计算产物。
- 阈值集中命名，默认上升倍数 1.2、窗口 7 天，不引入新的资源文件或新数据源。
- 产品、修饰决策、日期排除、日期窗口等现有缓存身份继续生效；修改规则时必须使对应派生结果失效。
- 展示层只消费判定结果，构造业务字段白名单。站点显示复用现有描述映射；不向表格或图像传入内部决策字段、源值对比或异常详情。
- 趋势预警与单片异常分别展示。自动图像复用现有指标分组与精确键筛选，使用独立图表 key 前缀，防止与既有预警及主报表冲突。
- 有可评估指标且零命中时显示无趋势预警；存在不可评估指标时同时显示数据不足数量；全部不可评估时不显示笼统正常结论。
- 读取/计算失败沿用明确失败提示和服务端日志，不能伪装成零命中。

## Testing Decisions

优先利用现有 AoiRsDataPort → ReportService → 页面测试入口，不新增测试专用生产接口。

- 纯规则：未超规格仍命中、20% 严格边界、单一条件成立不命中、真实零值、缺 T/缺 T−1、基线不足或为零、NaN/inf/负值、零分母。
- 时间与隔离：乱序输入、自然日窗口边界、过旧数据、跨月/跨年，以及厂别/站点/Code 不串组。
- 应用集成：以隔离端口和临时资源验证预警值与当前趋势值一致；专用策略开/关、日期排除、产品 revision/决策签名变化后不复用旧结果。
- 页面行为：有警、无警、部分及全部数据不足、服务失败；未点击查询仍显示预警；自动图像只包含命中键。
- 展示边界：普通模式表格实际输入、图表 hover、列菜单均不含内部字段；当前密度按 RS/片展示。
- 回归：AOI_RS Core、应用服务、Dashboard、单片异常、页面与导出相关测试；按变更范围运行缓存/架构守卫。
- UI 验证使用不连接数据库的最小夹具。若需要临时服务，记录本次进程树及端口，以生命周期清理覆盖成功、失败和中断，并核验监听释放；保留既有正式服务。

## Out of Scope

- 设备/腔室回追、责任归属、消息推送、定时监控及参考程序的文件分析或 PPT 流程。
- 向全指标预警矩阵、周报警率或历史工作簿写入趋势预警。
- 改动既有单片异常规则、源数据库、原始快照或已维护的工作簿内容。
- 将 Yield 的百分比阈值直接用于 RS 密度，或让 AOI_RS 依赖 Yield 检测器。
