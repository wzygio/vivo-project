## Solution
我们将“Codebaseline、EMA、截断、缩放、人工覆盖”这一条原始的修饰链路全部删除，全部改为由用户指定（`resources\趋势图人工修正.xlsx`这一文件暂时保留，暂时需要它来作为参考）。

指定数据来自“入库良率修饰表”，具体逻辑如下：
1. 读取原始良损：读取数据库，并依次“By产品型号”计算各“Defect Group/Defect Code”的原始良损：
    - 更新机制：每次运行只更新当月数据即可。即只更新“当月良损”
2. 日度良损生成：根据用户指定的月度良损（即“指定良损”），来生成各“日度良损”
    - 回退机制：如果一个“Defect Group/Defect Code”在一个月份没有设定“指定良损”，则优先使用其对应的上个月的“指定良损”。如果没有任何一个月有“指定良损”，则直接使用“当月良损”
3. 缩放倍数计算：根据“指定良损”计算缩放倍数（保留三位小数，见“## Data Source”），公式如下 $缩放倍数 = 指定良损 / 当月良损$
    - 更新机制：当检测到配置文件有改动时，重新计算缩放倍数
4. Mapping不良数同步缩放：根据缩放倍数，对计算Mapping的不良数进行缩放，确保月周天趋势图的不良数与Mapping一致：
    - Mapping图不良数影响因子：defect_modifier，“缩放倍数”，级联衰减

## Requirements
- 随机生成算法（根据人工指定的月度良损生成日度数据）：
    * 确保每次生成所有日度良损数据不变：比如，可以使用伪随机散列而不是伪随机数
    * 生成的日度良损数据要避免周期性震荡，否则看起来过于虚假
    * 日度良损跨月份过度要平滑，避免出现阶梯状数据
- Mapping数据同步：
    * 后续计算Mapping时，要乘以该倍数（主要是不良数，即分子），从而确保月周天的不良数水准与Mapping的不良数一致（取代原来的缩放逻辑）。 
    * Mapping图并不以月周天来划分，而是以批次来划分。因此匹配逻辑为：批次所属月份的缩放倍数。
    * 注意该缩放倍数与`src\yield_domain\core\defect_modifier.py`中的逻辑并不一致，前者是月度缩放，后者是全局缩放。也就是Mapping图的在计算不良数时，实际上是乘以了这两个倍数
