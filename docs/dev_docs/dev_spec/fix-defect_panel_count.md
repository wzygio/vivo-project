# Task：不良panel数对齐

## Problem
现在有一个问题：
“通过月周天不良率计算出的不良panel数”和“通过Mapping图的计算出的不良panel数”并不匹配，原因如下：
1. 二者虽然都接收panel_details_df作为数据集，但是mapping的panel个数与panel_details_df完全匹配，算法只是修改了panel坐标来改变mapping分布。
2. 然而panel_details_df对于月周天不良率的计算来说只是作为参考，实际算法是通过EMA算法产出，最终导致整体良率水平发生极大变化，进而导致不良panel数与原始数据集差异极大
    - $ 不良panel数 = 良率水平 × 产出数 $
3. 这一点在良率较低的Defect Code上极为明显。比如，一个Defect Code只有一天有良损（即不良率），但是EMA算法的拖尾效应会让后续几天也持续产出良损，最终聚合后提升了月度良损的水准。

## Task1：思考解决方案

### Requirements
解决方案应该同时满足以下两个要求：
1. 日度良损波动极小
2. “通过月周天不良率计算出的不良panel数”和“通过Mapping图的计算出的不良panel数”保持一致
3. 如果都能满足，则优先采用算法稳定、计算量小的算法

### Hint
我不在在乎不良数是否真实。较为简单的解决办法有以下两种：
1. 改变月周天不良率：在通过EMA算法计算出日度良损，进而聚合后计算出月度良损后，与原始的月度良损比较计算出一个倍数，然后让所有的月周天良率乘以该倍数。这一步应该放在月周天不良率计算的最后一步。
    - 这个所谓的原始月度良损，应该是在乘以defect_multipliers后，defect_multipliers直接作用于初始数据集（panel_details_df）这一点不能改变
2. 改变Mapping不良率：以“通过月周天不良率计算出的不良panel数”为准，去绘制Mapping图。但问题在于，Mapping图还是需要依赖原始panel_details_df中提取出来的panel坐标，这一点无法杜撰。除非我们舍弃原始的算法，默认改为随机分布，这也可以接受
    - 此外，Mapping图并不是By月份，而是By批次。我们可以让批次良损的基准设为月均良损
    - 当前Mapping图的绘制逻辑中还包括级联衰减来避免某个批次忽然升高，但如果批次良损绑定了月均良损，就无需担心这一问题。
