## Step2
将“规格表”中的数据转化为目标格式。想要将“规格表”中的字段转化为目标格式，您需要重点解析以下两个字段：
1. 站点：每条记录应该只对应一个站点，您需要通过换行符将其截断，
    - Example
    ```
    1K500
    12500
    13500
    B9500
    ```
2. 机台号-腔室：
    - 拆分步骤：
        * 首先，通过换行符拆分组别
        * 然后，通过“ ”（空格）或“-”拆分机台号和腔室
        * 再然后，通过“/”拆分多个“机台号”或“腔室号”
    - Example
    ```
    3AFS03/04/05/11 PM4/PM5
    ```

    上述字符其实对应着8个组合分别是：
    ```
    3AFS03-PM4
    3AFS03-PM5
    3AFS04-PM4
    3AFS04-PM5
    3AFS05-PM4
    3AFS05-PM5
    3AFS11-PM4
    3AFS11-PM5
    ```

# Task2-1：数据仿造优化
1. 我注意到当前的数据仿造需要显示触发，这是不合理的，应当改为自动触发（更新）。其更新机制可以参考真实数据的更新机制，使用快照的有效时间来空值是否更新
2. 数据仿造的关键数据有二，测量值和测量时间。关键在于设计一套内部自洽的动态更新机制。当前我设计的机制如下，请你先分析并理解：
    - 每次有效更新将每条测量时间推进 1 天，将测量值按配置增量推进；当前增量为寿命规格的 30%
    - 推进后的值超过寿命规格时，按配置重置到寿命规格的 0%～30%
3. 请你思考是否有更稳定、简洁的更新机制，只要能够满足内部自洽、动态更新：注意这里是不能够使用随机数据来模拟的，因为测量数据必定是一个近似的等差数列（不能完全等差，否则看起来太假），达到规格后从零开始。
    - 比如，假设更换时间为三天：一个备件前一天使用进度是30%，那么第二天不能忽然变为97%，而应该是类似60%。
    - 再比如，前一天使用进度是97%，那么第二天应该是类似30%（因为备件达到寿命规格后会更换），而不能是随机成58%。
