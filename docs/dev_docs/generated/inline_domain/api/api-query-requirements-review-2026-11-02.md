## 查询契约

所有查询参数均可省略，认证请求头仍然必须提供。不带参数时，查询当前启用且调用方获授权的全部产品、全部分类及全部授权厂别，异常事件默认为 OOS，日期默认上一完整 ISO 周。不再默认截断为100行。

| 参数 | 省略时 | 提供时 |
|---|---|---|
| `product` | 启用产品与授权产品的交集 | 单个产品；禁用或未授权返回403 |
| `sub_domain` | 全部获授权分类 | SPC、CTQ、AOI_TT、AOI_RS、Yield、Q-Time之一 |
| `factory` | 全部授权厂别 | 单个获授权厂别 |
| `step_id` | 全部发生站点 | 发生站点精确匹配，保留前导零 |
| `layer` | 全部层别 | 层别精确匹配 |
| `parameter_name` | 全部监控参数 | 监控参数精确匹配 |
| `event_type` | OOS | OOS或OOC |
| `start_date` | 上一ISO周周一 | YYYY-MM-DD，含当天 |
| `end_date` | 上一ISO周周日 | YYYY-MM-DD，含当天 |
| `entity_type` | 全部对象类型 | sheet或lot |
| `entity_id` | 全部对象编号 | 对象编号精确匹配 |
| `limit` | 不按条数截断 | 1～500，启用分页 |
| `cursor` | 第一页或完整结果 | 与同一筛选条件及显式limit一起使用 |

全部筛选条件按“且”组合，不增加模糊搜索或多值语法。空字符串不是“全选”，省略参数才表示全选。日期建议按上海时区解释；例如2026-11-02的默认窗口为2026-10-26至2026-11-01，内部比较采用半开区间 `[2026-10-26 00:00, 2026-11-02 00:00)`。只传一个边界时，另一个独立使用默认日期；开始晚于截止返回422。

OOC仅适用于四类Inline：未指定分类时遍历获授权且支持OOC的分类；显式请求Yield／Q-Time的OOC仍返回422。Yield的发生站点、层别保持null，带站点或层别筛选时不匹配Yield。

“默认不限制”指返回行数，不取消既有响应字节、读取超时、并发、访问频率及缓存容量限制。超过当前16MiB容量时明确返回503，不静默截断；显式分页也需要完整公开快照，不能绕过此容量限制。

## 返回与分页

删除“起始站点”。Q-Time的“发生站点”已经使用起点f_step，层别继续由起点站点描述产生。其余现有业务字段和meta结构保留，meta中的period_start／period_end_exclusive反映实际解析的日期窗口。

cursor可以理解为服务发给调用方的“下一页取数凭条”。先使用limit请求第一页，再把返回的next_cursor连同原筛选参数和limit发回，直到has_more为false。调用方不用解析或自行拼接cursor。默认完整取数时不需要它。授权、启用产品集合、日期范围或公开结果改变，以及服务重启、快照过期，都可能令旧凭条失效；届时从第一页重取。

所有来源合并后统一按公开发生时间及公开身份字段排序、分页，避免每个来源分别分页造成遗漏。快照必须绑定解析后的产品／来源／厂别集合与日期，不能只绑定省略参数的原始请求。

## 用户已确认的两处业务口径

1. 日期精度：接受YYYY-MM-DD，按上海时区包含首尾两天；只传一端时另一端独立使用默认日期。
2. 跨来源失败：用户选择返回可用部分。HTTP200的meta.complete=false及failed_sources明确标记失败的product／sub_domain／event_type与固定code=result_unavailable。成功空来源也算可用；全部选中来源失败503，error.failed_sources列出来源。请求级超时、容量、配置等错误不承诺逐来源列表。失败来源整批丢弃，不泄露已投影前缀或内部异常。

## 工作拆分、依赖与验证

执行顺序为 **01 → 02 → 03**，保留现有HTTP和真实临时工作簿测试边界。

1. **01 零参数授权查询与完整返回**。无前置依赖；实现授权范围聚合、可选参数、默认不限行、删除起始站点。验证无参数、部分参数、超过100行、跨产品／分类、越权和禁用产品。
2. **02 日期与业务字段筛选**。依赖01；将实际日期范围传递至各域既有发布结果读取流程，扩展Inline共同日期选择能力；实现站点、层别、监控参数筛选。验证首尾边界、单边默认、无效日期、旧页面默认周口径，以及Q-Time／Yield覆盖不足时的既有有效性判断。
3. **03 合并结果分页与交付**。依赖02；验证全局排序、游标的授权和实际范围绑定、结果变化失效、资源上限及选定的跨来源失败策略；完善使用说明、未来字段建议、评审和验证记录。按已有授权交付到目标分支及现有8890服务，操作前核验进程归属，不操作报表服务。

测试只使用合成数据及临时本地文件；不连接生产数据库，不启动生产计算，不修改正式工作簿。完整回归与已记录的24项基线失败逐项比较，不把既有失败标记为通过。保留原工作区所有无关改动。

## 后续可以扩展的返回信息（本次不添加）

| 方向 | 用途和前提 |
|---|---|
| 实测值、最小值／最大值 | 判断异常程度；需统一各来源量测含义，部分Lot事件没有单一数值 |
| 规格／控制上下限、单位、超出幅度 | 区分超限方向和程度；需明确OOS与OOC边界及缺失单位的表达 |
| Yield缺陷分组 | 方便按Array_Line等分组分析；现有发布已保存defect_group，可另行定义对外名称 |
| 结果发布时间及覆盖范围 | 帮助判断数据新鲜度；需统一各域发布元数据，不能伪造事件时间 |
| 稳定的异常事件ID | 支持调用方去重、增量同步；需统一跨来源的稳定键与重新发布规则 |
| 关联追踪信息 | 如Lot、Sheet之间的关联或Q-Time终点；需确认本地已发布字段及业务含义 |

后续扩展仍须遵守公开信息边界，不返回内部人工决定、路径、原始数据或诊断信息。
