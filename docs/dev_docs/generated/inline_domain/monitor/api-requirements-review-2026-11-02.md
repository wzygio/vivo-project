来源：[feat-API](../../../dev_spec/inline_domain/monitor/feat-API.md)。技术方案及源码证据：[修订开发方案](sheet-anomaly-api-development-plan.md)。用户已确认共同读取／HTTP测试边界与任务图；正式获批规格及状态由 [PRD](../../../../../.scratch/sheet-anomaly-api/PRD.md)、[四张任务卡](../../../../../.scratch/sheet-anomaly-api/issues/01-spc-http.md) 与 [执行计划](../../../../../.planning/2026-11-02-sheet-anomaly-api/task_plan.md) 追踪。

## Problem Statement

其他系统需要取得与自动预警看板同源、受人工释放及公开政策控制的异常明细。开发前只能通过Streamlit交互查看，没有独立HTTP接口。既有来源的粒度、字段、发布有效性和人工控制并不完全一致。

## Solution

增加只读鉴权API，共同消费本地发布结果，提供统一业务字段、真实Sheet／Lot身份、上一完整周窗口和稳定分页。共用既有应用读取端口与筛选规则；补齐发布中的Flag证据及Yield人工控制。层别由独立发布的本地工序字典投影得到，API请求不触发生产分析、SQL或维护文件写入。

## User Stories

1. 作为调用系统，我需要通过独立凭证查询授权产品和分类，避免获得其他范围的数据。
2. 作为调用系统，我需要取得SPC、CTQ、AOI_TT、AOI_RS、Yield和Q-Time的本地异常记录。
3. 作为调用系统，我需要区分片和Lot，避免把Lot报警误认为所有片报警。
4. 作为使用者，我需要分类、发生站点、部门、层别、监控参数和异常事件具有统一且可解释的含义。
5. 作为使用者，我需要OOS/OOC与USL/LSL等命中边界分开表达。
6. 作为数据负责人，我需要只有明确False的记录被释放，缺失或非法标记不会自动放行。
7. 作为Q-Time维护者，我需要继续使用原有人工决策台账，不维护另一套API决定。
8. 作为Yield维护者，我需要保存可编辑且跨发布保留的释放决策，发布重算不会擦掉人工历史。
9. 作为调用系统，我需要明确的上一完整ISO周和时间精度，避免把响应时间当数据发生或更新时间。
10. 作为调用系统，我需要稳定分页和明确的过期重查方式，避免翻页期间重复或漏记录。
11. 作为调用系统，我需要区分有效零异常与结果缺失／损坏／过期。
12. 作为数据负责人，我需要公开政策同时约束明细、计数、错误、元数据和游标，不泄露隐藏记录。
13. 作为运维人员，我需要接口只读本地结果，查询失败不会重算报表或影响生产数据库。
14. 作为运维人员，我需要有限缓存、解析并发、限流、安全日志和不访问数据库的健康检查。
15. 作为调用方开发者，我需要OpenAPI、启动配置、调用示例和错误恢复说明。
16. 作为维护者，我需要现有报表／矩阵调用及维护文件生命周期得到保留。

## Implementation Decisions

- 已确认：包含RS的Sheet/Lot、Yield及Q-Time Lot；不展开Lot推断片级异常。
- 已确认：四类Inline同时支持OOS/OOC，查询默认OOS；Yield与Q-Time没有OOC发布。
- 已确认：必要字段完整，资料不足时来源暂不可用；用户随后修订Yield厂别必需、发生站点允许NULL。没有站点时仍需维护描述以取得必填层别。
- 已确认：Q-Time发生站点和层别均采用起点f_step。
- 已确认：共同服务／文件端口与HTTP测试边界，SPC→其余Inline→Q-Time/Yield→集成使用说明的执行顺序。
- 独立FastAPI入口与跨域组合，共用Inline选择及纯公开政策，保留页面兼容包装。
- 本地字典通过独立有界同步生成；API请求不查询数据库、不运行生产、不补齐或写入维护结果。
- Q-Time保留原台账并发布明确False证据；Yield持久决定默认True，False释放并跨发布保留人工历史。
- 业务字段采用需求指定中文名称及明确对象身份；只投影公开白名单，不透传内部records字典。
- 一产品一分类、上一完整周、有限页大小／并发／缓存、绑定身份及公开结果的认证游标、安全错误与请求编号。
- 当前分支处于实现／回归阶段；运行状态、最终测试及提交证据另行核验，不等同于已经部署。

## Testing Decisions

- 最高外部边界为进程内HTTP客户端：验证真实JSON字段、鉴权、过滤、分页、状态码及禁止泄露。
- 业务读取使用现有文件端口，注入临时工作簿；发布链路用临时维护文件验证人工决策跨发布保留。
- 以原有共享读取、Q-Time／Yield发布、Inline校验测试为先例；新增测试观察外部行为，不复制实现计算。
- 禁止SQL和生产重算的替身断言覆盖缺文件、缓存miss、损坏、字典缺失和错误分支；校验输入文件字节未改。
- 覆盖True／False／Delete／非法缺失、周及时区边界、RS片／Lot、OOS/OOC、层别、字段缺失、权限与政策变化、游标篡改／淘汰／重启。
- 保留相关页面回归和后端依赖守卫；服务生命周期测试仅使用不连接数据库的最小页。

## Out of Scope

趋势／能力告警、IJP比例汇总、备件、IQC、图像、原始量测、任意历史、写入HTTP接口、自动迁移用户维护资料、部署到公网、擅自改动现有正式服务、未经确认的合并。维护工具供操作人员明确选择范围后运行，本次开发不自动执行生产迁移。

## Further Notes

用户已回答方向性问题并批准进入开发，计划模式complex。Yield缺站点不再是阻塞分支，但厂别与层别必须有真实维护资料；用户未来维护业务资料不等于允许API编造占位值。当前实现不自动迁移生产文件。

## 已批准的 Ticket 图

依赖图：01 → 02 → 03 → 04。每项都是可单独验收的纵向行为，03依赖01的公开HTTP契约及02的完整对象模型。

### 01：SPC 本地异常到公开 HTTP 查询

Blocked by：None。

交付：凭证授权的调用方可以从临时SPC发布文件取得公开明细、层别和分页；现有页面仍可使用共同服务。

- [ ] 只释放False及上一完整周，保留SPC参数排除与日期政策。
- [ ] 业务字段及对象身份正确，公开政策覆盖整个响应；本地字典缺失按获批约定处理。
- [ ] 鉴权授权、限流、可用性、安全错误、分页与健康检查通过HTTP契约测试。
- [ ] 请求无SQL、无生产计算、无维护写入；页面兼容和依赖守卫通过。

### 02：其余 Inline Sheet／Lot 与事件完整覆盖

Blocked by：01。

交付：CTQ、TT、RS的片／Lot均可按同一契约查询，同时支持四类Inline的OOC。

- [ ] RS保持chart_kind粒度；同片多事实不合并成伪造片数。
- [ ] TT分类、各来源时间及参数字段正确；OOS/OOC与命中边界分开。
- [ ] 所有来源仅False，保留原产品范围、日期及公开政策。
- [ ] 缺失、空表、损坏、非法字段、跨周边界有外部行为测试。

### 03：Q-Time／Yield 人工释放到本地 Lot API

Blocked by：01、02。

交付：现有Q-Time台账和新增Yield持久决策共同约束发布、看板及API，真实Lot明细可以读取。

- [ ] Q-Time明确保留False证据；原决策签名失效及新发布恢复行为保持。
- [ ] Yield新决策默认不释放，False可释放；同一锁内发布、历史／其他产品保留及指纹失效有测试。
- [ ] 不为旧缺Flag文件自动补False，提供显式初始化／正常发布的迁移路径。
- [ ] Q-Time站点及层别采用起点；Yield厂别必需、站点可NULL，缺层别描述时不可用，不编造位置。
- [ ] 既有有效性／覆盖校验、禁止SQL及文件只读断言通过。

### 04：集成、安全评审与可运行交付

Blocked by：01、02、03。

交付：运行入口、依赖、环境模板、字典同步、人工维护和调用说明完整，测试与评审证据可追踪。

- [ ] 覆盖全部来源的集成契约、政策／权限变化和分页重查验证通过。
- [ ] 临时工作簿／服务隔离及清理验证通过，不停止既有正式服务。
- [ ] 完成Standards／Spec评审和适用安全审查，修复阻断发现。
- [ ] 依赖／配置／知识路由／架构记录与实现一致，正式使用说明位于指定领域目录。
- [ ] 相关测试、依赖守卫及适用全套回归有命令与结果证据；提交范围不含无关用户改动。
- [ ] 报告开发分支、提交及验证结果；合并在另行确认后进行。
