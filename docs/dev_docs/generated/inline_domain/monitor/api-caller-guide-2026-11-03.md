# 异常片／Lot API 调用入门（给第一次使用 API 的同事）

日期：2026-11-03。适用接口：`/api/v1/sheet-anomalies`，当前实现版本 1.1.0。

这份文档可以直接转给调用方。实际动手请使用配套的 [跨设备测试步骤与案例](api-remote-test-2026-11-03.md)。完整技术约定以 [API 使用说明](../../../../../references/domain/inline_domain/monitor/guide-sheet-anomaly-api.md) 为准。

## 1. API 是什么，与打开报表有什么区别

打开报表时，人通过网页查看表格；调用 API 时，程序向指定地址发送查询，服务返回可供程序处理的数据。调用方可以把这些数据放入自己的系统、表格或后续流程中。

本接口负责读取已发布的异常片／Lot 明细。查询不会刷新报表、重新计算异常或补算历史。能查到哪些记录，取决于已发布结果、查询条件及调用权限。

一次调用包含四部分：

| 名称 | 通俗解释 | 本接口中的例子 |
|---|---|---|
| 地址（URL） | 请求发到哪里 | `http://10.72.26.31:8890/api/v1/sheet-anomalies` |
| 方法（Method） | 要做什么 | `GET`，表示读取数据 |
| 请求头（Headers） | 随请求提交的凭证等信息 | `X-API-Key`，值为分配给调用方的密钥 |
| 查询参数（Params） | 要查哪些内容 | `product=M626`，表示只查 M626 |

当前地址是本机内网部署地址。调用设备需要能访问该内网，服务电脑需要保持开机、唤醒、用户登录且 API 正常运行。如果主机 IP 改变，需向维护者确认新地址。

## 2. 开始前，向维护者取得什么

取得调用地址、为本调用方分配的 **API Key 原始密钥**，以及允许查询的产品／厂别／分类范围。密钥通过企业批准的凭据渠道单独交付；本文不包含密钥。

API Key 类似门禁凭证，放在请求头 `X-API-Key` 中。不要把密钥放进网址、共享文档、截图或程序日志，也不要把服务端保存的 SHA-256 摘要当成密钥。

当前部署记录中的授权范围为：

| 维度 | 范围 |
|---|---|
| 产品 | M626、M678、Z571、M673、Z517、Z576、Z553 |
| 厂别 | ARRAY、OLED、TP |
| 分类 | SPC、CTQ、AOI_TT、AOI_RS、Yield、Q-Time |

以上是已记录的部署范围，新调用方的实际权限以维护者分配为准。授权覆盖某来源，并不保证该来源当前数据可用。

当前入口使用 HTTP，网络传输没有加密；按已批准的内网访问方式使用。日后若提供 HTTPS 地址，改用维护者提供的新入口。

## 3. 第一条查询怎么写

查询 M626 的 SPC 超规明细，每页最多 10 行：

```text
GET http://10.72.26.31:8890/api/v1/sheet-anomalies?product=M626&sub_domain=SPC&event_type=OOS&limit=10
```

同时提交请求头，下面的文字是占位说明：

```text
X-API-Key: <维护者单独交付的原始密钥>
```

网址中的 `?` 表示查询条件开始，`&` 连接多个条件；以上条件同时生效。直接把业务网址粘贴到浏览器地址栏，通常无法提交这个请求头，会得到 401。配套测试文档提供了 Windows PowerShell 操作方法，无需安装开发环境。

**不填日期时，默认查询服务器上海时区的上一完整周。** 例如在 2026-11-03 调用，默认日期为 2026-10-26 至 2026-11-01，包含两端。若要查指定日期，建议同时填写开始和截止日期：

```text
GET http://10.72.26.31:8890/api/v1/sheet-anomalies?product=M626&sub_domain=SPC&start_date=2026-10-26&end_date=2026-11-01&limit=10
```

这些日期仅是操作示例，不承诺该日期有可用异常。验证具体记录时，请维护者提供一条当前可查询的记录及其日期范围。

## 4. 常用条件

| 参数 | 用途与示例 |
|---|---|
| `product` | 产品，例如 `M626`；省略表示全部已启用且获授权产品 |
| `sub_domain` | 分类，严格使用 `SPC`、`CTQ`、`AOI_TT`、`AOI_RS`、`Yield`、`Q-Time`；省略表示全部授权分类 |
| `event_type` | `OOS` 为超规格，`OOC` 为超控制限；默认 OOS，二者分开查询 |
| `factory` | 厂别，例如 `ARRAY`；省略表示全部授权厂别 |
| `start_date`／`end_date` | `YYYY-MM-DD`，按上海时区包含首尾两天 |
| `step_id` | 发生站点，精确匹配；保留前导零，例如 `00100` |
| `layer` | 层别，精确匹配，例如 `PI2` |
| `parameter_name` | 监控参数，精确匹配；含中文、空格等字符时需进行 URL 编码 |
| `entity_type`／`entity_id` | 对象类型 `sheet`／`lot`，以及对象编号，精确匹配 |
| `limit` | 每页最多返回行数，范围 1～500；建议初次使用填 10，正式取数可用 100 |
| `cursor` | 下一页凭条，首次查询不填，翻页时原样使用返回值 |

Yield、Q-Time 只支持 OOS。省略分类并查询 OOC 时，只查询支持 OOC 的已授权 Inline 分类。省略条件表示相应授权范围全选，填写空字符串不能代替省略。不支持的参数名会报 422。

不填 `limit` 时，接口尝试一次返回完整结果，仍受容量和读取超时限制；分页也不能绕过总结果容量限制。

## 5. 返回结果怎么看

返回格式为 **JSON**，可以理解为带字段名称的数据。`data` 是明细列表，`meta` 是对本次查询的说明。以下是虚构的一条完整响应，用来认识格式，不代表生产数据：

```json
{
  "data": [
    {
      "分类": "SPC",
      "发生站点": "00100",
      "部门": "ARRAY",
      "层别": "PI2",
      "监控参数": "示例参数",
      "异常事件": "OOS",
      "对象类型": "sheet",
      "对象编号": "DEMO_SHEET_001",
      "产品型号": "M626",
      "发生时间": "2026-10-28T10:00:00+08:00",
      "命中边界": "USL"
    }
  ],
  "meta": {
    "status": "alert",
    "returned_count": 1,
    "has_more": false,
    "next_cursor": null,
    "period_start": "2026-10-26T00:00:00+08:00",
    "period_end_exclusive": "2026-11-02T00:00:00+08:00",
    "timezone": "Asia/Shanghai",
    "read_at": "2026-11-03T09:00:00+08:00",
    "limitations": [],
    "complete": true,
    "failed_sources": []
  }
}
```

先看 HTTP 状态码，再看 `meta.complete`，最后看明细和是否还有下一页：

| 结果 | 正确理解 |
|---|---|
| HTTP 200，`complete=true`，有明细 | 所选来源都读取成功，已经收到本页数据 |
| HTTP 200，`complete=true`，`data=[]` | 当前查询范围没有可提供的异常记录；不能扩大解释为整条产线没有异常 |
| HTTP 200，`complete=false` | 只收到可用部分，`failed_sources` 列出不可用的产品／分类／事件；不能按完整结果统计 |
| `has_more=true` | 还有后续页，本页不代表全部结果 |
| `has_more=false` | 当前查询的分页已到末尾；仍需单独检查 `complete` |

`returned_count` 是本页明细行数。同一片在不同参数或站点上可以出现多行，因此它不是去重后的异常片数。`status=ok`／`alert` 也不能代替 `complete` 判断。

`read_at` 是本次取数时间，不是报表更新时间。`period_end_exclusive` 是查询结束的下一天零点，表示不包含这个时刻；上例仍包含 11 月 1 日全天。

返回中的“部门”表示厂别。Q-Time 的发生站点和层别取起点。Yield 为 Lot 级异常，发生站点和层别返回 `null`，表示未知；厂别仍需存在。Lot 级异常不表示其中每片均异常。`null` 是 JSON 空值，不是字符串 `"NULL"`。

## 6. “合并结果分页”是什么意思

如果一次查询多个产品、多个分类，服务会先合并它们的异常明细，统一按发生时间等字段倒序排列，再按 `limit` 分页。

例如合并后共有 23 行，`limit=10`：第一页最多 10 行，第二页最多 10 行，第三页剩余 3 行。**每页 10 行是全部所选来源合计 10 行。** 第一页可能同时包含 M626 的 SPC 和 M678 的 Yield。

翻页步骤如下：

1. 第一次请求带 `limit`，不带 `cursor`。
2. 如果 `has_more=true`，取出 `next_cursor`。
3. 保持原查询条件和 `limit`，把这个值作为下一次的 `cursor`。构造网址时对它做 URL 编码。
4. 重复到 `has_more=false`，合并每页 `data`，并检查完整性。

游标是临时凭条，不是页码，默认有效期 300 秒。不要编辑它或跨查询使用；收到 410 时丢弃尚未完成的整组分页数据，从第一页重新取。服务重启后旧游标也可能报 422，需确认条件后重新开始。

## 7. 失败时怎么反馈

| HTTP 状态 | 优先检查 |
|---|---|
| 401 | 密钥是否正确，是否放在 `X-API-Key` 请求头 |
| 403 | 产品、厂别、分类是否获授权且产品仍启用 |
| 410 | 从第一页重新查询 |
| 422 | 参数名、大小写、日期、OOC 适用范围、游标 |
| 429 | 按响应头 `Retry-After` 指示等待后重试 |
| 503 | 来源或服务暂不可用；查看 `error.code` 和存在时的 `error.failed_sources`，联系维护者 |
| 500 | 记录请求编号，交由维护者排查 |

反馈时提供：测试时间、调用设备、网址及筛选条件、HTTP 状态码、错误码、失败来源和响应头 `X-Request-ID`。隐藏密钥；不要发送带密钥的请求头截图。健康检查成功只说明服务能响应，业务查询及真实记录核对还需分别通过。

## 8. 交接给系统开发同事的一段话

> 请通过 GET 调用异常片／Lot API，并在 X-API-Key 请求头提交分配给本系统的密钥。日期按上海时区，包含开始及截止日；不填默认上一完整周。收到 200 后先检查 meta.complete，部分失败不能当成完整统计结果。需要分页时按 meta.next_cursor 连续取数，直至 has_more=false；游标失效时整组重新开始。数据行数不等于去重异常片数。接口读取已发布结果，不主动刷新来源。
