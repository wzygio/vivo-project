# MWD 指定良损算法逻辑

> 本文只描述当前实现的数据流、公式、保证和边界。方案是否适合合入及剩余风险见
> [MWD 指定良损方案评估与 Merge 建议](mwd-processor-opt-analysis-and-merge-assessment.md)。

## 一、算法目标与事实源

新流程用 Code Sheet 的月度“指定良损”生成 Code 日度趋势；Group 日度由 Code
最终日度向上汇总，Group Sheet 的“指定良损”只覆写 Group 月度结果：

```text
入库良率修饰表 Code Sheet → Code 月度目标整数 → Code 日度整数分配
                                      ├─→ Code 周度、月度聚合
                                      └─→ 按 Group 汇总为 Group 日度
                                                ├─→ Group 周度聚合
                                                └─→ Group 月度聚合
                                                      → Group Sheet 月度覆写

入库良率修饰表 Group Sheet ────────────────────────────────┘
```

最终 Code 日度整数是日度事实源。Group 日度不独立生成，而是严格等于同日
`Σ Code 日度整数`；Group 周度也由该日度结果聚合。Group Sheet 只负责覆写最终
Group 月度值，不允许把月度指定值反向分配到 Group 日度，因此 Group 月度可以与
Group 日度合计不同。

Code 日度不良数**不读取、不拟合、也不回落到 Panel 明细中的原始日度不良数**。
Panel 明细在 Code 日度路径中只提供：

- 每日总投入 `total_panels`，作为每个 Code 当日的分配容量；
- 实际出现过的 `(Defect Group, Code)` 唯一清单，用于建立日度输出网格。
- 按自然月、Code 汇总的原始月度良损，作为月度目标的最后回退。

原始月度良损只保留月度聚合结果，不保留原始日度分布。最终有效月度目标始终按
“当月指定 → 最近一个更早月份的指定 → 原始月度良损”解析，然后重新生成日度数。

Mapping 使用同一修饰表计算月度倍率，但在倍率应用后仍执行既有批次级联衰减。

## 二、应用数据流

### 2.1 修饰上下文

主要入口：

- `app/pages/入库不良率分析看板.py`
- `src/yield_domain/application/yield_service.py`
- `src/yield_domain/core/mwd_trend/modifier_table.py`

页面计算“入库良率修饰表”的文件签名，并将其作为 Streamlit 缓存参数传给 Group
趋势、Code 趋势和 Mapping。缓存未命中时，
`YieldAnalysisService._build_modifier_context` 执行：

1. 读取 `<产品>_Group级` 与 `<产品>_Code级` Sheet；
2. 使用经过全局 `defect_multipliers` 修饰后的 Panel 明细计算当月原始良损；
3. 更新当月原始良损和缩放倍数；
4. 从 Code Sheet 生成 Code MWD 使用的 `targets`；
5. 从 Group Sheet 生成只用于 Group 月度覆写的 `group_targets`；
6. 从 Code Sheet 生成 Mapping 使用的 `factors`。

```text
targets[Code][月份] = 该 Code 在该月最终采用的目标良损
group_targets[Group][月份] = 该 Group 在该月最终采用的月度覆写良损
factors[(Code, 月份)] = 目标良损 / 当月原始良损
```

Code Sheet 生成 Code 月度目标和 Mapping 倍率，并驱动 Code 日度趋势。Group Sheet
生成 Group 月度覆写值，不参与 Group 日度生成。

### 2.2 月度目标回退

`modifier_table.py::resolve_monthly_targets` 对每个不良项（Code 或 Group）、每个月按
以下顺序解析：

```text
当月指定良损
  → 最近一个更早月份的指定良损
  → 修饰表中的当月原始良损
  → Panel 明细按月汇总的原始月度良损
```

因此，业务人员可以只在需要改变水准的月份填写“指定良损”。未填写月份沿用最近一次
更早月份的指定；从未指定时使用该 Code 从 Panel 明细按月汇总得到的原始月度良损。
修饰表中的“当月良损”与该月度汇总使用相同口径，但即使历史月份没有工作簿行，程序
也会直接从本次 Panel 分析窗口补齐原始月度良损。Group 缺少月度覆写目标时，保留
Code 日度汇总得到的月度基础值。

## 三、Code 日度生成

主要程序：

- `mwd_trend/mwd_trend_processor.py::create_code_level_mwd_trend_data`
- `mwd_trend/daily_generator.py::generate_daily_counts`
- `mwd_trend/daily_generator.py::_generate_defect_daily`
- `mwd_trend/daily_generator.py::allocate_integer_counts`

处理单位是单个 `(Defect Group, Code)`：

1. 按日统计总投入数，并提取 `(Defect Group, Code)` 唯一清单；不计算原始日度不良数；
2. 按自然月、Code 统计原始月度不良数和原始月度良损；
3. 生成“日期 × Code”的容量日历，初始 `defect_panel_count` 统一为 0；
4. 按“当月指定 → 最近更早月份指定 → 原始月度良损”形成完整月度目标；
5. 将各月目标良损转换为月中锚点，生成逐日插值基线；
6. 叠加确定性哈希噪声，形成日度分配权重；
7. 逐自然月计算目标整数；
8. 在单日投入容量内，按权重分配月度目标，并写入最终日度不良数。

对月份 `m`，月度目标整数为：

```text
T_m = round(r_m × Σ P_d)
```

其中：

- `r_m`：该 Code 在月份 `m` 解析后的目标良损；
- `P_d`：日期 `d` 的投入 Panel 数；
- `T_m`：月份 `m` 需要分配的整数不良数。

这里的 `P_d` 是该产品当天的总投入数，并非从原始不良明细计算出的“By Code 投入”。
每个 Code 在同一天使用同一个 `P_d` 作为自身容量。日度权重为：

```text
w_d = 插值月度基线率_d × 确定性扰动_d × P_d
```

公式中没有原始日度不良数。

在目标良损满足 `[0, 1]` 且日投入为有效整数容量时，`T_m` 不超过当月总投入。

## 四、跨月“平滑”详细逻辑

### 4.1 “平滑”的准确含义

当前实现的“跨月平滑”是：**月中锚点之间的归一化前基线率做线性过渡**。

它不是以下承诺：

- 不保证 6 月 30 日与 7 月 1 日的最终不良数相近；
- 不保证最终日度良损在月界连续；
- 不保证日度整数序列单调变化；
- 不改变“每个月必须精确达到自己的月度整数目标”的优先级。

### 4.2 月中锚点

每个月的目标良损锚定在当月 15 日：

```text
A_m = (当月 15 日, r_m)
```

例如：

```text
A_6 = (2026-06-15, 0.001)
A_7 = (2026-07-15, 0.004)
```

选择月中而不是月初作为锚点，使目标变化在月界前后共同展开，避免在每月 1 日直接
把基线从上月目标切换为本月目标。

### 4.3 锚点间线性插值

对位于相邻锚点 `(t_i, r_i)` 与 `(t_{i+1}, r_{i+1})` 之间的日期 `d`：

```text
b_d = r_i + (r_{i+1} - r_i) × (d - t_i) / (t_{i+1} - t_i)
```

代码使用 `numpy.interp`：

- 第一个锚点之前，按第一个锚点的值平延；
- 最后一个锚点之后，按最后一个锚点的值平延；
- 只有一个目标月份时，整个日期范围使用同一个基线率；
- 相邻锚点之间逐日线性变化。

以上规则使 `b_d` 在月界没有“目标值阶梯”。例如 6 月 30 日和 7 月 1 日都位于
六月、七月锚点之间的同一条直线上。

### 4.5 确定性日度扰动

为避免完全直线或固定周期震荡，每天生成稳定哈希值：

```text
u_d = uint64(blake2b("产品|Code|日期")) / 2^64
n_d = 1 + volatility × (2u_d - 1)
```

默认 `volatility = 0.3`，因此 `n_d` 位于 `[0.7, 1.3)`。哈希输入包含产品、
Code 和日期，所以：

- 相同输入跨进程重复运行得到相同扰动；
- 不依赖 Python 内置 `hash()` 的进程随机种子；
- 不使用正弦函数，不引入固定周、月周期。

噪声只改变月内日度形状，不改变该月最终目标合计。

### 4.6 归一化前权重

日期 `d` 的原始分配权重为：

```text
w_d = b_d × n_d × P_d
```
- b_d：插值良损
- n_d：随机波动系数
- P_d：当日投入数
- w_d：当日不良数

其中 `P_d` 同时体现当天投入规模。投入为 0 的日期容量为 0，最终不会分配到不良数。

到这一步，跨月插值基线 `b_d` 是连续的；噪声会产生确定性日间波动，但不会形成
固定周期。

### 4.7 逐月独立归一化

系统不是把所有月份放在一起分配，而是对每个自然月分别将权重缩放到该月目标：

```text
α_m = T_m / Σ(d∈m) w_d
理想日度分配 q_d = α_m × w_d
```

`α_m` 是月份自己的归一化系数。只要相邻月份的目标、投入结构或权重合计不同，
就通常有：

```text
α_m ≠ α_(m+1)
```

因此，即使月界两侧的 `b_d` 位于同一条连续插值线上，乘上不同月份的 `α` 后，
最终分配水准仍可能在月界跳变。这是“基线平滑但最终日度不一定平滑”的根本原因。

### 4.8 容量约束与整数化

`allocate_integer_counts` 将理想分配转换为整数，并满足单日容量：

```text
0 <= C_d <= floor(P_d)
Σ(d∈m) C_d = min(T_m, Σ(d∈m) floor(P_d))
```

分配步骤为：

1. 按有效权重计算各日份额；
2. 若某日份额超过剩余容量，先把该日填满，再把剩余目标重新分给其他日期；
3. 对未饱和份额向下取整；
4. 按小数余数从大到小稳定补发剩余整数，直到达到月目标。

容量饱和、向下取整和余数补发都会进一步造成日间离散变化。因此最终输出是满足月度
合计与容量约束的整数序列，而不是连续曲线。

### 4.9 月界反例与约束优先级

固定每日投入、关闭噪声，并设置：

```text
2026-06 目标良损 = 0.1%
2026-07 目标良损 = 0.4%
```

可得到：

```text
6 月 30 日不良数 = 179
7 月 1 日不良数 = 284
相邻日上升约 58.7%
```

这不表示线性插值失效，而是七月为了达到更高的精确月度合计，使用了与六月不同的
归一化系数。

当前实现的约束优先级是：

1. 单日不良数不超过当日投入；
2. 月度整数合计精确达到目标；
3. 在前两项约束内保持插值基线和确定性波动形成的相对日度形状；
4. 不保证最终月界连续。

如果业务要求最终日度严格平滑，必须先定义可量化的边界指标，例如“相邻日最大变化
不超过 20%”，再决定允许牺牲多少月度目标误差。仅修改插值方式无法同时保证严格
月度合计和严格边界连续。

### Appendix-完整数字示例：6 月 1% 平滑过渡到 7 月 2%

为了只观察跨月处理，先使用一个刻意简化的例子：

```text
6 月指定良损 = 1%
7 月指定良损 = 2%
每天投入 Panel = 1000
volatility = 0（暂时关闭日度噪声）
日期范围 = 2026-06-01 至 2026-07-31
```

#### 第一步：建立月中锚点

系统不会在 7 月 1 日把基线从 1% 突然切换成 2%，而是建立两个锚点：

```text
2026-06-15：1%
2026-07-15：2%
```

两个锚点相隔 30 天，因此每天增加：

```text
(2% - 1%) / 30 = 0.033333 个百分点
```

插值基线如下：

| 日期 | 插值基线良损 | 说明 |
|---|---:|---|
| 6 月 15 日 | 1.0000% | 六月锚点 |
| 6 月 29 日 | 1.4667% | 沿直线逐日上升 |
| 6 月 30 日 | 1.5000% | 月末仍在同一条直线上 |
| 7 月 1 日 | 1.5333% | 没有直接跳到 2% |
| 7 月 2 日 | 1.5667% | 继续按相同步长上升 |
| 7 月 15 日 | 2.0000% | 七月锚点 |

最直观地看，这是一条跨过月界的斜坡：

```text
6 月 15 日                                              7 月 15 日
  1.0000% ───────────────╱─────────────── 2.0000%
                         ↑          ↑
                    6 月 30 日   7 月 1 日
                      1.5000%      1.5333%
```

所以，当前实现所谓的“跨月平滑”，首先指这里：**月界两侧继续沿同一条直线变化，
7 月 1 日不会直接从六月目标 1% 跳到七月目标 2%。**

#### 第二步：把基线换成日度分配权重

因为本例每天投入都是 1000，并且关闭了噪声，所以：

```text
w_d = 插值基线 × 1000
```

例如：

| 日期 | 插值基线 | 归一化前权重 `w_d` |
|---|---:|---:|
| 6 月 29 日 | 1.4667% | 14.667 |
| 6 月 30 日 | 1.5000% | 15.000 |
| 7 月 1 日 | 1.5333% | 15.333 |
| 7 月 2 日 | 1.5667% | 15.667 |

这些权重在月界附近也是连续上升的，但它们还不是最终不良数。

#### 第三步：分别满足六月和七月的月度目标

六月有 30 天，七月有 31 天，因此两个自然月必须达到的目标整数分别为：

```text
六月目标 T_6 = round(1% × 30 × 1000) = 300
七月目标 T_7 = round(2% × 31 × 1000) = 620
```

插值权重在两个月内的合计为：

```text
Σw_6 = 340
Σw_7 = 585
```

为了让月度合计精确等于 300 和 620，系统会分别使用两个归一化系数：

```text
α_6 = 300 / 340 = 0.88235   （六月权重整体压缩）
α_7 = 620 / 585 = 1.05983   （七月权重整体放大）
```

归一化后的理想日度分配为：

| 日期 | 归一化前权重 | 月度系数 | 理想日度分配 `q_d` |
|---|---:|---:|---:|
| 6 月 29 日 | 14.667 | 0.88235 | 12.941 |
| 6 月 30 日 | 15.000 | 0.88235 | 13.235 |
| 7 月 1 日 | 15.333 | 1.05983 | 16.251 |
| 7 月 2 日 | 15.667 | 1.05983 | 16.603 |

注意：基线只从 1.5000% 平滑增加到 1.5333%，但进入七月后，归一化系数从
`0.88235` 切换成 `1.05983`。因此最终日度分配仍会出现一个月界跳变。

#### 第四步：整数分配

使用当前 `_generate_defect_daily` 实际运行上述输入，最大余数法处理后的输出为：

| 日期 | 最终整数不良数 |
|---|---:|
| 6 月 15 日 | 9 |
| 6 月 29 日 | 13 |
| 6 月 30 日 | 13 |
| 7 月 1 日 | 16 |
| 7 月 2 日 | 17 |
| 7 月 15 日 | 21 |

并且月度合计严格满足：

```text
六月最终不良数合计 = 300
七月最终不良数合计 = 620
```

可以把整个过程理解为：先画一条跨月的平滑斜坡，再分别拉伸或压缩每个月的整段
斜坡，使每个月的面积精确等于人工指定的月度目标。前一步保证基线没有月初阶梯，
后一步保证月度合计准确；由于每月缩放系数可能不同，最终整数在月界仍可能跳动。

## 五、Group、周度与月度生成

Group 不执行月中锚点、稳定哈希噪声或月内整数分配。它先把已经完成 Code Sheet
修饰的 Code 最终日度结果按 `(日期, defect_group)` 求和：

```text
Code 最终日度整数
  → 按日期、Group 汇总
  → Group 日度整数
  ├─→ Group 周度
  └─→ Group 月度基础值
          → 应用 Group Sheet 月度指定良损
          → Group 最终月度
```

对应程序：

- `mwd_trend_processor.py::_build_group_daily_from_code_data`：从 Code 日度汇总
  Group 日度；
- `aggregation.py::safe_trend_aggregator`：从 Group 日度生成周度和月度基础值；
- `mwd_trend_processor.py::_apply_group_monthly_overrides`：只覆写最终月度值。

Group Sheet 的指定良损转换为该月覆写整数：

```text
Group 月度覆写整数 = round(Group 指定良损 × 该月投入 Panel 数)
```

该整数直接写入 Group 月度表。程序不会再把它重新分配到当月各日，也不会据此重建
周度。因此三个周期的关系是：

- `Group 日度 = Σ 同 Group 的 Code 日度`；
- `Group 周度 = Σ 对应自然周的 Group 日度`；
- 未指定月份：`Group 月度 = Σ 对应自然月的 Group 日度`；
- 指定月份：`Group 月度 = Group Sheet 指定良损 × 月投入`（取整并受月投入约束）。

当 Group Sheet 与 Code Sheet 的人工目标不一致时，日度和周度仍服从 Code 汇总；
只有最终 Group 月度显示服从 Group Sheet。这里的“Group 覆写优先”只限月度结果，
不表示 Group 可以反向生成或改写日度数据。

## 六、Mapping 月度倍率

Mapping 按批次号解析月份，再按 `(Code, 批次月份)` 获取倍率：

```text
缩放倍数 = round(回退后的目标良损 / 当月原始良损, 3)
```

应用方式：

- 倍数小于 1：确定性抽样减少缺陷行；
- 倍数大于 1：整倍复制并抽样余数，复制行使用 `_SIM_M` 后缀形成唯一 Panel ID；
- 未命中月份或 Code：倍率为 1，保持原数据；
- 当月原始良损为 0：倍率回退为 1，无法从零放大。
- 非有限、负值或超过 10 倍：记录错误并按 1.0 回退，防止异常配置造成行爆炸。

完整顺序：

```text
Mapping 原始不良行
  → 全局 defect_multipliers
  → 月度缩放倍数
  → 批次级联衰减
  → Mapping 最终不良行
```

## 七、MWD 与 Mapping 的一致性边界

当前实现统一：

- 同一份“指定良损”来源；
- 同一 Code、月份的调节方向；
- Mapping 级联衰减之前的目标水准。

当前实现不保证：

- MWD 完整自然月与 Mapping 最新五批次覆盖相同数据范围；
- MWD 月度整数与 Mapping 最终不良整数严格相等；
- Mapping 级联后的最终不良率等于指定良损；
- Mapping 上调倍率一定提高最终不良数。

差异来源包括：

1. MWD 使用完整自然月，Mapping 只选择最新五个有效批次；
2. Mapping 缩放后仍执行跨批次递减天花板；
3. MWD 使用 `round(rate × month_panels)`，Mapping 使用行复制、抽样和整数截断；
4. Mapping 倍数只保留三位小数；
5. 原始良损为 0 时 Mapping 无法放大；
6. 批次日期无法解析时不会应用月度倍率。

如果业务要求最终计数严格一致，必须重新定义两边共同的数据范围，并决定月度目标是否
可以覆盖 Mapping 级联衰减。当前实现无法同时满足“级联完全不变”和“最终计数严格
相等”。

## 八、算法保证与非保证汇总

当前算法保证：

- 相同输入得到相同 Code 日度结果；
- 在容量允许时，Code 各指定月份的日度整数合计等于 Code 月度目标整数；
- 单日不良数不超过当日投入；
- Code Sheet 驱动 Code 日度，Group 日度严格由 Code 日度按 Group 汇总；
- Code 周/月和 Group 周度均从最终日度聚合；
- Group Sheet 只覆写 Group 月度，不反向生成 Group 日度；
- 跨月插值基线没有月初目标值阶梯。

当前算法不保证：

- 最终日度整数在月界连续；
- Group Sheet 已覆写月份的 Group 月度等于 Group 日度合计；
- Mapping 与 MWD 最终计数严格相等；
- Mapping 上调在级联后仍然生效；
- 大倍率 Mapping 的内存和响应时间有固定上限。
