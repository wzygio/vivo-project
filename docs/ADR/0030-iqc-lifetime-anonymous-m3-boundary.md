# ADR-0030：IQC 寿命测点的 M3 与匿名展示边界

- Date: 2026-09-15
- Status: Accepted
- Scope: IQC lifetime
- Trace: [数据源分析](../dev_docs/dev_spec/iqc_domain/datasource-寿命测试报表分析.md)、`.scratch/iqc-lifetime/PRD.md`

## Context

寿命报表必须读取不同于既有 WMS 的 M3 连接，并隐藏 panel_id。样品在不同产品、批次、画面内分别编号；测试时间是持续时间数值，批次号虽形似日期，但属于标识。需求授权直接开发至 E2E 通过。

## Decision

1. 在 IQC 各 DDD 层新增 `lifetime/`，application 持有只读端口，域 composition 组装 M3 仓储。M3 连接池仅读取 M3_DB_*；保留原 DatabaseManager 的配置和重试生命周期。
2. core 在完整组内按 panel_id 字符串排序生成 1..N 编号，再删除原标识、额外列、原索引及 DataFrame attrs。只有公开 DataFrame 跨越 Streamlit 数据缓存；注入服务绕过默认缓存。
3. 批次号与数值测试时间不进入日历前推/当日截止流程。保持源衰减比例，不进行二次计算或寿命合格推断；未确认的物理单位不标注。
   - 2026-09-21 用户确认：批次号允许为空（NULL、空字符串或纯空白），在公开投影中统一为“未填写批次”，参与筛选、分组、编号和导出；不增加批次缺失提示。同产品/测试画面的空批次记录归为同组；其它身份和测点冲突校验保留。
4. 完全重复测点去重；相同组、样品、数值时间的冲突测点使报表失败。缺测保留空白及断线，不插值或平均。组内样品数不强制为五个。
5. 数据库故障不缓存、不回退示例；前端只显示安全业务提示，服务端仅记录错误代码和异常类型。表格使用原生 `st.dataframe`，图表和表格（含原生导出）只接受公开测点。

## Alternatives Considered

- 覆盖 DB_* 或修改既有 singleton：容易让其它报表连接错误数据库，故使用独立 M3 池。
- 在前端隐藏原 ID 列：数据仍可从图表 JSON、表格等取回，不符合匿名要求，故在应用输出前投影。
- 筛选后临时编号：会随选择或分页漂移，故先处理完整组。
- 持久编号表：可保证新增样品后旧编号永不变化，但需新增持久状态及写入，超出只读范围。本期保证同一数据集上的稳定排序编号。
- 按显示日期处理 test_time/date_key：会破坏测试进程与批次身份，故不应用日历转换。

## Consequences

优点：来源可对账，编号与图表一致，原 ID 无前端传播路径；时间与衰减口径清晰。
代价：源测点增长时读取和完整组投影成本增加，图表数量由用户选择的产品/批次范围决定；当前核验总量 100 条。
约束：若需要跨数据版本永不改变的编号或更大数据量的按需查询，应先明确编号持久化与全组查询契约。当前字典序中新增更靠前的 ID 可能改变旧编号。

## Verification

真实 M3 逐组逐测点比对全部要求字段；服务、缓存/重载、只读仓储和 AppTest 测试；Playwright 真实页与受控状态均通过。
命令、计数、回归限制及截图位置见数据源分析的验收记录。
