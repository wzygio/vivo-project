# ADR-0047：固定 ARRAY 跨站路径在取数侧补充

- Status: Draft（实现与验证后待用户批准合并并采纳）
- Date: 2026-11-17
- Scope: Indicator Q-Time 固定 1A200 → 21100 来源与原仓储的组合

## Context

原成品 Q-Time 表没有该路径，CPT 依赖已有主记录也不能直接补出。用户明确要求只借鉴 CPT 的取数关联/去重，标准输入之后完全沿用现有报表。真实样本证明两个 TrackIn 及产品映射可得，且多个起点可能共用一个终点。

## Decision

1. 在 Infrastructure 增加固定路径只读来源，生产组合根显式注入现有仓储，不修改应用出站端口或新建通用站点业务引擎。未注入的既有调用和其他厂别保留原行为。
2. 保留 CPT 按起点分组选择最早终点的粒度；以起点进站作为标准 timekey，避免终点共享引起的原人工决策键冲突。两端时间差在源准备完成，后续修饰使用原函数。
3. 起点产品规格按名称、版本、厂别唯一映射到产品代码；有限窗口、有容量上限和超时的只读查询拒绝歧义和截断，使用内存处理而非临时表。
4. 来源并入现有厂别快照，以 ARRAY 专属来源策略后缀使旧快照失效。成品源保留尾部增量，补充路径重读完整滚动窗口，原子替换它的旧片段；失败不推进完整新鲜结果。
5. 不设置实际规格，不新增无规格专用下游逻辑；保留原图表、三态人工决策、限幅、预警与发布语义。

## Alternatives

- 仅在页面增加选项：没有源数据，不能工作。
- 复用 CPT 全部状态/展示逻辑：越过用户限定的取数范围，且改变已验证的现有修饰与预警，未采用。
- 终点时间作键：样本出现重复终点，不能保持现有四键，改用 CPT 起点粒度。
- 只重读补充路径的增量尾段：会遗漏旧起点后来才完成的记录；当前有界规模可承受，采用全滚动窗口读取补充路径。

## Consequences

复用既有服务、页面和测试边界，维护成本集中在输入适配。补充路径每次刷新多一次有界履历与主数据读取；容量或负时长/映射问题会显式失败，不能用部分结果冒充完整成功。ARRAY 旧快照需要正常源刷新，其他厂别的原快照策略保持兼容。
