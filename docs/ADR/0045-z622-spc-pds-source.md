# 0045 — Z622 SPC 指定批次 PDS 测量接入

日期：2026-11-16。状态：已采纳并验证；交付为本地工作区改动，未执行 Git 发布或生产服务重启。

## 背景

2026-11-17 变更：用户确认既有 `mdw.dwd_imp_dv_param_spec` 已补入 Z622 规格，并授权恢复修饰、能力分析及 CPK/CPM 预警。原“仅测量、空规格”限制从此废止。Z622 从同一规格表读取自身规格，不引用 M626 阈值；PDS 来源、批次与原始快照身份不变。报表分析缓存使用独立版本失效，避免为恢复分析重取测量数据。离线能力元数据及周度统计不再跳过 Z622，目录继续复用 PDS 监控工作簿，和报表口径一致。下文记录 2026-11-16 的初始决策；当前行为及验证见[分析功能恢复记录](../dev_docs/generated/inline_domain/spc/z622-analysis-activation.md)。

[新品数据导入需求](../dev_docs/dev_spec/inline_domain/spc/task-新品数据导入.md)要求把 Z622 接入现有 SPC 报表，以现有数据源中的监控站点和参数确定读取范围，指定新来源为 `eda.array_pds_result_t`，指定批次为 `L3ZB6BE03`。PDS 为按事件时间等字段分区的大表，不能通过未限定分区的扫描发现业务范围。

既有 `SpcRepository` 委托共享测量制备管线，页头强刷则从组装层直接获取 raw repository。仅替换前者会让刷新走回旧来源。用户已确认允许组装层增加新品分发，并确认 Z622 当前仅导入测量，不采用 M626 的规格、不计算能力指标。

2026-11-21 变更：Z622 的 ARRAY PDS 批次改由 Inline 域配置的 `spc.z622_pds.lot_ids` 管理，初始包含 `L3ZB6BE03` 和 `L3ZB6BE04`。按 Glass ID 前九位匹配并填写 Lot ID，批次清单参与原始快照、SPC 输入缓存与 Z622 周度 Sheet 成员签名。下文的单批次描述记录最初的接入口径。

## 决定

1. 新来源由 SPC infrastructure 拥有，组装层为 Z622 绑定专用 raw 与元数据 adapter；其他产品保留原装配。首次加载、强刷、增量更新和断库回退复用现有快照生命周期。
2. M626 仅作为监控组合参考。以 2026-09-01（含）至 2026-11-17（不含）的实际三厂观测结果与 SPC 参数白名单求交集，排除既有站点／参数排除项，形成受维护的监控工作簿。全局资源注册表管理位置，启用产品清单包含 Z622。
3. PDS 只供 ARRAY 组合，批次由 `glass_id LIKE 'L3ZB6BE03%'` 确定，不通过产品字典推断。读取窗口从源时间 2026-10-01 起，并按日传递 `glass_start_time >= start AND glass_start_time < end`，每批传输 50,000 行，数据库会话只读且查询超时 30 秒。
4. 数据库只做范围和站点参数完整组合筛选；原始记录保留复测事实。共享制备按 `prod_code + step_id + param_name + sheet_id + site_name` 选择最新记录，避免只用 Glass／点位导致跨站点或跨参数误删。后续显示时间、日期排除、异常点过滤和最终点位输出继续使用现有实现。
5. 元数据提供监控组合的标识行，`usl`、`lsl`、`ucl`、`lcl`、`target` 全部未知。标识行不代表已配置规格；现有能力准入会排除缺规格数据，不能据此产生 CPK／CPM。未来引入规格属于单独的业务决定。
6. Z622 快照 manifest 和 SPC 输入缓存签名绑定 PDS 来源、批次及实际生效的逻辑监控组合；工作簿企业加密容器的字节变化不代表业务配置变化。来源或有效组合改变后，旧代次不能命中或作为失败回退。原始快照保留源时间，显示时间策略仍在输出边界执行。
7. 对共享 `publish_snapshots()` 增加可选 `extra_metadata`，将 Z622 来源签名与 Parquet、policy 和覆盖 manifest 在原有同一发布事务内暂存、替换和失败回滚。附加字段不能覆盖现有覆盖范围或文件身份字段；其他调用不传入此参数，维持既有发布行为。来源签名从实际读取的数据属性传入，发布前再次核对当前配置，避免查询后配置变化却签发新配置代次。

## 替代方案与取舍

- **仅在 `SpcRepository` 内替换 prepared 输出**：更少修改文件，但强刷绕过它；重复处理日期、分类及追溯还会形成第二条点位制备链。采用组装层分发后，刷新与读取契约一致。
- **查询 PDS 后使用 `DISTINCT ON` 排序去重**：可在 SQL 中返回每点最新值，但大范围排序增加数据库压力，也容易把多指标查询误写为仅按 Glass／点位去重。复用现有内存完整键去重，保留 raw 快照事实。
- **直接借用 M626 规格**：能使现有能力计算具备输入，但与用户确认的仅测量范围冲突。采用数值未知的标识元数据，使当前报表仍使用同一契约，又不制造阈值或能力结论。
- **将工作簿位置写死在新品代码或产品 YAML 中**：初始接入简单，但破坏资源位置单一来源。采用全局资源键 `spc_z622_monitoring`，维护者可调整工作簿位置。
- **发布三件套后单独改写 manifest 加来源签名**：单文件改动更少，但签名写入失败会留下部分发布代次，破坏既有回滚边界。选择可选附加元数据扩展，在共享原子发布内一次提交来源证明，避免新增第二套发布器。

## 后果与维护边界

Z622 的有效数据范围是指定批次、ARRAY 及已维护监控组合，不代表已接入 OLED／TP 或全部新品批次。工作簿中保留其他厂别参考组合供核对，不会据此跨来源读取 PDS。

日窗和分块限制单次工作范围，但整体耗时仍随选择天数和目标批次数据量变化。查询前的规模评估使用数据库目录与分区统计，不能用无界 `COUNT(*)` 或 `EXPLAIN ANALYZE` 替代。

受企业保护的工作簿经现有解密组件的 `excel-values` 策略只读取配置值：Office 只读打开，禁用宏和链接更新，不执行 SaveAs，临时标准副本归 `output/` 并清理。维护工作簿和产品配置是持久输入；读取失败必须显式报错，不能以空监控清单继续运行。
