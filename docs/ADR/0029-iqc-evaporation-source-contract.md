# ADR-0029：IQC 蒸镀材料报告目录、测量来源与判定边界

- Date: 2026-09-15
- Status: Accepted
- Scope: IQC 蒸镀材料报告
- Trace: [需求与数据源分析](../dev_docs/dev_spec/iqc_domain/eva_materials/datasource-蒸镀材料报表分析.md)、`.scratch/iqc-evaporation/PRD.md`

## Context

蒸镀材料页面从本地示例迁移至用户提供的 WMS SQL。SQL 先按目录展开特性，再关联票据的测点及存储结果。
目录曾因缺少 SELECT 权限而不可读，而测量结果表已经可读；直接用测量结果表替代目录会遗漏未录入项目。
SQL 同时输出存储 IQC/COA 结果和测点 CASE 判定，两者语义不同。2026-09-21 用户在对账后明确要求采用 CASE 的 ELSE OK 逻辑，包括缺测返回 OK。

## Decision

1. 仓储复用共享 DatabaseManager，在只读事务执行绑定日期参数的查询，完整保留目录展开及结果 LEFT JOIN。
   缺表、权限或查询错误使整次读取失败，不以部分记录、示例数据或空集作为成功结果。
2. 2026-09-21 更新：core 根据原 SQL CASE 判定各个 IQC／COA 测点，违反任一已提供的规格条件为 NG，否则 OK；缺测、无规格或无法命中比较符均遵循原 ELSE OK。
   对应五个测点任一 NG 则整体 NG，否则整体 OK。此规则替代读取存储整体结果的展示口径，原始字段仍按数据库值读取，不写回数据库；缺失规格和测点不补值。
   页面说明缺测按 OK 处理；判定规则版本纳入缓存键，避免沿用旧空白结果。
3. application 持有读端口，composition 绑定 infrastructure；core 维护测点判定、整体结果、公开字段投影。
   蒸镀材料实现在各层的 `eva_materials/` 子模块中，对应 section 也使用同名子模块；域级 composition 保持统一组装。
   既有寿命示例继续独立读取，生产页面不依赖其数据。后续业务的组织规则见 [CONTEXT.md](../../CONTEXT.md#business-submodule-organization)。
4. 检验日期窗口遵循原 SQL 的 CHECKEDDATE；仓储反算源窗口，输出 REQUESTDATE/CHECKEDDATE 时应用共享前推与当日截止。
   Streamlit 仅缓存公开 DataFrame；当前缓存包含显示窗口、前推、截止、有效产品、启用配置、工单类型以及判定／产品范围规则版本，TTL 服从全局配置。只缓存已经按物料成员关系完成筛选的公开数据。
5. 页面仅接收公开字段（首版 27 列，第 8 条优化后 28 列，第 9 条删除批次后 27 列）；根据后续页面简化要求，使用原生 `st.dataframe` 展示完整结果，不再手写着色与分页；数据库内部字段和异常细节不送往普通用户界面。
6. 2026-09-22 历史更新（产品筛选部分已被第 7 条替代）：infrastructure 固定限定 V3／有机；当时按通用产品源属性移除额外的产品条件。
   页面只保留日期与查询按钮，移除产品型号控件；不读取 enabled_products，不在应用层或前端过滤产品。产品型号作为源字段继续展示。
7. 2026-10-13 Task2 更新：用户确认“通用”不代表不能筛选产品；物料与产品通过蒸镀批次形成多对多关联。产品多选只提供严格启用范围，空选代表全部；物料关联任一所选产品即进入结果，保持检验事实行数和 WMS 产品属性。
   用户进一步明确选择工单主数据范围，包含尚未入库工单：沿用 Mapping 从工单描述提取批次日期的规则，工单产品规格关联产品主数据；工单子类型受全局工单策略控制。不要求 CT／入库 Panel 存在。
   adapter 在同一只读事务中读取事实和当前物料的成员关系，并在公开投影前过滤；association 不进入前端。产品／配置／策略改变隐藏旧结果。空启用列表不查询，配置或关联失败明确失败，不使用兼容默认型号或未过滤旧数据。当前细节由 [产品范围规则](../../references/domain/iqc_domain/eva_materials/rules-evaporation-product-scope.md) 维护。
8. 2026-10-13 后续展示优化替代第 7 条的 WMS 属性展示约定：公开“产品型号”使用所选范围内的关联产品代码，紧随其后增加“蒸镀批次”（蒸镀周期）。多值按物料聚合，保留检验事实行数，不推断来料批号的实际消耗归属。表格、公开缓存与 CSV 使用同一投影；范围版本升级为 v2。聚合顺序及字段语义由上述产品范围规则维护。
9. 2026-10-13 用户进一步要求删除公开“蒸镀批次”字段，恢复 27 列；周期继续用于内部产品关联，范围版本升级为 v3。日期初始默认范围改为上个月 1 日至今天，按日历月份计算。此项替代第 8 条的批次展示约定。

## Alternatives Considered

- **只读测量表**：减少依赖，但丢失尚未测量的目录项目，因此不采用。目录权限最终由用户开通。
- **根据测点计算整体 IQC/COA 结果**：首版未采用；2026-09-21 按用户后续明确要求采用上述规则。
- **故障回退本地示例**：能显示表格，但无法代表当前来料事实，因此不采用。
- **页面直接 SQL**：接入短，但难以隔离时间转换、查询故障和 UI 测试，因此使用应用端口。
- **以 WMS“通用”直接筛选产品**：不能表达蒸镀物料的多产品用途，错误删除有机材料，因此不采用。
- **完整 CT／入库关联决定产品范围**：语义限定已入库事实且实库超时；用户选择包含尚未入库工单的主数据关系，不将性能优化伪称为与 Mapping 入库范围等价。

## Consequences

正面：可追溯至原 SQL，未测目录项目不丢失；各测点计算结果与原 CASE 一致，可用固定端口测试异常路径。
代价：依赖目录权限及完整数据库链路；缺测也会按用户授权规则显示 OK，OK 不代表一定有测量记录。目录的多个备注可能匹配同一特性，保留原 SQL 行数语义。
约束：若未来需要归并目录重复、计算整体结果或再次调整物料/产品范围，须先定义新的业务口径，不能当作展示优化改变事实。

## Verification

以下为首版验证；当前产品筛选收敛验证见所链接数据源文档的“产品筛选收敛验收”。

- 真实数据库：原 FineReport SQL 与实现的 2,518 条记录、26 个业务字段逐行多重集对账通过。
- 29 项聚焦测试通过，涵盖字段/空白/筛选、只读查询窗口与截止、缓存热重载、失败重试、SQL 关联、架构和原示例回归。
- Playwright 真实页面：查询、分页、分类及特性筛选、27 列、空集、1365px/768px 无页面横向溢出通过。
- Playwright 受控端口：故障与恢复、末页 201–205 行、存储 NG、空白 COA、筛选空交集通过。
- 浏览器证据位于 `output/test-results/iqc-evaporation/`；测试入口在数据源分析中列出。

2026-09-21：产品型号改为多选，空选表示全部已启用型号加通用；型号集合按源值精确匹配，未启用型号与空型号不进入页面或导出。

2026-09-22（历史）：当时覆盖此前单选／多选产品范围约定；该产品筛选部分已被 2026-10-13 Task2 决策替代，V3／有机范围继续保留。

2026-10-13：产品范围通过工单主数据的蒸镀批次成员关系筛选；实库独立完整坩埚 SQL／工单关联及 WMS 字段多重集对账通过。来源、当前验证命令和结果见 [Task2 分析](../dev_docs/dev_spec/iqc_domain/eva_materials/datasource-蒸镀材料产品关联分析.md)。
