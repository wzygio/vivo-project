- 日期：2026-08-18
- 状态：已批准（2026-08-26，D1 经评审调整：Group Sheet 人工指定优先）
- 需求来源：`docs/dev_docs/dev_spec/yield_domain/feat-mwd_processor-opt.md`
- 关联页面：`app/pages/入库不良率分析看板.py`
- 关联代码：`src/yield_domain/core/mwd_trend/`、`src/yield_domain/core/mapping/mapping_processor.py`、`src/yield_domain/core/defect_modifier.py`、`src/yield_domain/application/yield_service.py`、`src/yield_domain/application/excel_service.py`
- 关联数据：`resources/入库良率修饰表.xlsx`（企业加密，Sheet 按 `<产品型号>_Group级` / `<产品型号>_Code级` 划分）

## 1. 背景与问题

入库良率模块的数据修饰链路当前为
"Codebaseline → EMA → 趋势调节/截断 → 月度校准 → 人工覆盖（趋势图人工修正.xlsx）"，
只有开发人员能理解，报表需交接给业务人员维护，必须简化。

### 1.1 现状链路（事实依据）

Code 级（`mwd_trend_processor.py:167-242` `create_code_level_mwd_trend_data`）：

1. `data_preparation.prepare_code_raw_data` 按日/Group/Code 统计原始不良 Panel 数与每日投入数；
2. `pad_daily_data_to_end` 补齐日历；
3. `ema.calculate_code_ema_noise` 以 `resources/codebaseline.xlsx` 的基线率为锚做月内有界 EMA，乘缩放系数与投入数，叠加**正弦**确定性噪声（`ema.py:117`）；
4. `trend_regulator.TrendRegulator` 按警戒线压制日度上限；
5. `allocation.reconcile_code_daily_counts` 把日度校准回原始月度整数总量；
6. `pipeline.run_manual_period_pipeline` + `manual_overrides.py` 应用
   `趋势图人工修正.xlsx` 的月/周/日人工覆盖（由
   `excel_service.inject_excel_overrides_to_config:230` 注入 `config.processing`）。

Group 级（`mwd_trend_processor.py:98-164`）不重算 EMA，由 Code 日度按 Group 汇总后走同一套人工覆盖管线。

Mapping 图（`mapping/mapping_processor.py:22` `prepare_mapping_data`）：以批次为粒度，
不良数 = 每 `(batch_no, defect_desc)` 的行数，只取最新 5 个批次，先经
`defect_modifier.apply_defect_multipliers`（YAML 全局倍率，`yield_service.py:159`），
再经 Rate-Based 级联衰减（`mapping_processor.py:137-189`）。
**红线：级联衰减逻辑禁止静态重构**（`.roorules:48`、`references/domain/yield_domian/yield_domain.md:107`）。

### 1.2 修饰表现状（已实测）

`resources/入库良率修饰表.xlsx` 共 10 个 Sheet（M626/M678/Z571/M673/Z517 × Group级/Code级），
列固定为：`不良类型 | 周期类型 | 时间标签 | 当月良损 | 指定良损 | 缩放倍数`。

- `周期类型` 目前只有"月度"；`时间标签` 形如 `2026-07`；
- `当月良损` 已填（2026-06/07/08），`指定良损`、`缩放倍数` 全为空；
- 文件中尚无任何代码读写该表（全库检索仅命中需求文档），需新建读写组件；
- 读取走既有 `_read_encrypted_xlsx_via_com`（COM 解密），写回走既有
  `excel_tools.replace_workbook_sheet`（openpyxl 失败时整体重写为明文工作簿，
  与 `codebaseline.xlsx` 既有行为一致）。

## 2. 方案评估（结论：可行）

需求方案（删除旧链路、全部改为"入库良率修饰表"人工指定）可行，依据：

1. **替换点清晰**。facade 的中段（EMA/调节/校准/覆盖）可整体替换为
   "指定月度良损 → 日度生成"，前后两端（`data_preparation` 原始统计、
   `aggregation`/`formatting` 聚合与输出）原样保留。
2. **读写基础设施齐备**（见 1.2），无需新增依赖。
3. **Mapping 同步可在不触碰级联衰减的前提下实现**：在级联衰减（步骤3）之前
   增加一个"月度缩放"前置抽样步骤即可，红线逻辑一行不动。
4. **安全默认**：当前修饰表 `指定良损` 全空，落地后所有趋势 = 原始数据、
   缩放倍数 = 1.0，行为可预测、可灰度。

需要需求方知晓的三个设计决策（本 PRD 已选定，评审时可调整）：

- **D5（开发阶段补充）当月良损的计算口径**：用与趋势图相同的一份 panel 明细
  （即 defect_multipliers 修饰后的展示数据）计算。这样 Mapping 数学严格成立：
  展示不良数 = 展示原始数 ×（指定良损 / 展示原始良损）= 指定水准；若改用 L1
  原始数据，在 defect_multipliers 非空时 Mapping 会与趋势差一个全局倍率。
  defect_multipliers 为空（默认）时与"数据库原始良损"口径一致。

- **D1 Group Sheet 仅覆写月度（2026-08-27 评审修正）**。Code 级 Sheet 驱动
  Code 趋势图与 Mapping 缩放；Group 日度严格由 Code 最终日度按 Group 汇总，
  Group 周度由该日度聚合。Group 级 Sheet 只覆写 Group 月度，不反向生成日度。
- **D2 写回时机**。Streamlit 页面计算（cache miss）时顺带把"当月良损"与
  "缩放倍数"写回修饰表；写回失败（文件被 Excel 占用等）仅记日志不影响展示。
  另提供 CLI 工具供业务手动刷新。
- **D3 `趋势图人工修正.xlsx` 停止消费、文件保留**。其六类覆盖配置不再注入
  `config.processing`；`mapping_config.xlsx` 的注入不受影响。

## 3. 目标设计

### 3.1 总体数据流

```text
原始 panel_details_df（L1，未修饰）
  │
  ├─► 修饰表管理器 modifier_table.py
  │     读取 <prod>_Group级 / <prod>_Code级
  │     计算当月原始良损 → 回写"当月良损"（仅当月行）
  │     检测"指定良损"签名变化 → 重算并回写"缩放倍数"（两位小数）
  │     输出：每月目标良损表（含上月回退）、Mapping 缩放因子表
  │
  ├─► Code 趋势：日度生成器 daily_generator.py（Code 级指定良损）
  │     → aggregation 聚合周/月 → formatting 输出
  │
  ├─► Group 趋势：Code 最终日度按 Group 汇总
  │     → aggregation 聚合周/月 → Group Sheet 只覆写月度 → formatting 输出
  │
  └─► Mapping：apply_defect_multipliers（YAML 全局，保留）
        → 【新增】按"批次所属月份的缩放倍数"确定性抽样/复制（Code 级）
        → 级联衰减（红线，不动）→ 前端
```

Mapping 不良数最终影响因子 = defect_modifier（全局）× 缩放倍数（月度）× 级联衰减，
与需求 §Requirements 第 45 行一致。

### 3.2 新模块一：修饰表管理器 `core/mwd_trend/modifier_table.py`

职责（全部为纯函数 + 一个 IO 类，便于单测）：

- `read_modifier_table(path, product_code) -> dict[str, DataFrame]`：
  读取 `<prod>_Group级` / `<prod>_Code级` 两个 Sheet；openpyxl 失败回退 COM
  （复用 `excel_tools` 既有模式）。列校验缺失时记告警并视为空表。
- `compute_current_month_loss(panel_details_df, level) -> DataFrame`：
  从原始 panel 明细计算当月的"不良类型 → 当月良损"
  （不良 Panel 去重数 / 当月投入 Panel 去重数；Group 级按 `defect_group`，
  Code 级按 `defect_desc`）。
- `resolve_monthly_targets(table_df, months) -> dict[(不良类型, 月份) -> rate]`：
  对每个不良类型逐月取目标良损：
  1. 当月 `指定良损` 非空 → 用之；
  2. 否则回退到**最近一个有 `指定良损` 的上个月**；
  3. 否则用 `当月良损`（原始水准，等价缩放倍数 1.0）。
- `compute_scale_factors(table_df) -> dict[(不良类型, 月份) -> float]`：
  `缩放倍数 = round(指定良损 / 当月良损, 2)`；`当月良损` 为 0 或空时倍数记 1.0。
- `signature(table_df) -> str`：对 `不良类型|时间标签|指定良损` 列做稳定哈希，
  用于"配置文件有改动"检测（与 `code_baseline.defect_multipliers_signature`
  同类思路）。
- 写回 orchestration：`sync_modifier_table(path, product_code, panel_details_df)`：
  - 当月行不存在 → 追加；已存在 → 仅更新 `当月良损` 列；
  - `指定良损` 签名与上次（存于同工作簿 `<prod>_metadata` Sheet 或 sidecar
    `resources/decrypted_files/` 不放，放 `data/<prod>/`）不一致 → 重算并回写
    `缩放倍数` 列与新签名；
  - 写回用 `replace_workbook_sheet`，`PermissionError` 等异常仅记日志。

### 3.3 新模块二：日度生成器 `core/mwd_trend/daily_generator.py`

输入：每日投入数序列（来自 `data_preparation`）、每个不良类型的
"月 → 目标良损"（3.2 输出）、波动幅度 `volatility`（默认 0.3，仅影响日度形状）。
输出：与现状 `automatic_daily` 同构的日度不良数表（整数）。

算法（逐不良类型）：

1. **月度目标量**：`target_count(m) = round(rate(m) × 当月投入总数)`。
2. **跨月平滑基线**：把各月目标良损锚定在月中（15 日），相邻锚点线性插值得到
   每日基线率 `base(d)`——跨月过渡天然平滑，无阶梯。
3. **确定性扰动**：`noise(d) = 1 + volatility × (2u − 1)`，其中
   `u = blake2b(f"{product}|{defect}|{date}", digest=8) / 2^64`。
   纯哈希白噪声：无周期性震荡（替换旧 EMA 的正弦噪声），且输入不变输出不变，
   满足"每次生成数据不变"（不依赖 Python 内置 `hash()`，避免进程间不稳定）。
4. **日度权重**：`w(d) = base(d) × noise(d) × total_panels(d)`；
   当月投入为 0 的日权重为 0。
5. **整数分配**：月内按权重把 `target_count(m)` 分配到日（最大余数法，
   单日上限 = 当日投入数；复用 `daily_generator.allocate_integer_counts`）。
   分配在月内闭环 → **月度合计精确等于目标量**。

Code 周/月与 Group 周度直接由最终日度经 `safe_trend_aggregator` 聚合；Group 月度
在聚合后应用 Group Sheet 覆写，且不回写日度。

### 3.6 Mapping 月度缩放（不触碰级联红线）

`mapping_processor.prepare_mapping_data` 新增可选参数
`monthly_factors: dict[(defect_desc, 'YYYY-MM') -> float] | None`：

- 在步骤2（位置修饰）之后、步骤3（级联衰减）之前插入步骤2.5：
  对每个 `(batch_no, defect_desc)`，按批次日期所属月份查因子 `f`（缺省 1.0）；
  - `f < 1`：确定性抽样 `sample(n=int(count×f), random_state=42)`；
  - `f > 1`：整倍复制 + 余数抽样，复制行 `panel_id` 加 `_SIM_M{i}` 防碰撞后缀
    （与 `defect_modifier` 既有模式一致）；
- 因子表由 `YieldAnalysisService.get_mapping_data` 从修饰表 Code 级 Sheet 的
  `缩放倍数` 列构建传入；趋势日度与 Mapping 因此共享同一"指定良损"水准，
  月周日趋势不良数与 Mapping 不良数在月度口径一致（需求 §Solution 第 4 条）。

### 3.8 边界与异常

- `指定良损` 全空 → 全部回落原始数据，缩放倍数 1.0；
- 某不良类型当月无原始数据（`当月良损` 空）但有历史指定 → 用最近上月指定良损，
  倍数以最近可得 `当月良损` 计算，缺失则 1.0；
- `当月良损 = 0` 且 `指定良损 > 0` → 倍数无法定义，记 1.0 并记告警
  （趋势仍按指定良损生成，Mapping 无法从 0 放大，接受该口径差异）；
- 修饰表文件不存在 / Sheet 缺失 / 被占用 → 全部按原始数据出图，仅记日志；
- 百分比字符串（"1.03%"）与">1 的小数防呆"沿用
  `excel_service._parse_override_excel` 既有解析惯例；
- 时间窗口外的月份：目标良损可取自修饰表全部历史行（不限于 3 个月窗口），
  保证上月回退链可用。
