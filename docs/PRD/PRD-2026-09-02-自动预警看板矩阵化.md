# PRD：自动预警看板矩阵化（产品 × 监控参数红绿矩阵）

- 日期：2026-09-02
- 状态：已评审（可行性已确认，待实施）
- 适用范围：`app/pages/自动预警看板.py`（矩阵化改造）、`src/inline_domain`、`src/yield_domain`、`src/indicator_domain/qtime`
- 需求来源：`docs/dev_docs/dev_spec/Inline_domain/feat-alert_center.md`（Task-1：自动预警看板）
- 可行性分析：`docs/dev_docs/generated/others/alert-center-matrix-board-feasibility.md`
- 前置 PRD：`docs/PRD/PRD-2026-08-25-Inline自动预警中心.md`

## 1. CAPABILITY

报表使用者打开自动预警看板时，系统在页首展示一张**产品 × 监控参数的预警矩阵**：

- **列** = 各启用产品（当前 7 个：M626 / M673 / M678 / Z517 / Z553 / Z571 / Z576）；
- **行** = 各监控参数（见 §3.1 矩阵行清单，覆盖 aoi_rs / aoi_tt / spc / ctq / yield / qtime 六个子模块）；
- **单元格** = 四态指示灯：🟢 达标（上一 ISO 周无预警）/ 🔴 不达标（有预警）/ ⚪ 无数据 / ⬜ 加载失败（灰点 + tooltip 原因）。

**点击红点单元格**后，按需懒加载该 (产品, 监控参数) 的预警明细表与图像，不阻塞矩阵本体渲染。

## 2. 背景与现状

### 2.1 已验证的现状（调研结论）

1. `app/pages/自动预警看板.py` 已是全产品模式：固定 `prod_code="ALL"`（`自动预警看板.py:138-153`），`MonitorAnalysisService.fetch_dashboard_data_dict`（`src/inline_domain/application/monitor/monitor_service.py:281`）逐产品循环加载（:311-314），缓存键已含逐产品 revision + (prod, scope) 决策签名（`自动预警看板.py:107-117`）。
2. 该页不参与 Header 单产品筛选：Header selectbox 被渲染但数据流忽略它，页面用自带控制台（监控类型 + 产品 multiselect + 厂别 multiselect）对已缓存 ALL 数据前端切片。
3. inline 数据规模：量测 ~246 万行 / ~30MB parquet；修饰工作簿均 ≤ 400K。yield 快照 ~354 万行。qtime 无本地文件，纯生产库查询。
4. qtime **无任何缓存**（全链路无 `st.cache_data`），服务层已支持多产品（`products: tuple[str, ...]`，空 = 全产品，`application/qtime/service.py:60`；仓储 `repository.py:116-118` 仅在非空时追加 WHERE）。ADR-0019 记录过目标表权限与超时历史。
5. `fetch_decorated_features` 缓存 `max_entries=12`（`decorated_features.py:79`），矩阵模式 7 产品 × 2~3 scope = 14~21 条目，会淘汰抖动。
6. `fetch_dashboard_data_dict` `max_entries=1`（`monitor_service.py:276`），任一签名变化全量重算。
7. SPC 页预警图像管线（RenderGate + `collect_memoized`，签名 = 产品 revision + 预警内容指纹，`spc_dashboard.py:762-828`）可直接复用为点击详情的懒加载渲染。
8. `safe_refresh_snapshots` 任一产品失败即整体不推进 revision（`monitor_service.py:655-712`）——全产品模式下需按产品降级而非整页失败。

### 2.2 已确认的业务决策

- **D1（矩阵不自动渲染图像）**：采纳需求方 hint，矩阵单元格只渲染指示灯；图像与明细改为点击后懒加载查询。
- **D2（qtime 接入矩阵）**：qtime 相关风险点全部按可行性报告建议修正——先补缓存层（§4.3），再作为矩阵行接入。
- **D3（矩阵页绕开 Header 产品筛选）**：沿用预警看板既有先例，不改 Session 单产品模型与 Header 机制。

## 3. CONSTRAINTS

### 3.1 固定业务规则

1. 矩阵行清单与预警口径（全部沿用既有判据，不修改任何算法）：

| 矩阵行（子模块） | 预警类型 | 判据来源 |
|---|---|---|
| aoi_rs 单片异常 | sheet 超规 | `aoi_rs_sheet_oos_decoration` 中 flag=FALSE 且时间 ∈ 上一 ISO 周 |
| aoi_tt 单片异常 | sheet 超规 | `aoi_tt_sheet_oos_decoration` 同上 |
| spc 单片异常 | sheet 超规 | `spc_sheet_oos_decoration` 同上 |
| spc 趋势波动 | cpk 超规 | 既有 CPK 预警（cpk < 1.33 且未被修饰） |
| ctq 单片异常 | sheet 超规 | `ctq_sheet_oos_decoration` 同上 |
| yield 单片异常 | lot 超规 | 既有 `compute_lot_oos_records` |
| yield 趋势波动 | 良率波动 | 既有 `AbnormalDetector` 结构化记录 |
| qtime 单片异常 | sheet 超规 | `build_qtime_alerts`（flag=False，`core/qtime/alerts.py:19-28`） |

2. 时间窗统一为上一 ISO 周（半开 `[上周一 00:00, 本周一 00:00)`），与前置 PRD §3.1 一致；yield/qtime 域按其既有时间口径对齐，不做强行重定义。
3. 单元格四态契约为唯一展示语义：达标 / 不达标 / 无数据 / 加载失败；各域适配到该契约。
4. 矩阵计算是**只读**消费，不得触发任何修饰工作簿重写；单产品/单域失败降级为该单元格灰点，不阻断其他单元格。
5. 矩阵页不参与 Header 单产品筛选；不改动 `SessionManager` 单产品模型。

### 3.2 渲染与缓存规则

1. 矩阵 payload 计算与渲染遵守 `RenderGate` 两阶段模式：全部 payload 计算完成后一次性渲染，禁止 stage 中调用 st.*。
2. 矩阵缓存键 = 逐产品 revision 字典 + 逐 (prod, scope) 决策签名 + 时间窗，沿用 `自动预警看板.py:107-117` 先例。
3. `fetch_decorated_features` 的 `max_entries` 由 12 调大至 ≥ 32。
4. 点击单元格的详情查询走独立懒加载路径，复用各域既有图像管线与独立 chart key 前缀，不与矩阵本体共享渲染周期。
5. "刷新缓存/刷新数据"后矩阵正确重建；普通 rerun 命中缓存。

## 4. IMPLEMENTATION CONTRACT

### 4.1 后端：矩阵数据服务

新增矩阵构建服务（建议落 `src/inline_domain/application/monitor/` 或新建 `src/shared_kernel` 无关的独立模块，遵循现有分层）：

```python
def build_alert_matrix_payload(*, reference_date) -> dict:
    """返回 {
        "products": [...],            # 列头，启用产品清单
        "rows": [...],                # 行头，§3.1 八行（含模块分组）
        "cells": {(row_key, prod): {"state": "ok|alert|no_data|error", "detail_key": ..., "message": ...}},
        "signature": ...,             # 缓存签名
    }；纯计算，无 st.* 调用。"""
```

各域单元格适配器：复用既有预警构建函数（`build_sheet_oos_alerts`、CPK 预警、yield 结构化记录、`build_qtime_alerts`），仅做"记录集合 → 四态"映射；任一域/产品异常被捕获并映射为 `error` 态。

### 4.2 前端：矩阵展示与懒加载详情

- 矩阵本体：Streamlit 原生组件渲染（`st.dataframe`/列布局，按现有 UI 惯例选择），单元格为色点 + 可点击。
- 点击红点 → 展开该 (产品, 行) 的详情区：预警明细表 + 图像（SPC/CTQ/AOI 复用各域 `render_*_alert_indicator_sections`；yield 复用 `render_alert_code_expanders`；qtime 复用其预警中心 expander 内容），走 `RenderGate.collect_memoized`，chart key 前缀独立（如 `matrix_detail`）。
- 矩阵放置于 `app/pages/自动预警看板.py` 页首，既有汇总图/Top10/明细表保留在下。

### 4.3 qtime 缓存层补齐（D2 前置）

1. `application/qtime/service.py` 查询入口加 `@st.cache_data`（或在页面/section 层包裹）：键 = (products 集合, shop, step_options, 时间窗, 决策签名)，TTL 与 inline 对齐（12h，读 `config/global.yaml`）。
2. 决策签名：qtime 修饰工作簿（`resources/indicator_domain/qtime/qtime_oos_decoration.xlsx`）按文件 (mtime_ns, size) 计入签名，与 inline `decision_signature.py` 的 file_stat 门控同款思路，避免每次 rerun 直读 Excel。
3. 全产品调用：矩阵侧传 `products=()`（或全产品元组），页面既有单产品调用保持不变。
4. 缓存失败/库超时：映射为单元格 `error` 态，不阻断矩阵。

### 4.4 缓存参数调整

- `decorated_features.py:79`：`max_entries=12` → `32`（覆盖 7 产品 × 3 scope + 余量）。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 首次冷启动全量计算慢（7 产品 × 多 scope + yield 354 万行） | 中 | L1/L2 缓存已有；RenderGate 单 spinner 集中计算；矩阵不重算已缓存内容 |
| L2 缓存淘汰抖动 | 中 | §4.4 调大 max_entries |
| qtime 直查生产库超时/权限 | 中 | §4.3 缓存层；失败降级 error 态 |
| 单产品失败拖垮整板 | 中 | 单元格级降级（灰点 + tooltip） |
| 跨域口径不统一导致半新半旧 | 中 | §3.1 四态契约 + 统一签名预算完成后渲染 |
| 矩阵缓存键遗漏某域签名导致脏数据 | 中 | 键组装集中在矩阵服务一处，单测覆盖签名敏感性 |

## 7. NON-GOALS

- 不修改任何预警判定算法与阈值；
- 不改动 Header 产品筛选机制与 `SessionManager`；
- 不为矩阵新增推送/通知能力；
- 不重排自动预警看板既有汇总图与 Top10 的设计；
- 不为 qtime 新增本地 parquet 快照（仅应用层缓存）。

## 8. 验收标准

1. 自动预警看板页首出现产品 × 监控参数矩阵，列 = 7 个启用产品，行 = §3.1 八行；
2. 单元格四态正确：与同期各单产品页预警结果手工抽查一致；
3. 点击红点单元格后展示该产品该参数的预警明细与图像，且不影响矩阵本体；
4. 任一产品数据缺失/加载失败时仅该产品列对应单元格灰点降级，其余正常；
5. 普通 rerun 命中缓存（无重复全量计算、无重复 COM/DB 调用）；"刷新缓存"后矩阵正确重建；
6. qtime 页既有功能无回归（查询交互、预警中心、图像）；
7. 全部单元测试与 E2E 测试通过。

## 9. 测试计划

- **单元测试**：矩阵 payload 构建（四态映射、空数据、单域异常降级）；qtime 缓存键签名（产品集合/时间窗/决策签名变化触发重算，相同则命中）；`max_entries` 调整后 21 条目不淘汰。
- **集成测试**：临时工作簿/快照模拟多产品预警，验证矩阵与单产品页口径一致；qtime 缓存层 mock 库查询验证命中语义。
- **E2E 测试**（`tests/e2e/`，Playwright）：矩阵渲染存在性与四态展示；点击红点懒加载详情；刷新缓存后重建；qtime 页回归。
