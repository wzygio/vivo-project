# PRD：报表数据日期前推

## 1. 背景与目标

天柱专项报表面向外部客户展示制造质量数据。业务需要预留四天用于数据修饰，因此客户在显示日期 `D` 看到的应是源系统业务日期 `D-4` 的数据。

本功能引入统一的“显示日期前推”策略：启用时，将受支持的制造事实时间统一平移 `+4 天`；关闭时，保持真实日期。该策略只改变报表时间轴，不改变测量值、缺陷、规格、修饰、聚合和告警算法。

## 2. 术语

- **源时间（source time）**：数据库或原始 Parquet 中记录的真实制造时间。
- **显示时间（display time）**：页面、下载和应用服务消费的时间，等于 `源时间 + offset_days`。
- **显示窗口**：用户在页面选择的起止时间，以显示时间解释。
- **原始快照**：持久化源时间的 Parquet；不得写入已平移时间，防止重复平移和配置切换污染。

“日期前推”不是预测未来数据。任何显示时间晚于查询截止日的记录都不得进入页面结果或下载结果。

## 3. 范围

### 3.1 纳入范围

- 全局配置：`config/global.yaml`。
- `yield_domain`：`warehousing_time`、`array_input_time`。
- `inline_domain`：共享 SPC/CTQ/AOI_TT 测量事实和 AOI_RS 独立事实的 `start_time`。
- `indicator_domain`：Q-Time 的 `timekey`；IJP 的明细 `print_time` 和日聚合 `day`，以及依赖时间窗口的筛选选项。
- `equipment_domain`：真实与仿造备件事实的 `glass_start_time`。
- 快照加载窗口、增量更新、窗口过滤、缓存签名及相关单元/集成/E2E 回归。

### 3.2 不纳入范围

- 修改测量值、缺陷数量、规格、良率、Q-Time `wait_time` 或设备寿命算法。
- 修改人工修饰工作簿中的审计时间、文件修改时间、快照 TTL 时钟和日志时间。
- 在本次代码变更中复制整个项目或部署第二个端口。内部服务使用同一代码、关闭策略即可；具体端口由部署脚本配置。

## 4. 配置契约

`config/global.yaml` 新增：

```yaml
data_forward:
  enabled: true
  offset_days: 4
```

- `enabled=false` 时偏移量为零，行为与当前系统一致。
- `enabled=true` 时 `offset_days` 必须是非负整数；生产默认值为 `4`。
- 缺少配置时安全回退为关闭，保证旧环境升级后不会静默改写日期。
- 解析结果应为不可变策略对象，并提供稳定签名供缓存区分开关和天数。

## 5. 功能需求

### FR-1 统一平移

共享内核提供唯一的时间平移能力。输入 DataFrame 必须复制后再处理，不修改调用方对象；无目标列或空表时保持列契约；非法时间按现有各域规则转为缺失值或由原有校验处理。

### FR-2 查询窗口语义

用户查询 `[display_start, display_end]`（或既有半开区间）时：

1. 直接查询型仓储将窗口反向换算为源窗口：`source = display - offset_days`。
2. 返回事实统一平移为显示时间。
3. 按原区间开闭语义对显示时间再次过滤。

这保证窗口头部不丢数据，也保证显示截止日之后的数据不泄漏。

### FR-3 三个月快照窗口

产品级原始快照的全量加载起点改为显示截止日向前 3 个月所在月份的第一天，终点为显示截止日。例如显示截止日为 2026-09-02，加载范围为 2026-06-01 至 2026-09-02。

- 原始快照继续保存源时间。
- 读取后平移并按显示窗口过滤。
- 到新月份后，下一次成功刷新裁剪早于新月初边界的记录。
- 增量更新继续保留重叠缓冲、去重、原子写入和数据库失败降级语义。

### FR-4 各域一致性

- 同一事实中的相关绝对时间应使用相同偏移，持续时间不得改变。
- IJP 日趋势的 `day` 必须与明细 `print_time` 落在相同显示日。
- Q-Time 只平移 `timekey`，不得改变 `wait_time` 和 `q_spec`。
- 设备真实和仿造事实使用相同显示策略；三天新鲜度判断以源时间完成，再将合格结果平移，避免 `+4 天` 造成“未来数据”误判。

### FR-5 开关隔离与缓存

- Streamlit/服务缓存 key 或签名必须包含策略签名，切换开关后不得命中另一模式的派生缓存。
- 原始 Parquet 不因开关切换而重写；同一份原始快照可供客户模式和内部真实日期模式读取。
- 内部真实日期部署使用 `enabled=false` 的独立配置副本或部署目录，不复制业务源码。

## 6. 非功能需求

- 不拼接新的用户输入 SQL；既有参数化查询方式保持不变。
- 不输出数据库凭据、SQL 明细或 traceback 到页面。
- 配置关闭时应通过现有回归测试，结果与变更前一致。
- 平移函数保持向量化，避免逐行处理。
- 所有新增行为使用固定时钟测试，覆盖月初、跨月、闰日、空表和无效时间。

## 7. 验收标准

1. 配置关闭时，四个 domain 的时间列和查询参数均不变化。
2. 配置开启且偏移 4 天时，源时间 `2026-08-29 10:30` 显示为 `2026-09-02 10:30`，值和标识字段不变。
3. 查询显示窗口 2026-09-01 至 2026-09-02 时，直接查询型仓储实际查询 2026-08-28 至 2026-08-29，并只返回显示窗口内记录。
4. 截止日 2026-09-02 的全量快照加载起点为 2026-06-01；跨到 2026-10-01 后起点为 2026-07-01。
5. 原始快照中的时间保持真实日期；重复读取不会累加偏移。
6. 显示时间晚于页面截止日的原始快照记录不会出现在结果中。
7. 开关或偏移量变化后，派生缓存签名变化。
8. Yield、Inline、Indicator、Equipment 定向测试通过，关键页面 E2E 测试通过。

## 8. 风险与对策

- **重复平移**：只允许共享函数在仓储返回边界执行，快照保持原始时间；测试重复读取。
- **窗口错位**：直接查询反向换算，快照查询在平移后过滤；测试闭区间和半开区间。
- **跨月少四天**：快照使用自然月月初，不使用简单 `end - 3 months`。
- **缓存串模式**：策略签名进入缓存边界。
- **设备新鲜度误判**：先按源时间判断新鲜度，再做显示平移。
- **内部/外部服务配置冲突**：采用独立部署目录或配置挂载，复用同一代码版本。
