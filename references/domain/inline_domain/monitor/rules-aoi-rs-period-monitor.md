# AOI_RS 周期密度监控

## 范围与页面

超规预警看板中的独立 AOI_RS 监控区只展示原生数据表，按产品分表，下载 Excel 每个产品一个 Sheet。产品范围与顺序来自启用产品配置，产品注释仅用于控件标签。厂别单选默认 ARRAY，产品、站点和 RSCode 默认全选；清空产品/站点/Code解释为全部当前可用选项。站点、Code选项由已发布历史提供，首次查询前以全部范围查询，成功后提供具体选项。改变查询条件后收起旧结果，重新查询才展示。

半年、季度和月份选项属于服务器当前年，默认选中已开始的全部周期。周数1–53，默认5，包含本周，使用 ISO 周并带年份。半年、季度、月、周分组排列，组内时间升序；模板中的乱序/重复周标题不作为计算依据。

## 密度与数据边界

每个产品/厂别/站点/RSCode的目标周期密度为 `Σcode_qty / 同产品厂别站点目标周期的distinct sheet/glass数`。半年和季度直接在整段去重，不能平均月密度或相加月分母。有过货而无缺陷为0，无过货为缺失值。

无 L1 的专用输入适配器按产品、单厂别和自然月分批读取有限字段；过货限制在规格/缺陷已知的 AOI_RS 站点，不扫描该产品所有工序的过货。查询严格失败上抛，PostgreSQL查询设120秒语句超时，并按50000行读取批次。既有 DAO 默认容错调用保持兼容；新监控使用严格路径，读取失败禁止覆盖历史。

基础设施把显示窗口换回源窗口，查询后执行日期前推、当天截止和 Inline 日期排除，再进行统计。现有 AOI_RS 专用规则开启时只读使用现有决策、Sheet/Lot投影和周密度限幅，不改写 OOS/OOC 台账；关闭时趋势分子沿用常规报表口径。周期计算已抽为共享纯函数，旧报表保留原两月三周七天周期轴。

## 周期明细持久化

`resources.inline_domain.files.aoi_rs_monitor_history` 配置独立汇总工作簿，默认 `resources/inline_domain/monitor/aoi_rs_period_density.xlsx`。每个产品一个 Sheet，保存周期长表及成功覆盖记录，不保存逐片明细。普通界面和下载只能接收公开宽表，不得直接暴露内部历史字段。

每个周期保存分子、去重分母、密度、周期起止、覆盖截止、刷新时间、输入规则签名及可选月份依赖。即使真实空周期也保存覆盖记录，避免重复回填。历史文件损坏、结构错误或取数失败时明确失败，不按空文件覆盖。

读取、回填和发布在同一个线程/进程事务锁内进行；内存生成完整工作簿，经同目录临时文件原子替换。任意产品计算失败则不发布本批新历史；其他产品及不需更新的周期保留。

## 刷新与失效

- 缺失或规则不兼容的周期回填；完全覆盖的闭合周期直接复用。
- 当前周期按全局缓存 TTL 复用，跨天覆盖推进后更新；管理员刷新强制更新当前受影响周期。
- 当天只覆盖到全局截止时刻，周期结束后需要补齐最后一日截止时刻之后的有效数据，不能把当天中午误当成已闭合周期完整覆盖。
- 专用规则开启时，周限幅依赖周末所属月份的完整可用月密度。因此当前月中已结束的周也可能更新；辅助月基准参与计算，但未选中的月份不出现在公开表格。
- 日期排除、专用配置、决策、参数豁免、日期前推、截止时刻和算法版本进入政策签名。显式查询还读取规格并加入计算签名；关闭源服务后不依靠原始逐片缓存重算。
- 展示签名包含查询条件、服务器日期、相关政策/决策及历史文件身份；同日变更后同时收起旧表格和下载。
- 缓存仅保存原生容器、DataFrame及导出字节；不把应用服务或自定义 ViewModel放进缓存。

当前半年/季度若仍开放，重新计算仍需读取其完整有效时间窗口；这里复用的是已闭合周期结果，不提供逐片增量事实仓库。
