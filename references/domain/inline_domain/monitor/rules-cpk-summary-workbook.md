# CPK / CPM 周度汇总与达标率趋势规则

规则更新日期：2026-11-23。本文描述统计与维护契约。正式文件迁移及真实数据修复的完成状态以对应执行记录为准。参见 [Task0–Task3](../../../../docs/dev_docs/dev_spec/inline_domain/monitor/feat-cpk_cpm_summary.md) 和 [ADR-0046](../../../../docs/ADR/0046-capability-summary-weekly-rollup.md)。

## 页面与资源

`app/pages/历史预警看板.py` 在普通模式下可查询 CPK 和 CPM 达标率趋势图。数据更新状态及 AOI_RS 区域使用管理员展示模式。各筛选 Expander 默认折叠，CPK 与 CPM 分别拥有产品选择、查询签名、图表标识和 fragment。清空产品选择表示全部启用产品。

三个看板分别维护工作簿。路径由 `config/global.yaml: resources.inline_domain.files` 拥有，应用通过组装层和资源路径解析器读取完整配置路径：

| 资源键 | 默认文件 | 内容 |
|---|---|---|
| `monitor_summary_workbook` | `resources/inline_domain/monitor/北极星报警率汇总.xlsx` | 原报警率产品 Sheet；本次能力汇总调整不改变其统计规则及维护数据 |
| `cpk_summary_workbook` | `resources/inline_domain/monitor/北极星CPK汇总.xlsx` | `<产品> CPK` Sheet |
| `cpm_summary_workbook` | `resources/inline_domain/monitor/北极星CPM汇总.xlsx` | `<产品> CPM` Sheet |

CPK/CPM 持久字段为产品、监控类型、厂别、周期类型、时间标签、总项目数、达标项目数、预警项目数和达标率。监控类型为 `SPC`，汇总厂别为 `ALL`。兼容输入中的“CPK总项目”“CPK总项数”等别名，规范字段仍为 `CPK总项目数`；CPM 同理。

“显示标签”可由周期类型与时间标签唯一生成：`2026`→`Y26`、`2026-Q4`→`Q4`、`2026-11`→`M11`、`2026-W46`→`W46`。应用内部和表格投影可使用该派生字段，CPK/CPM 正式汇总文件不再持久保存它。报警率文件的既有字段保持原样。

原合并工作簿及迁移前备份属于历史维护输入。拆分和数值修复须先备份，保留本次范围外的数据与原始快照；失败不得用空文件替换维护文件。

## 周度项目数与预警数

统计单位为产品、厂别、站点、参数和完整 ISO 周，先按业务键确定项目，再按产品汇总全部厂别。

1. **总项目数**：从已验证覆盖范围的共享原始测量快照，复用 SPC 测量制备、规格覆盖、异常点过滤、最终点位修饰、Sheet 特征及 `build_period_capability_report()` 计算。对相应 CPK 或 CPM 可计算值计数；零标准差产生的有效无穷能力值也属于可计算项目。缺规格、无有效能力值或参数豁免的组合不进入分母。Z622 使用自身 PDS 测点和规格，按相同口径计算总项目数。
2. **预警项目数**：读取 `spc_cpk_cpm_decoration` 维护工作簿，CPK 使用产品同名 Sheet，CPM 使用 `<产品>_cpm` Sheet。对对应完整周、按产品／厂别／站点／参数／周期业务键去重后的 `flag=False` 记录计数，兼容规范化的 `false`、`0`、`0.0` 表示。
3. **达标项目数**：总项目数减预警项目数。
4. **达标率**：达标项目数除总项目数；总项目数为零时为 `1`，显示 `100.00%`。

预警生产仍遵守 [能力明细工作簿规则](../spc/rules-spc-cpk&cpm-decoration.md) 中的能力阈值及跨度条件。汇总消费维护后的释放标志，不再用 `status`、修正后能力值或 48 小时门槛二次剔除已保存的 `flag=False` 记录；这些条件也不额外限制分母。预警数大于总项目数、重复业务键冲突、负数或无效数值均须显式失败。

产品的首条超规记录产生时才创建相应预警 Sheet。预警工作簿正常可读时，未创建的产品 Sheet 和空 Sheet 均表示零预警，项目总数仍由 SPC 计算。预警工作簿不存在或无法读取时，查询与重算均停止。

## 读取、时间与缓存边界

`SnapshotCapabilitySource` 只读取共享原始快照及已捕获的元数据，不刷新原始快照，不查询数据库，也不发布或修改决策台账。读取原始 Parquet 前核验 policy、manifest 中的文件代次和所需源时间覆盖范围；文件身份变化、覆盖缺失或元数据缺失均为失败，不能当作零项目。

快照保留源时间。按现有策略转为显示时间后，沿用当天截止和 Inline 厂别／日期排除，再进行去重、规格处理、异常点过滤及最终点位修饰。能力统计同时消费共享最终 `raw_measurements_df` 与由其生成的 Sheet 特征，不在其后重写点值；[SPC 数据流](../spc/data-flow-spc.md)及 CONTEXT 的最终点位边界继续适用。

参数目录和规格的离线捕获由 [`tools/refresh_capability_metadata.py`](../../../../tools/refresh_capability_metadata.py) 明确触发，默认输出在 `data/inline_domain/spc/capability_metadata/`。捕获先检查源表结构和低成本规模估计，在只读数据库事务内按产品、捕获时间筛选；带时间字段的源均适用时间谓词。元数据快照保存代次和文件校验信息，界面仅消费该本地输入。需要更新元数据时运行维护命令，界面读取失败不触发数据库回退。

周度分母缓存仅保存原生 DataFrame，采用项目配置的 TTL 与容量，身份包括产品、完整周标签、统计日期、测量快照代次、元数据捕获代次、配置和相关决策／异常点规则文件签名。源数据或规则变化后重新统计，不复用旧代次。汇总持久化使用独立工作簿的跨进程事务锁，规划、合并、原子替换在同一事务内完成；重复查询且数值未变化时不重写文件。

## ISO 周向上归属

ISO 周日期以 ISO 年、周号、星期构成，完整周从周一到周日，见 [Python 官方 `date.isocalendar()` 说明](https://docs.python.org/3/library/datetime.html#datetime.date.isocalendar)。周历没有与自然月一一对应的整周归属关系；本模块按业务约定采用需求指定的“向后归属”：整周归入其周日所在的自然月。例如，跨越10月和11月、周日为11月1日的一周全部归入11月；跨年同样按周日的自然年、月确定归属，不直接使用 ISO 周年的年份作为自然年。

按以下顺序加和总项目数、达标项目数和预警项目数，每层达标率均由该层合计的达标项目数／总项目数重新计算，不能平均下级达标率：

`完整周 → 周日所属月份 → 自然季度 → 自然年度`

更新已有部分月份时，用新周贡献替换该周旧贡献：`月度维护基线 - 旧周贡献 + 新周贡献`，保留本次范围外的贡献。若待替换周或月基线缺失，无法确定旧贡献，则先获取该月截至统计日全部已结束周的覆盖；只有明确具备完整覆盖时才按该月全部周记录重建月度。随后更新涉及季度和年度，其他月份、季度、年度及其他周记录保持原值。

当前尚未结束的周不进入重算。图表时间轴仍沿用当年、当前季度序列、最近三个月和包含当前周位置的最近四周；当前周位置的存在不代表已取得完整周能力统计，不能把未完成周当作已完成结果生产。

## Task0–Task2 批量维护

维护入口为 [`tools/rebuild_capability_summaries.py`](../../../../tools/rebuild_capability_summaries.py)，命令参数以该程序的 `--help` 为准。原始快照、决策台账和报警率数据不因能力历史修复而重算或覆盖。

先更新本地规格与目录，再计算候选结果；以下重建命令默认不发布正式文件：

```powershell
.venv/Scripts/python.exe tools/refresh_capability_metadata.py
.venv/Scripts/python.exe tools/rebuild_capability_summaries.py --source-workbook "resources/inline_domain/monitor/北极星报警率与CPK汇总.xlsx" --as-of 2026-11-17
```

候选输出默认位于 `output/test-results/capability-summary/`。计划通过一致性检查后，同一命令追加 `--apply` 执行带备份的拆分与写回；可用 `--prepared-weekly <目录>` 复用已核验的周度计算文件。历史冲突的处理以实际用户授权为边界，不因启用 `--apply` 而扩大修复范围。

复用目录必须包含 `rebuild-inputs.json`。校验覆盖统计日、全部产品与周组合、原始快照和政策版本、规格目录、预警台账及计算文件完整性；输入变化或缺少记录时须重新计算。正式拆分在共享工作簿事务锁内核对计划使用的基线，拒绝覆盖已存在的新目标文件，避免丢失计算期间的维护修改。无可用月度子记录的历史季度和年度保持原值；非空的非法数值不会按缺失值补零。

- **Task0**：拆分三种工作簿并注册路径；CPK/CPM 缺失总项目数补0，缺失达标项目数补总项目数，缺失预警项目数补总项目数减达标项目数，缺失达标率按计数计算。需求中“预警数缺失时为总项目数减预警项目数”是自引用表达，执行口径采用上述计数恒等式。随后由已有月度计数重建涉及季度，再由季度重建年度。

Task0 补全后，以已知总数及预警数统一校正达标数和达标率，确保计数恒等式和零总数100%规则成立；这类派生值纠正不重新计算范围外周度的总数或预警数。
- **Task1**：以执行时统计日为参照，重算最近五个已结束 ISO 周的 CPK，再更新这些周涉及的月、季、年；其他时间区间保持原值。
- **Task2**：以统计日上上个月1日至统计日为显示范围，重算范围内已结束周的 CPM，包括周日归入范围首月的跨月周。分母从共享快照取得，不受原 SPC 页面较短展示窗口限制。随后更新这些周涉及的月、季、年，范围外记录保持原值。

例如统计日为2026-11-17，CPK 的五个完整周为 W42–W46；CPM 对应2026-09-01至2026-11-17范围内已结束且归属这些月份的周。历史月份与最新统计发生冲突时须保留明确证据并按用户授权处理，不能静默截断、清零或删除矛盾值。本文不宣称任何尚未核验的真实历史数据已一致。

按现有 CPM 台账刷新预警时，项目内工具使用工作簿既有总项目数重新计算达标项目数和达标率。预警数超过既有总数时，工具报告对应产品和周期并停止写回。使用说明见 [CPM 预警数刷新 Skill](../../../../tools/refresh-cpm-warning-counts/SKILL.md)。

## 页面查询与展示

查询按产品读取上一个完整周的分母和维护预警标志，替换该周及受影响的月、季、年；必要的完整月覆盖采用前述规则。已结束周之外的历史修复由批量维护入口承担。

图表总项目数使用柱形，年度、季度、月度、周度分别着色；达标率使用右侧百分比轴和折线，各周期类型使用独立线段。不同时间粒度之间不连接折线，未知值保留空白。汇总表保留，原“CPK/CPM 最新项目明细”和厂别筛选移除。普通模式的表格、图例、hover 和错误提示只包含公开业务内容。

同一筛选 Expander 内先展示所选产品的汇总图，再依次展示每个所选产品的独立趋势图。各图复用本次查询已读取并更新的同一批历史记录，使用相同时间轴与统计口径，不逐产品追加数据读取或更新。清空产品选择时按全部启用产品展示。

产品选择变化使本模块旧结果失效，重新查询后显示；清空选择使用全部启用产品。CPK 与 CPM 的局部事件保留对方的选择及已提交结果。Plotly 普通滚轮用于页面浏览，入口显式保留 `scrollZoom=False`。
