# Yield 看板数据流、缓存与按需详情

更新：2026-11-03。适用：入库不良率分析看板及复用其生产用例的预警发布 CLI。本文拥有报表编排、输入版本、缓存和详情加载契约；具体数值规则仍由 [MWD](../mwd_trend/algorithm-mwd-trend.md)、[Sheet/Lot](../sheet_lot/algorithm-sheet-lot.md)、[Mapping](../mapping/algorithm-mapping.md) 和 [预警结果规则](rules-yield-alert-results.md) 各自维护。

## 1. 正常数据流

```text
加载启用产品配置、日期策略、资源注册路径
  → 页头刷新控制：当前产品的输入版本与展示指标版本
  → 读取 Mapping 脚本配置（按产品／手动输入版本复用）
  → 确定自然月起点、分析结束日和维护资源版本
  → 预警生产用例（一个请求作用域）
       → 小型健康缓存 → 原始 Panel 缓存／L1 仓储
       → 用原始健康元数据绑定本次输入代次
       → 修饰后 Panel（本次操作中只取回一次）
       → 修饰表两级目标／倍率上下文（一次读取和批量月度参考计算）
       → Code MWD → Group MWD
       → 警戒线、覆盖表原生解析结果 → Lot
       → 周度趋势及上周 Lot 的当期预警；分别发布结果文件
  → 统一读取已发布结果 → 显示结构化预警
  → 显示 Group 月／周／日宏观图（独立 fragment）
  → 显示自动预警缺陷图像的折叠入口
  → 显示手动 Code 筛选区（独立 fragment）
```

初次进入不请求 Sheet、Mapping 明细，也不提前构建每个命中 Code 的图。月度趋势图仍保留；禁用的只是月度趋势**预警**。Lot 当期预警固定为参考日的上一完整 ISO 周，详见预警规则。

用户展开自动区后先看到缺陷名称；再展开某个 Code，才加载完整 Sheet／Mapping 并构建该 Code 的图像。手动筛选需先查询，随后首个所选 Code 默认展开，其他 Code 按展开状态计算。点击 Lot、选择筛选项或打开详情只重跑所属 fragment，不重新生产预警。

## 2. 版本与缓存身份

### 2.1 分开管理输入与展示

`yield_report_source` 是当前产品的共享输入 revision；趋势、Lot、Sheet 的展示指标 revision 继续独立存在。

| 层次 | 缓存／版本包含什么 | 失效方式 |
|---|---|---|
| 原始 Panel | 查询 DTO（产品、时间）、数据策略 DTO、共享输入 revision 与日期策略 | 既有 TTL、产品报表刷新；L1 继续按自己的覆盖、TTL、完整刷新／增量与失败回退规则工作 |
| 来源健康 | 与原始 Panel 相同的根身份，只返回健康小字典 | 既有 TTL、输入 revision；并发代次不一致时仅清当前查询的健康项 |
| 本次输入代次 | 共享输入根身份＋实际健康元数据（来源刷新时间、覆盖、状态） | 来源健康换代后变化，不把展示指标刷新当作源数据更新 |
| 修饰后 Panel、Code／Group、Lot／Sheet／Mapping | 输入代次、配置、窗口、维护资源 revision、相关策略、`read_only` 等完整实参 | 数据换代、手动刷新、配置／产品／日期变化或 TTL |
| 覆盖表 | 产品、配置完整文件路径／Sheet、手动资源 revision、本次输入代次 | 相关输入代次／资源版本或 TTL |
| 原生绘图投影 | 实际数据签名、产品、Code／Group、Mapping 布局和脚本 | 任一相关输入改变或 TTL |
| 会话图像材料 | 实际 MWD／Lot 数据摘要、输入代次、规格、选中 Lot、布局／脚本 | 数据变化或 TTL；最多 16 个条目 |

页头“刷新缓存”和成功的“刷新数据”都会推进当前产品的共享输入 revision 及三个展示 revision；刷新数据失败不推进。其他产品不失效。矩阵仅刷新某项已发布结果的展示 revision 时，不伪造原始 Panel 更新。

维护资源仍遵循显式刷新及既有 TTL：编辑文件本身不绕过页面的手动资源版本。路径和 Sheet 仍由全局资源注册表／产品配置装配，不能从配置父目录猜固定文件名。只读和可写修饰上下文是不同缓存项，不能用只读预热替代应发生的写回。

### 2.2 一次操作内复用，跨操作仍复制

`application/report_cache.py` 使用请求局部的 ContextVar 字典。预警生产或一次详情加载结束后，在 finally 中清除本次字典。它只避免同一次操作内反复从 `st.cache_data` 反序列化同一份中间结果；没有用 `cache_resource` 全局共享可变 DataFrame。

调用先规范化全部默认参数。因此省略 `read_only=False` 和显式传 `False`、位置传参与关键字传参会命中相同缓存，Sheet 可复用原 Lot 结果。失败不写入请求 memo；显式 `_data_port` 仍绕过默认生产缓存与 memo，保持测试／独立适配器隔离。并发请求拥有各自的原生对象。

### 2.3 防止新旧数据混用

输入代次在派生缓存中保留，但原始读取／健康缓存只取其共享根身份，避免为绑定健康信息再次读取整份 Panel。返回原始 DataFrame 时核对真实健康元数据，若与调用方捕获的代次不同，抛出专用换代信号，禁止把新数据存入旧代次派生缓存。

详情加载先检查捕获的来源健康与分析参考日。数据换代或跨日时，清理当前查询的小型健康缓存，交给页面／fragment 发起整页重跑，重新生成一致的视图。该信号不被转换成普通详情空表、失败缓存或持久发布失败。图像签名还摘要实际完整 MWD／Lot 输出，避免手动 revision 未变时复用旧图。

## 3. Excel 与月份准备

- 覆盖表在 Lot 和 Sheet 之间共享一次校验后的原生解析结果。普通 XLSX 使用 openpyxl 路径；缺少产品 Sheet 是合法的无覆盖；缺少必要字段、打不开或计算失败向上报错，不能当作无覆盖成功。
- 普通、数组或数据表公式通过单元格 `data_type='f'` 识别；有公式时交给 Excel 计算，不把缺少公式缓存值的单元格直接转成 NaN 后丢弃。
- 企业保护文件保留只读 COM 回退。创建独立实例，在打开前禁用宏和外部链接更新，结束／失败时 Close、Quit、释放 COM 初始化；不连接用户原有 Excel 实例。
- 修饰表普通文件一次打开，读取本产品 Group／Code 两个 Sheet；受保护文件一次整本读取后投影两级 Sheet。
- 修饰表的各月原始良损使用一次日期解析、一次月度投入分母分组及两级分子分组。每月仍按唯一 Panel 计数，缺失不良按完整窗口＋台账清单补零；整月没有投入不凭空补参考值。当前月可更新，历史月只补缺行，已有人工指定值保持。
- Code MWD 的月份键只格式化唯一日期并映射回每行，月度分母和缺陷分子复用同一键。重复缺陷记录、合成 Panel ID、空月与索引顺序仍按既有规则处理；日度生成、扰动、整数分配和最终聚合公式没有改变。

## 4. Array 时间开关

唯一开关为 `config/domain/yield_domain.yaml → array_input_time.query_enabled`，当前是 **false**。ConfigLoader 将校验后的布尔值装配进运行配置。

- `_get_array_times` 在访问数据端口前返回含列名的空表；不会查询 Array 历史视图，也不执行自定义 Array 时间替代逻辑。
- Lot／Sheet 仍正常计算，阵列投入时间保持空值，不用入库时间等其他日期伪造。
- UI 不提供阵列投入时间排序，过时的排序控件状态会清理；Sheet 默认按 Sheet ID 排序。
- 原 SQL、端口、仓储、自定义时间及排序分支均保留。未来显式设置 true 并通过页头刷新配置后，可恢复原有查询和排序；启用前应按性能报告 P2-A 对底层视图规模与执行计划做受控检查。

## 5. 详情与绘图投影

`load_report_details` 只在用户请求后调用，按完整窗口计算 Sheet 和 Mapping。不得先按所选 Code／Lot 裁剪原始输入再执行随机分配或 Mapping 级联，避免随机数消费顺序、批次集合和理论天花板改变。

Sheet 和 Mapping 各自捕获普通读取失败并给出安全提示；一种失败不阻断另一种，也不撤回已显示的宏观结果与已发布预警。失败的图像材料不进入会话 memo，可再次重试。正常空数据保持普通无数据语义。

Lot 明细仅拼接、清洗一次，再按 Code 建立原生索引，自动与手动图像共享它。保留原先按缺陷名称筛选的语义和排序，不在此次优化中改变同名 Code 的分组口径。Mapping 按输入版本、产品、Group／Code、批次、布局和脚本缓存矩阵；Plotly Figure 在展示侧生成，不进入 `st.cache_data`。

候选筛选只需趋势／Lot：当前月均门槛要求 Code 具有月度趋势，Mapping 独有且没有月度趋势的 Code 本来就不能通过门槛，因此无需为了准备下拉列表先计算 Mapping。门槛仍由两处共同配置，月度数值图和月均筛选未被周度预警规则移除。

普通模式的提示、图表、hover、列菜单与导出仍遵循项目展示边界；请求版本、内部标记、维护路径和原始技术异常不进入展示载荷。
