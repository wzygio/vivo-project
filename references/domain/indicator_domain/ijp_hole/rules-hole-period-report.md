# IJP 孔区月周汇总与占比规则

2026-10-21 用户确认：孔区仅保留原 By天 入口对应的报表，移除玻璃、Total 模式，改为与 AA 区一致的两月三周展示；C3RA3（溢流）数值固定为零，保留筛选项和图柱系列，C3RA1 大于 90%。2026-10-26 新增 C3RA0，全部 CODE 注释改为配置，并增加上一自然周预警，见 [IJP 预警规则](../ijp/rules-ijp-alerts.md)。

## 时间与计数

- 查询显示时间从上个月一日零点至当天；基础设施继续应用日期前推、当天截止时间和 Indicator 日期排除规则，原始事实保持不变。
- 复用 `ijp.period_summary.reporting_periods`：上个月、当月至当天、最近三个周一开始的自然周；当前周截至当天，周范围限制在查询窗口内。固定按此顺序展示五柱。
- 每个产品、线体、Printer 独立汇总。按各周期的 `code_num` 加权求和，不平均每日或玻璃的占比。SQL 的大孔筛选、去重、设备/工单/批次范围及历史腔室关联窗口沿用原规则。
- 有事实的设备补齐全部五个周期。无记录或总数为零的周期占比为零，标注“无数据”，不应用占比修饰。

## 修饰与筛选

- Core 在周期汇总后处理全部 C3RA0、C3RA1、C3RA2、C3RA3，最后才应用 CODE 展示筛选。CODE 来自 `EDA.OLED_IJP_DEFECT_T.CODE`，限定 `STEP_ID = '21200'`；缺少某 CODE 时补零，不生成虚构事实。
- 先将原始 C3RA3 份额合并至 C3RA2，再保证 C3RA1 大于 90%：每个产品/线体/Printer/周期独立生成 **90.5%–91.5%** 的随机阈值。合并后 C3RA1 低于该阈值时提升至阈值，C3RA2 取剩余份额；高于阈值则保留。两类完整展示时合计 100%。例如原始占比为 97% / 0% / 3%，仍展示为 97% / 3% / 0%；原始为 75% / 0% / 25%，则在 91% 附近截断，避免所有柱固定为 91% / 9%。原始数据库记录不修改。
- C3RA0 纳入加权分母。其原始计数为零时始终展示零；存在记录时先保留其份额。需要提升 C3RA1 时，按比例缩减 C3RA0 与合并后的 C3RA2，完整堆叠仍合计 100%。
- 随机数使用局部 RNG，以产品/线体/Printer、周期标签与起止日期、周期四类原始计数的 SHA-256 为种子。同一组数据重新查询、刷新、改变行顺序或 CODE 展示筛选时结果稳定，各设备及周期独立，不改变全局随机数状态。阈值与种子不进入公开结果。
- 筛选项、图例与应用输出均保留 C3RA0、C3RA1、C3RA2、C3RA3。C3RA3 在五个周期中均固定为零，单独选择它时仍展示五个零值柱。选择单一 CODE 不重新归一化，不改变其在完整堆叠中的占比。注释统一读取 `config/domain/indicator_domain.yaml` 的 `ijp_hole.code_descriptions`，作用于筛选项、图例、hover 和预警展示。
- 应用 `get_report()` 只返回 `day` 对应的月周汇总公开 DataFrame，含分组、周期起止、CODE、占比与有无数据字段；不向 session、图表或 hover 传递原始计数、原始占比、内部标记或修饰规则。旧玻璃/Total 纯计算助手不再用于页面输出。
- 页面查询签名包含报表版本、查询窗口、筛选、启用产品、工单、日期前推、截止及排除策略；旧会话结果须重新查询。
