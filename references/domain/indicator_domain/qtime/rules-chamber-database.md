# 蒸镀腔室 Q-Time 数据库规则

## 来源和范围

生产组合根使用 `DatabaseChamberQTimeRepository`。腔室事件与LL1来自
`mdw.dwt_inout_sub_unit_gls`，LL1 IN的`prod_id`精确关联
`mdw.dwr_mes_productspec.productspecname`得到`productcode`，不依赖SPC抽样覆盖。
仅OLED、P/E和3CEE01/3CEE02；显示名称仍为3CEE001/3CEE002。
严格限制已启用型号，规格名多版本同型号去重，未知/多型号glass隔离；不猜测产品。
所有月份均使用数据库来源，不按月份切换数据源。2026-10-21已删除旧Excel适配器、
对应资源路径配置及两份九月工作簿；测试统一使用数据库区间格式。

## 区间口径

按设备、glass和LL1进片时间划分过货批次，事件按完整event_timekey顺序配对。
相关腔室中OUT行与下一事件的时间差为秒，下一UNIT_ID须非空；不是同腔IN/OUT加工时间。
精确重复事件去重，复过货及同次过货内重复转移保留。仅存在真实配对时生成区间；
缺少下一腔不填零。非法/负数测量按缺失；不改写源事实。
11条路径为Core `CHAMBERS`（PT→OC1至OC9→OC10），不包含LL1→UL1和末尾两条扩展路径。

## 日期、安全和缓存

日期按进片显示时间选择，首尾日包含；默认当月、最多31日且不晚于服务器当天。
反算源窗口后按date_timekey前后各补1日扫描，供跨午夜补齐；跨出补齐窗口的长流程不保证
完整，不推造缺失配对。输出应用前推、当天全局截止和Indicator日期排除，然后进入Core。
只读查询、60秒语句超时、500,000条结果上限；超上限拒绝整个结果，不静默截断。
参数化查询；技术原因只写服务端日志，页面使用安全业务错误，读取失败不切换数据源。

日期变化清理已提交结果、重新查询。缓存以日期、来源、启用范围、前推/截止/排除策略和
规格区分；产品/线体/腔室多选在已查询的日期窗口内即时过滤，空选取全部启用范围。
配置规格控制超限线及纵轴，严格大于才超限；展示继续排除大于1000秒的点。
保留SVG点位和独立fragment，页头刷新同时清理两个模块。

## 按天点位修饰

配置位于 `config/domain/indicator_domain.yaml` 的 `qtime.chamber_point_decoration`。
`enabled` 控制开关，`start_date` 默认2026-10-12，`end_date` 默认 `today`（本次报表当天），
首尾日期均包含，可改为固定ISO日期。`threshold_seconds` 默认300秒，作为检测阈值。
`mode` 当前为 `remove`；原随机算法仍保留，配置为 `random` 可恢复。
`minimum_seconds` 与 `random_seed` 仅用于随机模式，随机下限必须非负且严格小于上限。
`point_count_threshold` 默认50。日期使用前推后的进片显示日期。

默认按“每天＋线体＋腔室”统计所有启用产品的有效点位；`group_by: [line, chamber]`
可加入 `prod_code` 分产品统计，空列表表示每天汇总整个模块。每个过货区间计一个点，
不按GlassID去重。只有严格大于300秒的点数严格大于50时，才处理该组所有超300秒的点。
`remove` 从报表结果中移除这些点；`random` 将其替换为
`[minimum_seconds, threshold_seconds)` 内的稳定随机值。两种模式互斥，移除模式不调用随机算法。
等于300秒、未达到数量门槛的组、范围外日期和缺失值不变；检测阈值及数量仍由配置控制。

Application先接收Infrastructure已经应用前推、截止和日期排除的事实，再由Core完成
产品归属/启用范围过滤和修饰。统计先于页面产品/线体/腔室筛选及1000秒展示过滤，
因此筛选不会改变触发条件，源值大于1000秒的有效点也参与统计。
处理不写回数据库或源数据；移除模式保留其余点位值和状态，随机模式按当前规格重新判定状态。
页面只接收处理后的业务结果，全部移除时显示现有业务空态。
纵轴和规格线继续使用 `chamber_target_seconds`，与修饰阈值独立。

`random_seed` 默认0，结合点位身份生成稳定随机值；刷新、排序和页面筛选不使数值跳变，
重复的相同点位身份获得相同数值，不改变全局随机生成器；此算法在移除模式下不生效。
完整配置（含模式）进入服务缓存签名；
日期进入现有缓存键，`today` 随当天推进，配置变化清理旧提交结果并要求重新查询。
