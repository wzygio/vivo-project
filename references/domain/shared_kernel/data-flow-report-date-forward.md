# 报表日期前推数据链路

核验日期：2026-09-10。本文说明制造事实从源数据到报表的日期流转，适用于 Yield、Inline、Q-Time、IJP 和 Equipment。

## 统一日期口径

报表需要预留数据修饰时间，因此同一笔制造事实具有两种日期：源日期记录实际发生时间，显示日期决定它出现在报表的哪一天。

统一策略由 [global.yaml](../../../config/global.yaml) 的 `data_forward` 配置控制：

- `enabled: true`：显示日期 = 源日期 + `offset_days` 天。
- `enabled: false`：显示日期与源日期相同。

各生产报表共用该策略，不按产品或模块分别设置偏移天数。核验时配置为 **3 天**；例如源日期 9 月 7 日对应报表日期 9 月 10 日。该数值可配置，文件中的“四天”注释和早期设计记录不代表当前生效值。

## 从源数据到报表

```mermaid
flowchart LR
    A[制造源数据<br/>保留真实发生日期] --> B{取数路径}
    B --> C[直接查询源数据]
    B --> D[保存或读取原始快照<br/>仍为源日期]
    C --> E[交付报表数据前<br/>统一转换为显示日期]
    D --> E
    E --> F[按显示日期筛选与归属周期]
    F --> G[业务统计与报表处理]
    G --> H[页面、趋势和导出]
```

日期转换发生在源数据交付给报表处理的边界。后续业务模块消费已转换的数据，不再各自加一次天数；原始数据和快照始终保留源日期，重复读取不会累加偏移。

### 直接查询：先找对源日期，再转换结果

用户选择的是报表显示窗口，取数前需要反向减去偏移天数。

以偏移 3 天为例：用户查询报表 9 月 10 日的数据 → 查询源系统 9 月 7 日的数据 → 将返回记录的显示日期转换为 9 月 10 日 → 进入当日报表。多日窗口的起止时间同样反向换算，原有边界是否包含的口径保持不变。

这保证报表取得的是目标显示日期对应的事实，而非只给另一批数据换日期标签。

### 原始快照：保留源日期，读取后转换

快照链路先保存一段较宽的源数据，再从中形成报表。快照加载起点采用截止日第三个前序自然月的月初，这一口径独立于日期前推开关。

读取快照后，制造事实日期统一转换为显示日期，再按报表窗口筛选。刷新或数据库失败后读取旧快照，都沿用这一日期口径；旧数据原有的新鲜度或不可用状态不会因日期平移而变成正常。

## 各模块的衔接

### 最新一天的统一截止时间

`config/global.yaml` 的 `report_cutoff.latest_day_time` 定义最新报表日的截止时刻，
默认 `"12:00:00"`，包含该时刻。最新报表日由服务器本地当天确定，不取前端筛选
结束日或数据中最大的日期。启用前推四天时，显示今天对应源日期四天前的中午；
关闭前推及不参与前推的 Equipment、IQC 使用真实今天中午。历史日期保留完整一天。

统一规则由 `shared_kernel/report_cutoff.py` 提供，仓储在日期平移后截断输出。
原始 Parquet 与增量覆盖元数据继续保存完整源窗口，包含下午记录；次日这些记录
成为历史后可以重新进入报表。截止时刻与服务器当天参与派生缓存签名，配置改变
或跨日会使旧派生结果失效。IJP 和 AOI_TT Particle Size 在 SQL 中先聚合，因此
仓储先限制查询结束时间，再执行汇总，避免下午记录混入上午计数。

Yield 保留 `first_ship_date` 作为业务归属日期，并额外读取 20 位
`first_ship_time` 作为精确入库时刻；两者可能跨日，不相互替代。只有最新业务日
按精确时刻截断，历史业务日保持原口径。精确时刻仅保存在原始快照，不新增到
报表输出列。缺少该字段的旧快照下次读取会重建完整请求窗口；重建失败沿用旧
快照降级状态，但无法判断时刻的最新日记录不会进入报表。

Q-Time 原有输出时间键保持秒级，原始快照额外保留源事件微秒用于截止判断；
已有秒级快照按其已有精度判断，增量回读后补齐源精度。Equipment 原始快照保存
每个测量键的最新状态；若最新状态发生在截止后，输出会剔除该条，不能从已经
压缩的快照重建同一测量键中午之前的旧状态。IQC 中只有日期而没有时分秒的
示例批次字段仍按日期解析，无法据其推断日内发生时间。

| 模块 | 数据进入报表的链路 | 参与转换的日期 |
|---|---|---|
| Yield | 入库明细及投入时间 → 统一日期转换 → 良率趋势、Lot/Sheet 等分析 | 入库时间、Array 投入时间 |
| SPC | 共享测量数据 → 统一日期转换 → 测量制备 → SPC 报表 | 测量开始时间；关联主制程履历的事件时间采用同一显示口径 |
| CTQ | 复用 SPC 测量链路 → CTQ 报表 | 继承已转换的测量时间 |
| AOI_TT | 共享测量数据 → 统一日期转换 → TT 统计；Particle Size 独立查询同样先反算窗口、再转换结果 | 测量开始时间、Particle Size 对应时间 |
| AOI_RS | RS 原始快照 → 统一日期转换 → 查询窗口筛选 → RS 统计 | 检测开始时间 |
| Inline Monitor | 复用 SPC 测量链路；报废数据读取后另行统一转换 → 预警处理 | 测量时间、报废时间 |
| Q-Time | 显示窗口对应的源明细或源快照 → 统一日期转换与筛选 → 过货监控 | 过货时间键；等待时长保持原值 |
| IJP | 显示窗口反算 → 查询源明细或日汇总 → 日期转换 → 溢流报表 | 打印时间、日汇总日期 |
| Equipment | 源数据新鲜度与未来时间校验 → 备件当前状态报表 | 不参与全局前推；测量时间与最后更新显示到天 |
| IQC 示例 | 示例文件 → 日期解析与筛选 → 示例报表 | **未接入日期前推**，保留示例原日期 |

Equipment 展示当前状态，真实及仿造快照均使用自身时间，不参与全局日期前推。仿造快照按当前时钟维护，再前推会产生未来日期。内部保留时间精度以支持最新记录匹配与更新，页面测量时间和最后更新仅展示 `YYYY-MM-DD`。

## 切换策略时的数据边界

改变开关或偏移天数后，报表派生结果需要按新口径重新取得或计算，不能沿用旧策略的报表缓存；底层原始快照继续复用。关闭前推即可让同一批源事实按真实日期进入报表。

该策略只转换约定的制造事实日期。日志时间、缓存有效期、文件时间、人工修饰审计时间，以及等待时长、寿命等持续时长不参与平移。

设计决策及实现约束见 [源时间与显示时间边界 ADR](../../../docs/ADR/0022-source-and-display-time-boundary.md)。
