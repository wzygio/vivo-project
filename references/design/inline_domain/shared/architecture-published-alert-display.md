# 已发布结果驱动的独立预警展示

核验日期：2026-10-27。本文维护报表与自动预警矩阵共用的展示设计；各指标的业务阈值、周期、数据来源仍由各域规则拥有。矩阵行清单见 [看板架构](../../../domain/inline_domain/monitor/architecture-alert-dashboard.md)，决策见 [ADR-0036](../../../../docs/ADR/0036-shared-published-alert-display.md)。

## 1. 生产与消费边界

生产流程保持各域原有入口：前置处理、异常识别、人工决策、结果发布。发布成功后，正式 Excel 是预警展示的输入。报表和矩阵都调用 `app/sections/shared/alert_results.py::read_alert_result()`，不以计算函数刚返回的内存明细代替已保存结果。

```text
各域原有分析 → 发布结果 Excel
                    ↓
             文件版本与有效性检查
                    ↓
             共同预警选择与缓存
              ↙             ↘
        监控报表预警        矩阵状态／详情
```

复用只覆盖“预警显示”管路：读取已发布结果、字段规范化、周期／产品筛选、参数豁免和公开投影。不会为了显示矩阵状态运行报表生产、SQL、点位修饰或能力重算；缺文件或读缓存 miss 都不能成为运行生产流程的理由。

原报表可以继续正常计算和发布。即使初始化、计算或后续报表数据为空，页面仍调用独立预警展示。已保存预警来自最后成功发布结果，不能声称读取 Excel 就完成了本次源数据更新。生产失败时保留明确提示；旧结果仍须满足其各域原有有效性约定。

## 2. 共同接口与原生载荷

`read_alert_result(row_key, product, reference_date, **selection)` 返回原生 dict：

| 字段 | 契约 |
|---|---|
| `state` | `alert`／`ok`／`no_data`／`error`；读取失败不能变成成功零预警。 |
| `records` | 筛选后的原生记录，供公开投影和指标键选择；不直接把内部字段传入前端。 |
| `alerts` | 展示列白名单；Inline 单片及能力为既有中文业务表，其他域保持自己的公开字段。 |
| `alert_factories` | 从命中的记录归约，用于矩阵厂别筛选。 |
| `message`、`metadata` | 安全的业务状态及各域发布范围信息。技术异常只进入日志。 |
| `evaluation` | 仅 AOI 趋势使用：完整已发布评估，包含未触发、不可评估等状态；不能仅存报警行替代。 |

`product=""` 对支持的报表汇总启用产品，复用逐产品结果缓存，公开记录去重。备件为全厂共用，不虚构产品归属。相同业务范围使用相同参数；不同范围不得声称计数必然一致。

`alert_result_signature()` 汇总实际文件版本、规则配置、参考日、范围以及即时有效性。矩阵的单元格和详情签名也使用它。域特定读取和验证保持原有边界，不将不同工作簿强制改造成一套元数据格式。

## 3. 缓存与一致性

共同 `_cached_alert_result` 使用 `st.cache_data`，只存 DataFrame、dict、标量等原生载荷。键包含指标、产品、参考日、实际文件／政策签名、该指标产品 revision 和显式范围；上限512项，TTL来自全局配置。

工作簿解析缓存按绝对路径、`mtime_ns`、大小复用：Inline 四类 OOS 和 CPK／CPM 使用 `read_cached_alarm_workbook`；IJP／备件／IQC共用中立位置的快照读取器；Q-Time和Yield复用各自文件适配器。解析缓存负责文件复用，共同结果缓存负责预警选择复用。

同一 Streamlit 进程中，报表与矩阵使用同一个缓存函数和缓存条目。`st.cache_data` 返回副本，调用方修改表格不会污染另一页面；这不是承诺共享可变 DataFrame 对象身份。独立定时进程与 Web 服务只能通过文件共享结果，不能共享进程内存。

时间有效性在结果缓存外检查：即使文件没改写，正式快照过期也会改变签名。PPA排除、日期排除和能力跨度配置也进入对应签名，不靠用户全局清缓存使规则生效。

## 4. 各域适配

| 范围 | 发布与读取规则 |
|---|---|
| SPC／CTQ／AOI 单片 | 消费现有产品 OOS sheet，`__flags`仍由人工维护；SPC 使用独立PPA预警排除。存在的有效空产品表为零预警，缺产品表为 `no_data`，读取损坏为 `error`。 |
| SPC CPK／CPM | 继续读取各自产品能力 sheet，共用能力算法和工作簿解析；不因某一指标失败阻止另一指标与单片预警。 |
| AOI_RS／AOI_TT 趋势 | 新的各产品评估表＋`__meta__`，保存完整既有 detector 输出；参考日、算法／日期排除策略、条数和TTL验证通过后展示。不是新增趋势算法，也不新增矩阵行。 |
| Yield | 继续使用既有发布结果应用服务；矩阵Lot取上周，报表显式传 `time_period=30`，锚点来自发布的最近Lot日期；趋势仍遵守`is_current`的period口径，内部标记不进入展示表。 |
| Q-Time | 各厂别正常生产后发布完整告警与最小Lot归属投影；矩阵取全部厂别上周，报表显式传厂别、站点及滚动窗口。所需厂别缺发布、陈旧或覆盖不足时不可用，不查询补齐。 |
| IJP／备件／IQC | 保留原成功状态、日期、TTL、条数、产品成员及初始化空模板语义。仅表头模板仍为`no_data`，损坏、过期正式发布仍为`error`。 |

新增资源注册在 `config/global.yaml`：`resources.inline_domain.files.aoi_rs_trend_alerts`、`aoi_tt_trend_alerts`，以及 `resources.indicator_domain.files.qtime_alerts`。默认位于对应业务资源目录；读取和发布都通过注册解析，不改变原始Parquet、人工决策或规格工作簿。

Inline OOS 原有刷新门控新增结果内容签名：分析输出或有效flag变化时，即使产品revision和决策签名未变，也发布实际变化结果；相同内容保留TTL门控。避免页面读取刚算出的内存结果，而矩阵仍读取门控前的旧Excel。

旧工作簿尚无内容签名时，保留原revision／决策／TTL门控，在下一次正常发布时补齐签名；不会仅为补充元数据而强制重写企业保护文件。两个展示入口在过渡期仍共同读取最后已发布版本。

Q-Time新结果文件独立于厂别原始L1和`qtime_oos_decoration`决策表。`alerts_<shop>`是公开告警，`products_<shop>`仅保存产品／站点／Lot／时间用于范围和分母校验，`__meta__`逐厂别记录覆盖、源健康、策略、发布时间和条数。不会将修饰结果写回L1，也不改变原厂别刷新流程。

## 5. 图像与失败隔离

预警表与状态必须在可选图像失败后仍可见。原报表已有数据时，按共同预警键筛图；没有可用图像输入时保留表格和安全提示。矩阵详情先取共同保存结果，图像使用原有独立 loader，并在异常时降级为空图输入。Q-Time已保存详情无需数据库，用户点击“加载预警站点图像”后才进入原报表图像流程。

SPC的CPK、CPM、单片以及AOI的单片、趋势分别隔离：一个绘图分支抛错不能阻止后续预警读取。正常模式不公开flag、人工决策、源值对比、配置路径或异常堆栈。

## 6. 验证与运行限制

验证使用临时工作簿、禁止SQL的替身、内存计数器及Streamlit AppTest，覆盖同版本只解析一次／同参数只选择一次、策略与文件失效、PPA与周边界、有效空／缺失／损坏／陈旧、报表失败后仍读预警、图像失败后仍读下一项，以及公开字段白名单。

读取器不创建或补齐维护数据。首次没有AOI趋势或Q-Time正式结果时，需对应正常生产流程成功发布；Q-Time全厂矩阵要求三个厂别都已有有效正式结果。用户明确要求预建时，Q-Time可用专门初始化方法创建仅表头的完整空模板，返回`no_data`，不捏造已完成生产或成功时间；开始正式发布后恢复完整厂别覆盖检查。仅部署读取器或运行矩阵预计算不能替代真实发布。
