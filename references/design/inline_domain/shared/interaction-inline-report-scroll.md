# Inline 报表滚动与图表交互设计

## 1. 背景与范围

2026-09-09 的 SPC 报表出现数据已加载、鼠标位于图表区域时无法继续向下滚动的现象。检查时主内容容器允许滚动，内容高度大于视口高度；当时图表渲染入口未覆盖 Streamlit 默认启用的 Plotly 滚轮缩放，存在图表缩放与页面滚动争用滚轮的问题。

同样的配置缺口也存在于 CTQ、AOI_TT、AOI_RS 报表。本设计覆盖这四个报表的普通指标图和复用相同渲染入口的预警指标图，不扩展到其他业务页面。

2026-11-03 补充：SPC 再次反馈查询后网页滚轴无法移动，单参数也会出现。此次代码和运行时图表均已设置 `scrollZoom=False`，独立浏览器会话中精确发送滚轮后可正常滚动，尚未稳定复现用户原标签页的间歇状态。因此本次不重复修改图表配置，而对 SPC 增加限定范围的页面布局修复：由浏览器文档承担纵向滚动，减少对 Streamlit 内部 `stMain` 滚动状态的依赖。其他三页继续保留原滚动布局。

两次问题应分别记录，不能把现象相似直接视为同一原因：

| 项目 | 原滚轮缩放冲突 | 本次网页滚轴故障 |
|---|---|---|
| 现象 | 鼠标位于图表时无法继续向下浏览 | 点击查询后图像可渲染，但网页纵向滚轴无法移动；仅一个参数也会出现 |
| 已核实状态 | 当时图表未显式关闭滚轮缩放 | 本次图表配置和运行时均为 `scrollZoom=False` |
| 处理 | 在 Plotly 渲染入口关闭滚轮缩放 | SPC 页使用浏览器文档自然滚动，释放内部主容器的高度和 overflow 约束 |
| 适用范围 | SPC、CTQ、AOI_TT、AOI_RS 的指定图表入口 | 仅含 SPC 厂别筛选控件的页面，包含普通报表与预警内容 |
| 证据边界 | 旧图表配置缺口已确认 | 原标签页间歇触发条件尚未稳定复现；本次已验证新布局和模拟内部滚动锁定下的防护效果 |

## 2. 交互原则

**长报表中的普通滚轮操作优先用于页面纵向滚动。** 鼠标位于图表绘图区时，也应能够继续浏览后续指标。

- 关闭图表滚轮缩放，避免滚轮在图表区域被用于修改坐标范围。
- 保留图表工具栏的放大、缩小、重置坐标与平移，以及原有拖拽交互。
- 保留原有图表尺寸、三列布局、折叠面板和图表标识。
- 不通过隐藏滚动条、固定页面高度、禁用全部鼠标事件或将图表静态化处理该冲突。
- 普通报表与预警图使用同一滚轮策略。

这项策略针对 Plotly 图表。表格自身的滚动、浏览器缩放及未来的独立全屏分析工具，应按各自交互需求单独处理。

## 3. 实现归属

滚轮行为属于前端展示层，由 `app/sections/inline_domain/` 在调用 `st.plotly_chart` 时显式传入：

```python
st.plotly_chart(
    figure,
    width="stretch",
    config={"scrollZoom": False},
)
```

已有 `key` 等参数继续保留。配置应放在渲染入口，而不是 Plotly Figure 的业务布局、后端 application/core/infrastructure 或数据缓存中。当前配置只有一项，直接在各渲染入口声明，不额外增加包装层。

| 报表 | 图表范围 | 渲染入口 |
|---|---|---|
| SPC | 月周日分布、主站点设备/腔室分布、过货时间分布 | [spc_dashboard.py](../../../../app/sections/inline_domain/spc/spc_dashboard.py) 的 `_render_indicator_payload` |
| CTQ | 月周日分布、主站点设备/腔室分布、过货时间分布 | [ctq_dashboard.py](../../../../app/sections/inline_domain/ctq/ctq_dashboard.py) 的 `_render_ctq_indicator_payload` |
| AOI_TT | 月周日趋势、By Lot、By Sheet；覆盖不同 Particle Size | [aoi_tt_dashboard.py](../../../../app/sections/inline_domain/aoi_tt/aoi_tt_dashboard.py) 的三类图表调用 |
| AOI_RS | 月周日趋势、By Lot、By Sheet | [aoi_rs_dashboard.py](../../../../app/sections/inline_domain/aoi_rs/aoi_rs_dashboard.py) 的三类图表调用 |

页面文件负责调用这些区块。图表配置不改变查询、异常点过滤、规格、统计或修饰结果。

### SPC 的浏览器原生滚动布局

[scroll_layout.py](../../../../app/sections/inline_domain/spc/scroll_layout.py) 通过 `st.html` 注入仅含 CSS 的布局规则，由 [SPC 页面](../../../../app/pages/SPC监控报表.py) 在初始化时调用：

- 选择器以 `.st-key-spc_factory_filter` 为页面范围标记，只有实际存在 SPC 厂别筛选控件时生效；导航到其他页面后自动失去匹配，不留全局滚轮监听器或页面状态补丁。
- 文档 `html/body` 恢复自然高度和纵向滚动；`stApp`、`stAppViewContainer` 改为相对定位和自然高度，释放原来只允许内部主容器滚动的布局约束。
- `stMain` 按报表内容自然增高，不再独立滚动；浏览器文档提供唯一的报表纵向滚动条。侧边栏保留视口高度和独立导航能力。
- 不固定报表高度，不隐藏文档滚动条，不新增嵌套结果滚动框，也不通过脚本接管或取消滚轮事件。
- 图表继续显式使用 `scrollZoom=False`，工具栏、拖拽、三列布局、指标折叠面板和稳定图表 key 保持既有职责。

这是一项面向间歇性滚轴故障的布局防护；不能把独立测试会话或模拟的内部滚动锁定，描述为已经稳定复现原用户会话的浏览器根因。

## 4. 后续维护约束

新增或迁移上述报表的 Plotly 图表时，应显式保留 `scrollZoom=False`。新增其他 Plotly 配置项时合并到同一个 `config`，避免覆盖滚轮策略。

SPC 页面应同时保留原生文档滚动布局的初始化调用。若筛选控件 key 改名，必须同步更新布局范围选择器并执行浏览器滚轴验收；不得将范围扩大到门户首页或其他报表。

更新或部署布局代码后，原浏览器标签页应重新加载，必要时使用 `Ctrl+F5`，再点击查询验收。业务数据缓存的刷新或命中，不能替代对当前标签页滚轮、原生滚动条拖拽和图表工具栏的实际检查。

若仍有“无法滚动”，应分别检查：主滚动容器的实际高度和 overflow、图表的滚轮处理、覆盖层拦截事件，以及浏览器是否因大量绘图无响应。不能仅凭外层 `.stApp` 的 `overflow: hidden` 判断页面被锁定；Streamlit 可由内部主容器承担滚动。

## 5. 验证方式与边界

自动化回归检查实际渲染调用，确认各类图表均收到 `scrollZoom=False`，并保留已有布局与数据传递断言。测试位置为 `tests/unit/app/sections/` 下的 `spc`、`ctq`、`aoi_tt`、`aoi_rs` 对应测试。

浏览器验收应覆盖：

1. 加载多个指标，确保内容高度超过视口。
2. 将鼠标分别放在趋势、Lot/设备、Sheet/时间图的绘图区，向下滚动，确认页面位置变化且坐标范围不因滚轮改变。
3. 滚动到最后一个指标，再向上返回；展开预警图后重复检查。
4. 验证工具栏缩放、坐标重置与平移仍可使用。

单元测试可确认配置和调用覆盖，不能替代真实浏览器滚动验收。2026-09-09 的 SPC 检查已读取主容器尺寸；修复后的现场滚动验收因浏览器调试连接中断尚未完成。其余三页本次通过代码核对与渲染回归测试验证，不将其描述为已完成现场滚动验收。

### 2026-11-03 布局修复验证

无数据库测试页使用实际 SPC 级联筛选和 `_render_indicator_payload`，覆盖：单参数三张图、多参数 33 张图、普通及管理员展示、重复查询、空数据、加载失败，以及导航到无 SPC 筛选控件的页面。验证真实 Chrome 滚轮在空白区及三类图表区改变文档位置、右侧原生滚动条可拖动、能够向上返回，且滚轮不改变图表坐标范围，工具栏放大、重置和平移仍可用。

本次验证结果：

- SPC 页面入口、缓存入口及图表渲染的 52 项测试通过，执行文件为 `tests/unit/app/pages/test_spc_page_alerts.py`、`tests/unit/app/pages/test_spc_page_header_cache_discovery.py` 和 `tests/unit/app/sections/spc/test_spc_dashboard.py`。
- 浏览器记录共 7 个场景：旧布局模拟锁定、新布局模拟锁定、普通单参数、管理员多参数、空数据、失败提示和非 SPC 页面，全部通过。单参数文档高度为 1413px、多参数为 8198px，均超过测试视口的 1000px；这些数值属于测试夹具，不代表生产报表数据量。
- 正向查询场景均验证了空白区滚轮、三类图表区滚轮、原生滚动条拖拽、向上返回、工具栏操作和重复查询。非 SPC 页面确认布局选择器不匹配，仍使用其原有 `stMain` 滚动方式。
- 7 个场景结束后，临时测试服务进程退出、监听端口释放、测试浏览器关闭；原有正式服务保留。测试没有查询生产数据库或改写业务工作簿。

负向对照显式模拟内部 `stMain` 滚动被禁用：旧布局无可供用户滚动的溢出容器，新布局仍由文档提供滚动。该模拟只验证防护效果，不等于复现现场故障。浏览器证据保存在 `output/test-results/spc-scroll/document-scroll-verification.json`；测试服务和浏览器会话必须在成功、失败或中断后按进程归属清理，正式服务保持运行。

自动化工具注意：当前 `agent-browser mouse wheel` 的事件可能落在 `(0,0)`，不继承前一条 `mouse move` 的坐标。验收必须检查事件的实际 `clientX/clientY`，或通过 CDP 在明确的页面坐标发送原生滚轮，不能把工具栏上的滚轮无效当作页面卡死。
