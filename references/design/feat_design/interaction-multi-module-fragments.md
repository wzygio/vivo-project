# 多模块页面的 Fragment 隔离范式

核验日期：2026-09-24。适用于同一 Streamlit 页面内有多个独立筛选、查询和展示模块的场景。
实例：[Q-Time 页面](../../../app/pages/Q_Time监控报表.py)。

## 默认划分规则

同一个页面包含多个独立业务模块时，每个模块用一个 `@st.fragment` 划分。
把该模块的筛选控件、查询按钮、结果、空态和错误提示完整放在同一 fragment 内。
用户操作某个模块的控件时，只重跑该模块；其他模块保持当前结果和图表。

页面首次加载、浏览器刷新以及主动发起的整页刷新仍然会执行所有模块。
Fragment 解决的是局部重跑，不是数据缓存，也不保证模块在首次加载时并行执行。

## 所有权与状态

| 内容 | 所属位置 | 约束 |
|---|---|---|
| 页面配置、初始化、共享页头、服务组装 | `app/pages/` | 保持薄组装层，在 fragment 外执行 |
| 模块 UI 及 `@st.fragment` 入口 | `app/sections/<domain>/<submodule>/` | 控件和结果在函数体内创建 |
| Widget key、查询签名、当前展示结果 | 各模块自己的 Session State 命名空间 | 使用模块前缀，不修改其他模块的状态 |
| 查询缓存和刷新接口 | Application 层 | 保留既有缓存签名和原生载荷约束 |
| 共享刷新按钮 | 页头 | 注册各模块缓存及刷新处理函数，按既有机制整页重跑 |

不要向 fragment 外创建的容器持续写入元素，否则局部重跑可能累积旧内容。
不要在模块内随意调用默认的 `st.rerun()`，它会触发整页重跑。
通常控件交互已经触发当前 fragment 重跑，同次执行中更新状态并渲染新结果即可。
确实需要再次局部重跑时，`st.rerun(scope="fragment")` 只能用于正在发生的 fragment
局部重跑，不能无条件放在首次整页执行路径上。

跨模块的产品、权限、配置或数据版本变更应走明确的整页刷新路径，再由各模块重新核验
查询签名。不要依赖“修改另一个模块的 Session State 后它会自动重绘”。

默认使用普通 `@st.fragment`。只有证实数据访问和共享资源线程安全时才考虑
`parallel=True`，不得为了局部交互隔离顺带改变数据库连接或快照并发模型。

## Q-Time 实例

- [站间模块](../../../app/sections/indicator_domain/qtime/dashboard.py) 的
  `render_qtime_dashboard` 是上方 fragment，状态前缀为 `qtime_`。
- [单腔模块](../../../app/sections/indicator_domain/qtime/chamber_dashboard.py) 的
  `render_chamber_dashboard` 是下方 fragment，状态前缀为 `chamber_`。
- 页头在两个 fragment 外，继续注册两组缓存和刷新处理函数。全局刷新规则见
  [页头更新机制](data-flow-page-header-refresh.md)。
- 管理员保存站间数据后先重新查询，再用 `st.rerun(scope="fragment")` 重建上方模块的
  下载内容及图表；此调用仅发生于 fragment 内确认按钮触发的局部重跑路径，避免默认
  `st.rerun()` 带动下方模块重跑，也避免下载控件保留保存前的旧台账。

单腔报表按“线体－腔室”建立 Expander；每个有效过货记录占据一个等距点位，按完整
过货时间排序，坐标标签和悬浮信息只显示到小时，同小时记录不合并。颜色使用完整启用
产品顺序分配，筛选后保持对应关系。单次测量大于 1000 秒时从图表中剔除，
恰好 1000 秒保留，缺失值不绘制，不修改源工作簿或缓存的原始测量结果。
页面不展示说明、覆盖信息、数据完整性警告、统计卡片及明细/汇总表；查询失败和空态仍明确显示。

图表使用 SVG `go.Scatter(mode="markers")`，不使用 WebGL。旧版同时绘制 11 张 `Scattergl` 图时已复现 WebGL 上下文
耗尽，第三张 OC2→OC3 的上下文被回收；分组增加图表数量后更不能依赖每图独占 WebGL。
纵轴固定为 0～6000 秒，6000 秒规格线显示在图表上边界，标签朝图内放置。

## 验证要求

1. 用浏览器分别操作上、下模块，记录各模块和页面主体的执行次数；只有被操作模块增加。
2. 验证另一模块的筛选和已提交结果保留，页面没有重复控件或陈旧结果。
3. 验证共享刷新仍能清理相应缓存及结果，并在整页执行后恢复两个模块。
4. 同时打开所有分组检查图表，不能只验证单图；检查浏览器绘图异常和窄屏布局。

验证入口：[浏览器回归](../../../tests/e2e/chamber_qtime.js)、
[隔离测试页面](../../../tests/e2e/fixtures/chamber_qtime_app.py)。
AppTest 适合检查筛选、统计和空态；实际 WebSocket 触发的 fragment 隔离需由浏览器验证。
