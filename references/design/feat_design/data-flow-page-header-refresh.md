# 页头数据、缓存、代码与配置更新机制

核验日期：2026-09-22。适用入口为 [page_header.py](../../../app/components/page_header.py)
的 `render_page_header`；独立页面可直接复用 `perform_hard_reset`。

## 1. 两个按钮的固定职责

| 按钮 | 执行顺序 |
|---|---|
| 刷新数据 | 刷新已注册的数据快照 → 刷新缓存 → 重载代码 → 重读配置 |
| 刷新缓存 | 刷新缓存 → 重载代码 → 重读配置 |

两个按钮在管理员操作区显示，沿用 `admin=true` 的现有展示条件及页面的按钮开关。
普通浏览器刷新、产品筛选和项目文件变更检测均不等同于点击这些按钮。
文件变更检测仅设置 `code_update_pending` 提示，不自动卸载模块或中断当前运行。

“刷新数据”必须在快照任务全部成功后调用 `perform_hard_reset`，不能另建一套仅清缓存的
收尾逻辑。“刷新缓存”直接调用同一个函数，不执行 `refresh_handlers`。
产品或指标作用域只能决定数据缓存的失效范围，不能用于跳过代码重载、配置重读或视图清理。

## 2. 数据快照刷新

页头依次执行页面注册的 `refresh_handlers`。具体数据库、产品、厂别和时间窗口由这些
application/composition 入口及其 infrastructure 实现决定，页头不直接查询数据库。

Yield、Inline、Q-Time 的既有人工刷新入口按各自窗口全量重取；这不等于扫描整个数据库历史。
默认向前重刷 7 天是 infrastructure 的增量刷新规则，不能据此把页头人工刷新解释为只重刷 7 天。
仓储规则见 [Infrastructure 数据刷新机制](../system_design/data-flow-infrastructure-refresh.md)。

本次快照任务使用点击时已经注册的处理函数和配置；后续代码重载、配置重读在快照成功后进行。
如果修改的是快照生成逻辑或查询配置，并要求本次快照立即按新版本生成，应先点击“刷新缓存”，
再点击“刷新数据”。报表读取、去重和计算逻辑在重新导入后使用新版本。

## 3. 共用的缓存与代码更新流程

`perform_hard_reset` 按以下顺序执行：

1. 调用 `invalidate_page_cache`，按页面注册范围使业务缓存失效。
2. 清除当前会话中名称包含 `view_model` 的视图缓存。
3. 调用 `deep_reload_modules`，卸载其管理的项目模块；页面下一次导入时读取新代码。
4. 以显式 `product_cache_scope` 为优先，否则使用会话当前产品，调用
   `SessionManager.load_and_set_config` 重读全局及产品配置。
5. 清除变更提示、Yield/SPC 快照签名、矩阵详情、矩阵加载状态及两类预警查询签名等派生状态。
   产品选择和无关会话状态保留。
6. 显示一次完成提示。“刷新数据”的提示额外包含数据快照已刷新。

| 缓存注册情况 | 失效方式 |
|---|---|
| 产品 + 指标 | 推进选中产品对应指标的共享 revision |
| 仅产品 | 推进该产品的共享 revision |
| 无产品、有 `cached_funcs` | 调用注册函数的 `.clear()` |
| 无产品、无 `cached_funcs` | 调用 `st.cache_data.clear()` 和 `st.cache_resource.clear()` |

revision 使后续读取使用新缓存键，不代表立即删除所有旧条目。定向刷新保留其他产品和指标的
有效缓存，也不会无条件销毁全局资源缓存或数据库连接。需要清空整个服务进程的内存数据及
资源时，使用已有的 [Streamlit 重启流程](../system_design/data-flow-infrastructure-refresh.md#11-streamlit-定时重启与内存缓存)。

Python 模块重载是进程级行为，不按产品隔离，也不等于重启服务或替换所有已经被引用的旧对象。
后续导入读取新模块，业务缓存继续遵守各自的版本和输入签名。
跨重载复用的缓存必须遵守 [原生载荷边界](../../../docs/ADR/0001-streamlit-cache-native-payload-boundary.md)。

## 4. 失败处理与生效边界

- 页面没有注册快照任务时，“刷新数据”仅提示没有独立任务，不报告刷新成功；可使用“刷新缓存”。
- 任一快照任务明确返回 `False` 或抛出异常，本次不进入 `perform_hard_reset`，保留当前缓存
  版本、会话视图及待应用的代码变更提示。为兼容既有处理函数，返回 `None` 不作为失败信号；
  新增处理函数应明确返回成功与否，尤其不能将数据库失败后的旧快照回退当作刷新成功。
- 多个快照任务不是统一事务。某个任务失败时，先前成功任务已经发布的快照不会整体回滚。
- 代码重载或配置重读抛出异常时，不显示完整成功提示，不清除待应用标记；保留日志并向调用方
  传播异常。已经完成的快照发布、缓存失效或模块卸载不会回滚。配置加载器自身的页面停止行为继续生效。
- 刷新后的页面由 Streamlit 按按钮回调的正常重跑流程重新执行，不在回调中额外调用 `st.rerun()`。
- 本机制依赖服务已加载包含该机制的新页头。旧服务仍持有旧按钮回调时，可能需要先重启一次
  以加载本次修复；此后的后端更新可通过两个按钮触发。

## 5. 回归验证

- [页头刷新测试](../../../tests/unit/app/components/test_page_header_product_cache.py)：
  两个按钮在产品、产品指标及无产品范围下的执行顺序；快照成功后完整收尾；缓存和资源的全局
  清理分支；快照失败、无任务、代码或配置失败时不误报成功；视图和查询状态清理。
- [热重载测试](../../../tests/unit/app/components/test_hot_reload.py)：
  在隔离子进程中修改后端函数、执行真实模块卸载，再导入得到新结果，且 PID 保持不变。
- [指标产品缓存测试](../../../tests/unit/app/components/test_indicator_product_cache.py)：
  定向 revision 失效与代码/配置重载兼容，不退化为全局数据缓存清空。

这些自动化检查验证代码和回调契约，不代表已在生产数据库执行全量刷新。
